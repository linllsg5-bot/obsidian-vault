# 知识图谱App协作系统设计 — 三角色多 Agent 架构

## 系统目标

1. 构建确定性、可监控的多 Agent 协作
2. 降低 Token 消耗 60-80%
3. 提供可视化工作状态监控
4. 确保安全边界和故障隔离

## 三角色分工

```
用户请求 → Commander → Lobster流水线 → Coder ↔ Reviewer → 输出
```

| Agent | 模型 | 职责 | 权限 |
|---|---|---|---|
| **Commander** | DeepSeek-V3 | 需求分析、任务分发、结果聚合 | 通信/编排工具，无文件写权限 |
| **Coder** | DeepSeek-V3（主力）| 代码编写、调试 | read/write/edit/bash/web_search |
| **Reviewer** | DeepSeek-V3（轻量）| 代码审查、架构评估 | 只读 |

## 文件系统安全隔离

```
workspace-commander/  # Commander 私有
workspace-coder/      # Coder 私有
workspace-reviewer/   # Reviewer 私有
shared/               # 共享目录，只追加
```

## 预期成本节省

- 新增功能（1000 行）：$4.90 → $1.20（节省 75%）
- 代码审查（500 行）：$3.15 → $0.55（节省 82%）

## 实际执行结果

**阶段 1 只完成了工作空间创建**。后续接入 Lobster、配置 openclaw.json、实际运行等步骤未完成。

当尝试启动"永动机"（AUTO_AGENCY_SOUL 里的 4 象限系统）时，遭遇大面积 HTTP 502 Bad Gateway，被主代理 Gemini 紧急叫停。这是这个系统**唯一一次实际运行尝试**，也是它的终点。

## 历史意义

这个设计是 OpenClaw AUTO_AGENCY_SOUL（永动机宪法）的前身/同期实现——用 Commander/Coder/Reviewer 对应 CEO/CTO/CPO 的逻辑基本相同。
