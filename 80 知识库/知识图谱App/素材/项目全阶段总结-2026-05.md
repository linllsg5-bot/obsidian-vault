# 知识图谱App项目全阶段总结（2026-02-28 ~ 2026-03-02）

## 4 个发展阶段

| 阶段 | 时间 | 核心内容 |
|---|---|---|
| 阶段一：启动 | 02-28~03-01 | 4 大创意构想（量化/费曼/印钞机/数字分身）+ 多 Agent 架构设想 |
| 阶段二：痛点 | 03-01 | 会话记忆丢失 + WSL 性能 + Lobster 阻塞 |
| 阶段三：重构 | 03-01~03-02 | API 安全化 + 共享模块 + PROJECT_LOG.md + USER-FEEDBACK.md |
| 阶段四：规划 | 03-02 | SQLite 升级 + 图谱可视化（待实施，后来暂停）|

## 4 大核心创意（构想阶段）

1. **知识量化交易系统**：知识点像"股票"，掌握度像"股价"
2. **费曼技巧逆向 AI 导师**：AI 扮抬杠学生
3. **全自动量化印钞机**：每天分析 100 篇金融/AI 论文 → 量化策略 → 回测
4. **数字分身养成计划**：个人知识图谱 RAG + "过去的自己"对话能力

## 完成的任务（阶段三）

- API 密钥安全化（硬编码 → 环境变量）
- 公共模块抽取（减少 130 行重复代码）
- 项目状态看板（PROJECT_LOG.md）
- 用户反馈记录文件

## 技术现状（暂停时）

双 UI 架构（TKinter + Flask）+ 纯 JSON 存储 + DashScope Qwen API
缺失：无关系查询、无可视化图谱、无 SQLite

## 经验教训

| 做错了 | 做对了 |
|---|---|
| 过度设计复杂系统（用户只需一个文件看全局）| 立即响应痛点 |
| 依赖外部工具（Lobster 阻塞就卡住）| 采纳"按需读取，分类放置"原则 |
| 同时处理设计+编码+验证 | 向后兼容重构 |

## 用户思维模式（识别自这个项目）

- **务实 > 完美**：先解决，再优化
- **手动 > 空等**：工具不行就手动
- **精简 > 复杂**：一个文件看全局
- **分类按需读取**：信息不堆积
