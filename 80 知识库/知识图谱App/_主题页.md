# 知识图谱 App — 项目综合页

> 这个项目于 2026-02-28 至 2026-03-02 期间在 OpenClaw 里构建，是用户在 Claudian 之前的早期 AI 协作开发实践。项目状态：已完成重构 40%，后续被暂停（用户精力转移到 prototype-spark 方向）。

---

## 项目定位

不是"记笔记的工具"，是"**人类心智网络（Mind-Network）的数字外脑**"。

设计准则：每一行代码、每一个 UI 交互，都必须有严格的认知科学和教育学理论支撑。

## 核心理论底座（来自 COGNITIVE_ARCHITECTURE_V3 白皮书）

这个项目把 4 大认知科学理论映射成产品功能：

| 理论 | 来源 | 产品映射 |
|---|---|---|
| 认知负荷理论 | Sweller 1988 | 强制原子化卡片（Zettelkasten）+ 目录树=工作记忆缓冲区 |
| 双重编码理论 | Paivio 1971 | 文字 Markdown（语言通道）+ ECharts 力导向图（视觉通道）实时联动 |
| 最近发展区 ZPD | Vygotsky | 拓扑排序的学习路径导航：前置节点未点亮则阻止进入 |
| 布卢姆分类学 | Bloom | 引入 Python 运行沙盒让用户从"记忆/理解"上升到"应用" |
| 间隔重复+主动召回 | Ebbinghaus | 连线（edges）=提问线索，复习模式下隐藏节点让用户填空 |
| 费曼技巧 | Feynman | "苏格拉底模式"：AI 扮演小白，用户当老师，AI 找茬评估 |
| 联结主义 | Connectionism | edges 比 nodes 重要——创建连线时强制用户写"Relation Context"（为什么连？） |

## 3 个设计阶段

### 阶段一：原子知识网（消除认知超载）—— *当前进行中*
- 废除长篇"文档"概念，强制 Zettelkasten 卡片
- 文中专有名词自动超链接（数据库里有就链）
- Hover 弹出微缩卡片（降低工作记忆切换成本）
- ECharts 不是装饰品，是导航器（中心=当前节点，周围=前提/延伸/易混淆概念）

### 阶段二：ZPD 学习导航仪
- 知识点状态机（未解锁 / 学习中 / 已掌握 / 需复习）
- AI 计算最短学习路径（Binance 自动化交易 → 反向溯源，高亮前置依赖）

### 阶段三：苏格拉底/费曼竞技场
- **费曼房间**：点 🥊 按钮，文章折叠，AI 说"我不太懂 X，你讲讲？"
- AI 比对用户解释与节点内容，精通→节点变金色；有漏洞→生成红色"认知补丁节点"

## 技术栈状态（项目暂停时）

- **UI**：双轨——TKinter（桌面）+ Flask（Web）
- **数据库**：JSON 文件（待升级到 SQLite），已完成 API 密钥安全化 + 共享模块（shared/）
- **AI API**：DashScope Qwen（后改为多模型协作设计）
- **缺失**：无关系查询、无可视化图谱

## 多 Agent 协作设计

项目中设计了一个多 agent 协作系统（见 [[协作系统设计-2026-05]]）：

```
用户请求 → Commander → Lobster流水线 → Coder → Reviewer → 输出
```

- **Commander**（DeepSeek-V3 or gpt-4o-mini）：需求分析、任务分发
- **Coder**（DeepSeek-V3 主力）：代码编写
- **Reviewer**（DeepSeek-V3 轻量，只读权限）：审查
- **预期成本节省**：75-82%

⚠️ 实际运行时，agency_engine 尝试启动四象限永动机，遭遇大面积 HTTP 502（见 `AGENCY_LIVES.md`），被主代理 Gemini 紧急叫停。见 `AGENT_DASHBOARD.md` 凌晨事故通报。

## 数据库 Schema 设计亮点（knowledge_graph_schema.sql）

- `nodes`（知识节点）: id / title / content / node_type / tags / learning_status / blooms_level
- `edges`（关系）: source_id / target_id / **relation_type** / **context** / strength
- `review_queue`：spaced repetition 复习队列
- `connections`（外脑突触）: 知识与现实目标的映射

**`edges.context` 字段是关键设计**——每条连线都必须写"为什么连"，体现联结主义理念。

## 项目停止的原因（推断）

按时间线：
- 2026-03 初开始知识图谱 app
- 之后用户转向 OpenClaw 本身的完善（构建 COGNITIVE_ARCHITECTURE / DIALOGUE / CONTINUITY 等）
- 2026-05 开始做 prototype-spark（被触发型写作者工具）
- 知识图谱 app 未见后续记录

知识图谱 app 的"帮用户学习"方向 → 被吸收进更广泛的"扩大版尝试帮助工具"愿景（写作 / 学习 / 项目是同一架构的不同 instance）。这个项目可能成为"学习 instance"的蓝图。
