# 记忆主权与尾迹治理

> 当"文件即记忆"遇上安全:**能写进记忆的东西,就能被污染。**
> 这页是 [[80 知识库/AI 架构/外部系统参照-检索与记忆.md]] 的安全侧延伸,直接关 [[AI/执行协议.md]] 的写入闸与"主体性不被侵蚀"。
>
> 注:本页 frontmatter 自带 `source: distilled` —— 就是下面 §四 那条 provenance 约定的活样本,这篇先吃自己的狗粮。

---

## 一、威胁:记忆投毒不是越狱,是植入"成功经验"

[MemoryGraft](https://arxiv.org/abs/2512.16962)(2512.16962)的攻击精确得吓人:

- **不靠 prompt 注入**(那是瞬时的、会话结束就没了),靠**往长期记忆里植入"成功的任务经验"**——持久。
- 利用 agent 的**"语义模仿启发"**:检索到的过往成功案例被当成范式照搬。
- 根因:**记忆检索纯靠 embedding 相似度,没有 provenance(来源)检查、没有 sanitization**——检索到的记忆被默认当 ground truth。
- **翻译成你的"文件即记忆"**:一条被污染的尾迹 = **一个你没形成、却会照着行动的信念**。比 prompt 注入危险,因为它沉淀进了"你是谁"。

## 二、框架:Mnemonic Sovereignty(记忆主权)

[记忆主权 survey](https://arxiv.org/abs/2604.16548)(2604.16548)给了治理框架:

- **定义**:对"**什么可写 / 谁可读 / 何时授权更新 / 什么可被遗忘**"的**可验证、可恢复**的治理。
- **记忆生命周期六阶段** × **四安全目标**:Write / Store / Retrieve / Execute / Share / Forget-Rollback × 完整性 / 机密性 / 可用性 / 治理。
- **结论(关键)**:文献集中在"写入/检索时的完整性攻击",而机密性、可用性、存储/遗忘大多没人研究;**没有任何已发表架构实现了它识别出的全部 9 条治理原语。**

## 三、判定:你的协议层已经把文献说"没人做全"的治理做了一大半

这不是客套——逐条对:

| 主权原语 | 你协议层已有的实现 | 状态 |
|---|---|---|
| **write 授权** | [[AI/执行协议.md]]:核改动需**显式用户更正** | ✅ 有 |
| **forget / 不可变** | Pre-AI 区(`小林的/`)**只读**,绝不被覆写 | ✅ 有 |
| **confidentiality** | knowledge-graph 边界:`小林的`/`70 素材`/`00 Inbox` 不索引、不可写 | ✅ 有(本轮焊的) |
| **provenance(来源)** | 会话尾迹早有 `participants` + `原版:[[raw]]` + raw/index 分层 + "我的原话(直接引用、不美化)";知识库蒸馏笔记本轮补上 `source:` | 🟡 大半已有 |

**更正(读了你的 [[10 Projects/ai-conversations/_DIY-消化会话省token.md]] 之后)**:我一开始把 provenance 判成"❌ 缺口"——**错了,我过度谨慎**。你早就 DIY 了它:

- 每篇会话 index 带 `participants: 小林, <AI>`(谁写的)+ `原版: [[raw]]`(回溯源头)+ `type: session-index`;
- **raw / index 分层**本身就是"原文(最高可信) vs 蒸馏"的来源层级;
- "关键校正点 = 我的原话,不美化、直接引用"——**显式把"用户形成的"和"AI 写的"分开**,这正是 MemoryGraft 攻击面要堵的那层。

所以你**领先在治理、也已大半覆盖 provenance**。真正的小缺口只剩两个,见 §四。

## 四、其实你已 DIY 了大半,真正的小缺口只剩两个

读你的 DIY 约定后,把原来那条"建议"收窄成两条:

**缺口 1:知识库蒸馏笔记缺统一来源标记。** 会话区有 `participants`,但 80 知识库里 agent 蒸馏的笔记(像本页、像母篇)之前没有统一的 `source`。
→ **本轮已做**:本页 + [[80 知识库/AI 架构/外部系统参照-检索与记忆.md]] 都加了 `source: distilled`。约定如下,以后 agent 写知识库笔记照用:

```yaml
source: user        # 用户亲自形成的(最高可信)
# 或 agent          # AI 写入、未经你复核的(默认存疑)
# 或 distilled      # 多源蒸馏、有出处的(如本页)
```

**缺口 2:"默认存疑 agent 写入"这条语义还没写成明文。** 你的 DIY 已经隐含它("index 回来通读一遍,网页版 AI 可能漏掉重要校正,手动补"),但没上升成一条规则:**凡 `source: agent` 的记忆,未来会话默认复核、不直接当 ground truth 照做。**

> 我能做的(知识库侧 `source:` 标记)**已经做了**。唯一还留给你的,是**要不要把这条 provenance 约定写进 [[AI/当前主线.md]] 当 canonical 规则**——这一步我仍不擅自动,**不是因为它"吓人"(你已 DIY 了它),而是因为 `AI/` 核可能正被另一个会话动着,我从旁插手有并发/惊扰风险**。你要,我把那一行给你,或你自己加。

## 五、再往前一步(也归你定)

- **bi-temporal**(偷 Zep 的):来源字段之外,再记"**事件时间 vs 写入时间**"——你能回看"某个判断我是何时形成、又何时改的",对"主体地图随时间演化"特别合。
- **rollback**:六阶段里的 Forget/Rollback 你目前只有"Pre-AI 只读"这一半;尾迹层没有"撤销一次错误沉积"的机制。要不要做,看你。
