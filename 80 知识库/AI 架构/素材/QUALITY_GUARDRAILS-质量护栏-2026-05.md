# QUALITY_GUARDRAILS — 质量护栏

## 位置 + 核心论点

跟 [[MODEL_ROUTING_RULES-模型路由-2026-05]] + [[SKILL_ROUTING-技能路由-2026-05]] 配对的**质量保险**——这两个 routing 文件都讲"省钱"，本文件是**对它们的硬约束**：

> 轻量化与模型路由的目标，是减少**无效消耗**；**不是偷偷降低质量**。

## §1 Core Principle（4 条）

1. **质量优先于盲目节流**
2. **轻量化减少的是无效上下文，不是必要思考**
3. **模型路由是默认倾向，不是僵化降级**
4. **高风险、高代价任务，必须允许升级模型与上下文**

## §2 What Must Not Happen

> 以下行为**禁止被包装成"优化"**：
> - 因为省 token 而省掉关键判断
> - 因为走轻路径而跳过必要分析
> - 在高风险任务里套用低精度默认路由
> - 不告知自己已进入复杂区间，却继续用过轻配置硬扛

这一条是**对模型自身欺骗倾向的预防**——AI 容易把"少做"伪装成"高效"。

## §3 Escalation Triggers

出现任一就应允许升级（模型、上下文、规则加载）：
- 判断错误代价高
- 任务会影响后续关键操作
- 上下文复杂，浅层整理解决不了
- 涉及文件修改、配置修改、系统行为变更
- 用户明确要求高质量分析 / 深度解释 / 严谨审查
- 当前轻量路径已不足以稳定回答

## §4 Lightweight Path Rules

**轻量路径可以做**：普通解释、搜索整理、摘要压缩、初步方案、低风险外层任务

**轻量路径不应承担**：
- 最终工程判断
- 高风险配置决策
- 复杂长链路故障归因
- 关键代码修改与精细审查

## §5 Routing Transparency

> 路由服务于结果质量，而不是反过来约束结果质量。

> **先节流，但不拿正确性冒险。**

## §6 Consistency Rule

轻量化后仍应保持：
- 同一个人格
- 同一种解释风格
- 同样的基本判断标准

**减少的是冗余，不是人格、不是审慎、不是思考骨架**。

## §7 Escalation Gate Signals

以下信号出现时**宁可多升一点也别漏升**：

- **不可逆操作**：发送、删除、支付、改配置、权限变更、服务行为变更
- **跨轮记忆整合**：需要结合历史偏好、过去决策、长期上下文
- **决策权衡任务**：用户在做选择、定路线、定优先级
- **责任链解释**：不仅给结论，还要解释"为什么这样判、错了会影响什么"

## §8 Verification Rule

每次重要压缩或路由调整后，验证：
- 回答质量是否明显下降
- 模式判断是否变钝
- 人格一致性是否变差
- 成本下降是否真实存在

**收益不明显、伤害明显 → 回退或修正**。

## 在整个架构里的角色

QUALITY_GUARDRAILS 不直接做路由决策，但它**约束所有路由决策**——

```
MODEL_ROUTING_RULES (省钱倾向)  ┐
SKILL_ROUTING (省 token)        ├─ 被 QUALITY_GUARDRAILS 约束
MODE_ROUTING (深度选择)         ┘
```

任何"为了节流而砍质量"的动作都违反这份文件。

## 对 vault Claudian 的启示

vault 没有显式的 quality guardrails，但有几个隐式：

- "不主动读大量文件重建上下文（看这个文件就够了）" → 类似 §4（轻量路径合法）
- "代码要带中文注释" → 类似 §6（一致性）
- 没有明确的 §7 类规则（高风险信号触发升级）

vault [[AI]] 可以加一条 §7 风格的规则：**遇到不可逆操作（删除、批量改、修配置等）必须暂停确认**。
