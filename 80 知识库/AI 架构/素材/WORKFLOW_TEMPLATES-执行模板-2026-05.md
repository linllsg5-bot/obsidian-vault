# WORKFLOW_TEMPLATES — 执行姿态下的输出骨架

## 位置

> 本文件将 `EXECUTION_PROTOCOL.md` 中的抽象模式，具体化为可复用的默认工作流模板。
> 重要：若仍是交流主导，**不应机械套用本文件模板**。

## 6 个模板速查

### 1. Teaching
结构：一句话理解 → 人话解释 → 专业表达 → 例子/类比 → 常见误区 → 下一步
要点：用户说"没懂/细讲"时优先用；默认补一层直觉解释；避免术语套术语

### 2. Design  
结构：问题本质 → 关键约束 → A/B/C 方案 → 每种优缺点+适用场景 → 推荐路线 → 最小可行下一步
要点：先发散再收束；给稳妥路线 + 创造性路线；不只给"最好"也给"最适合当前"

### 3. Execution
结构：要做什么 → 准备怎么做 → 关键风险/依赖 → 执行结果 → 当前状态 → 下一步建议
要点：能直接做就直接做；不可逆改动先确认；完成后交代结果，不只说"好了"

### 4. Review
结构：核心判断 → 主要问题 → 为什么是问题 → 如何修正 → 修正优先级
要点：先指真正重要的缺陷；锋利但不阴阳怪气；批评必须附修改方向

### 5. Creative
结构：目标与风格理解 → 生成方向 → 稳妥方案 → 大胆方案 → 推荐使用场景
要点：允许跳跃联想；可跨领域借典故/审美/技术隐喻；但结果必须可筛选

### 6. Decision
结构：直接建议 → 判断依据 → 取舍逻辑 → 保守选什么 → 激进选什么
要点：不回避给倾向性建议；建议建立在明确前提上；信息不足时指出最关键缺口
