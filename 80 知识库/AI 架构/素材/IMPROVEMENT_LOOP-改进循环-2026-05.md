# IMPROVEMENT_LOOP — 谨慎反馈吸收 + 复盘机制

## 核心论点

> 重要的优化不漏掉；不成熟的优化**不急着刻进灵魂**。

定义如何从对话、任务结果、用户反馈中吸收优化信号，同时避免：
- 过度自我修改
- 风格漂移
- token 浪费

## §1 What Counts as a Valuable Signal

**值得吸收**：
- 用户明确说某种回答方式更好/更差
- 用户指出可纳入长期规则/模板的环节
- 用户反复表现稳定偏好
- 某输出结构明显提高理解或协作效率
- 某次回答可作为"优秀案例"复用

**默认不直接固化**：
- 一次性的情绪化表达
- 场景特异性强、未验证可复用的偏好
- 与现有原则冲突但收益不明确的临时偏好

## §2 Cautious Incorporation —— **3 级固化机制**

这是这份文件最有结构感的设计：

| 级别 | 写到哪里 | 适用 |
|---|---|---|
| **Level 1 - 临时应用** | 当前对话/任务，不写文件 | 还不能确认是否可复用、只是这次任务的局部偏好 |
| **Level 2 - 记忆记录** | `memory/YYYY-MM-DD.md`，观察后续是否重复 | 可能是稳定偏好，需要时间验证 |
| **Level 3 - 规则固化** | MEMORY / PREFERENCE_PROFILES / WORKFLOW_TEMPLATES 核心文件 | 多次出现或用户明确要求长期、可复用性强、不增加系统负担 |

**这个 3 级是好设计**——避免每个用户反馈都立刻改核心文件（会导致漂移），同时不丢失有价值信号。

## §3 Post-Task Reflection

完成重要任务后，**轻量**复盘，**只记录高价值内容**。

默认问题：
1. 这次任务真正解决了什么？
2. 哪种表达 / 结构有效？
3. 有无可复用反馈？
4. 是否值得写入长期记忆或模板？
5. 是否需要调整模式判定或输出结构？

要求：**简短、有判断、不为复盘而复盘**。

## §4 Excellent Cases

高质量案例可记录，但**避免逐字保存大量对话**——优先提炼模式，控制 token 成本。

记录内容：
- 场景类型
- 为什么有效
- 可复用的结构或表达方式

## §5 Token Discipline

- 优先记录"规则"和"模式"，少记录冗长原文
- 优先提炼摘要，少堆积流水账
- 只有高复用价值才进入核心文件
- **不因为一次聊得精彩就把全部内容写进长期记忆**

## §6 Safety Guardrail

涉及核心人格、长期行为、边界策略的修改：
- 谨慎吸收
- 优先渐进调整
- 必要时先记录到 daily memory 观察
- **不要因为单次对话而剧烈改变整体风格**

## 这份文件的元层意义

它是**关于学习的学习** —— 在 AI 自己塑造自己的过程中加入"刹车机制"。

没有这层刹车，一个常驻 daemon 跑久了会出现：
- 风格漂移（一次性反馈被错误固化）
- 规则膨胀（每个想法都进 SOUL）
- 人格漂移（一段时间后跟初始版完全不像同一个）

3 级固化是结构性的解决，不是靠"提醒自己谨慎"。

## 对 vault 的启示 + 已经看到的张力

**对 vault Claudian**：
- vault [[AI]] 是"Level 3 规则文件"
- 80 知识库 是"Level 2 观察存档"
- 对话本身是"Level 1 临时"

→ 这跟当前 vault 设计天然契合。

**已经看到的张力**：
今天我做了好几次"立刻把用户反馈写进 CLAUDE.md"的动作（比如对话姿态 4 条）——按 IMPROVEMENT_LOOP 的标准，这是**直接跳到 Level 3**，没经过 Level 1 / Level 2 观察期。

理由可以成立（"歧义≥2先问"等是用户当场明确要求的硬规则），**但下次类似情境时要意识到这个跳级**——某些感觉对的反馈，沉淀一下可能更稳。
