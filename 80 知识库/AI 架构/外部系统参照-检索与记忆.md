## 一、主线 A — Spark 检索引擎:LightRAG 是最近的现成参照,但"双层"是 false friend

LightRAG(arXiv:2410.05779,HKUDS)的 dual-level,拆开是这样:

- **低层** = 取具体实体 + 属性/关系(specific query:谁写的、哪一年)
- **高层** = 取宽主题/概念、跨多实体聚合(abstract query:这在讲什么)
- 机制极简:**一次 LLM 调用**把 query 切成 `{low_level_keywords, high_level_keywords}` JSON → 低层词向量匹配实体、高层词向量匹配关系 → 再抓一跳邻居补结构。

**先泼冷水**:它的"双层"是**语义粒度轴**(细节 vs 主题)。Spark 的"双层"若指别的轴——KG 层 vs 向量层、或热缓存 vs 冷存——那就是同名不同物。**别被两个字骗着照搬,先确认你那两层切的是哪根轴。**

**能直接偷的三样**:

1. **query 端 low/high 关键词切分**——一次 LLM 调用就路由了检索,便宜。
2. **KG 构建的 profiling**:每个实体存成 key-value,key 是"短检索短语"。≈ Spark 的 **block-centric contextual wing**——每个 block 配一个检索把手。
3. **增量更新 = 取并集**:新文档单独抽 →(节点集 ∪、边集 ∪)→ 不重建全图。正面打"成本缓存"。

**但别整碗端走**:LightRAG 每个 chunk 都跑 LLM 抽实体/关系,ingest 端是隐藏重税。它的亲兄弟 **MiniRAG** 存在的全部理由就是这个 ingest 太贵(只要 ~25% 存储)。诚实的读法:**LightRAG 给你检索架构,MiniRAG 给你 ingest 成本纪律——两者分开拿。**

> 对照点:已停的知识图谱 App 里 `edges.context`「为什么连」字段(联结主义),和 LightRAG 的 relation-description 是**同一直觉**——见 [[80 知识库/知识图谱App/_主题页.md]] 的 schema 设计。Spark 不是从零起,是接这条旧线。

## 二、主线 B — 协议层"会呼吸但不失忆":ACE 把这句话变成了实验数据

最重的一条:**"失忆"不是修辞,是被测量过的故障模式,有名字——context collapse。**

ACE(arXiv:2510.04618)实测:整体重写式更新,第 60 步上下文 18,282 token / 准确率 66.7 → **一步坍成 122 token / 准确率 57.1**。起因正是"每步把整个上下文重写一遍"。

→ 你 [[AI/当前主线.md]]「会呼吸但不失忆」担心的事,他们用数字钉死了:**整文件重写 = 失忆的机制本身。**

**ACE 的解法,直接映射你的协议**:

- 别每次重写整个 `当前主线.md`。改成 **delta:新增带 ID 的 bullet、旧的就地更新**。
- 你的「**尾迹**」= 他们「带 helpful/harmful 计数器的 bullet」。那个计数器,就是你「用户做的问的才保留」被量化了。
- grow-and-refine + 向量去重 = 你要的「沉积但不臃肿」。

### 关键连接:ACE 用工程,证明了 [[80 知识库/认识与思维生成/_主题页.md]] §三 早已用哲学立住的东西

ACE 整套靠**可靠执行反馈**(代码跑没跑过)驱动 Reflector。作者明确警告:**没有可靠反馈,"上下文会被虚假信号污染"。**

你的协议层**没有 pass/fail**——「身份基底对不对」没有单元测试。所以**不能裸接 ACE 的自动 curation**:Curator 会把你的核搅成一摊和稀泥的共识——那正是 ACE 命名的 **brevity bias**(朝"短、通用、讨喜"坍塌)。

而你那条红队修正(认识与思维生成页 §三、§四)**早就给了答案**:协议层的"执行反馈"不是 success/failure,是**"用户有没有顶回来"**。

- §三:差异必须做在**编排层**的"诘问者角色",对"赞同"显式扣分——不是 prompt。
- §四第二条:康德边界纪律——显式分开"我构造的"和"世界顶回来的"。

→ **两条独立的线(ACE 工程 / 你的红队哲学)在同一点收口**:把内容平滑成共识 = 死。要保留被标 harmful 的 bullet、那些矛盾、那些阻力——**把摩擦留在 playbook 里**。ACE 给了这件事的工程词汇(delta-bullet + 反污染),你的红队给了它的认识论理由(aporia / 被抵抗才点燃)。**抄 ACE 的数据结构,不抄它的自动驾驶。**

## 三、Letta / MemGPT — 故意不走的路,当反面坐标

MemGPT(arXiv:2310.08560,Letta)卖点:agent 用 function call **自己改自己的记忆**(OS 式内存分层 + 中断控制流,把"长上下文"变成可换页的虚拟内存)。

但 [[AI/执行协议.md]] 明写:**协议核改动要显式用户更正。**

→ **MemGPT 对你的「核」是反模式**:你是有意识地选择"不让 agent 自主重写身份基底/用户档案"。它适合草稿/工作记忆,对身份层危险。**不是没看到这条路,是看到了不走。**

> 这跟 [[80 知识库/AI 架构/_主题页.md]] 里 OpenClaw 的 **IMPROVEMENT_LOOP「3 级固化」**(临时/记忆/规则)是同一个判断:**不是每个信号都立刻改核心。** MemGPT 把"自主改核"当卖点,你和 OpenClaw 都把它当**要防的事**。

---

## 收口:三句话

1. **LightRAG** 偷检索架构(low/high 切分 + 并集增量),成本纪律外包给 MiniRAG;动手前先把"双层"对轴。
2. **ACE** 证明"不失忆"的直觉是对的、并给了 delta-bullet 的现成做法;但它的自动驾驶你不能接——你没有执行反馈,你的反馈是「被抵抗」,这恰好把红队页 §三 的结论焊死了。
3. **Letta** 是你刻意不走的路:自主改核 = 你明令要防的。

## Round 2 — 其余系统(2026-06-04 补)

把地图剩下的也照过一遍,仍按"会不会改变你要做的事"分层。

### 🔴 学术界独立收敛到了你的架构(EverOS 2601.02163 + 记忆 taxonomy 2603.07670)

- **EverOS**:MemCells(原子单元:情节 + 事实 + 带有效期的 foresight + 元数据)→ MemScenes(在线增量聚成主题簇 + 更新 User Profile)→ 重构式回忆。**这逐字就是你的"尾迹沉积 → 主体地图扩张"。**
- **2603 taxonomy** 把它形式化为 **write–manage–read 循环**;关键点:**"manage" ≠ append**——要 summarize / 去重 / 打分 / **解矛盾** / delete。还有一句狠话:**"有没有记忆"的差距,常常大于"换不换底座模型"。**
- **偷**:把"**解矛盾**"做进尾迹 consolidation(和 ACE 的 delta-bullet 同一指向——沉积不是堆,是主动消解冲突)。
- **别学**:EverOS 的 MemScenes 是**自动**聚的——对产品没问题,对你的**身份层**就是 MemGPT 同款危险。benchmark(93% LoCoMo…)厂商自报,**拿架构,别拿数字**。

### 🟡 知道即可(各一个 takeaway)

- **Cognee / Mem0 / Zep(Graphiti)**:库/图式记忆层 = MemGPT 反模式。唯一值得偷:**Zep 的 bi-temporal**(事件时间 + 写入时间)。
- **Nano-GraphRAG**:~1k 行极简 GraphRAG,手搓检索核的起点——但你已有 knowledge-graph,只在想从零重写时才看。

### ⚪ 以后再说 / 书签

- **RAG-Anything**(多模态,Spark 存图表时)、**CodeGraph / Code-Graph-RAG**(Spark 有代码库时,"94% 更少 tool call"是其自报)、**Awesome-GraphRAG + 记忆 survey**(书签)、**Obsidian 1.12 内置 CLI**(你已在此路)。

记忆投毒 + 主权治理 + 尾迹 provenance 缺口够分量,拆出去了 → [[80 知识库/AI 架构/记忆主权与尾迹治理.md]]。
