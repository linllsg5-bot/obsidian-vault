## 标注者备注（给人复核）

### 校正点
1. **"其实你已经配好了"**——AI 一开始猜的 OpenClaw config schema（`models` 是对象、`apiKey` 用 `${VAR}`）是错的。看到小林贴出的实际 `openclaw.json` 后纠正为真实的 schema（`models` 是数组、需要 `"api": "openai-completions"` 字段、`apiKey` 是明文）。这是本场最重要的认知校正。

### 开口
1. **freemodel 挂了，要不要换付费中转站？**——AI 提到了 packyapi.com、apiyi.com、anyrouter、自建 Sub2Api 等选项，但对话在 fallback 设置成功后结束，未进入"换中转站"的讨论。freemodel 的可靠性问题未解决。
2. **密钥轮换**——AI 两次警告 JSON 里明文密钥已过第三方服务器，建议立即轮换 Google/FreeModel/OpenAI/key+gateway token。raw 里无后续确认是否轮换了。
3. **"如果要真分工路由"**——AI 提到 subagent 可以分别配模型（主 Opus + subagent Sonnet），留了口子但未展开。

### 割裂
本场无明显割裂——对话始终围绕 OpenClaw 中转站配置，主题一致。

### 存疑
1. `freemodel` 的 `api` 字段在 raw 的 openclaw.json 是 `"openai-completions"`——不是标准的 Anthropic Messages API 格式。这意味着中转站把 Claude 模型包装成了 OpenAI 兼容格式。可能需要确认这个协议转换是否影响 Claude 的能力（如 system prompt、tool use 等）。
2. Google API key 在 openclaw.json 中出现了多次（`google`、`google-ai`、`goplaces`、`notion` 四个字段都用同一个 key），且明文裸存。安全风险。
3. 小林在终端粘贴命令时频繁被换行截断——`--strict-json` 和 JSON 数组参数被 bash 当成独立命令/文件名。这可能是复制粘贴时的终端行为问题，不是认知问题。
