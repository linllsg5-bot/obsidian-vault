## 弧线二：Gemini 三条入口——封号风险的完整论证

〔林〕〔校正〕"我想要gemini转接google ai studio的，你反代antigravity会被封号吗？gemini cli呢？哪个额度多？我该选哪个？是gemini 3.5flash最好用吗？还是3.1pro preview？你是要反代吗？"

〔AI:claude〕〔实〕CLIProxyAPI 本身就是反向代理——问题不是要不要反代，是反代**哪个 Gemini 入口**。三道门，封号风险天差地别：

| 入口 | 封号风险 | Flash 免费额度 | 能否喂 agent |
|---|---|---|---|
| **AI Studio API Key** | 几乎没有 | ~1500次/天 | 完整 tool use |
| Gemini CLI OAuth | 有风险（官方点名"第三方自动化=滥用"） | ~1000次/天 | 残 |
| Antigravity OAuth（现在这个） | 同样有风险 | 预览期大但会变 | 残 |
| 网页反代（WebAI-to-API） | **拉满（赔主账号）** | Pro 不透明 | 完全不能跑 agent |

〔AI:claude〕〔实〕Gemini CLI 官方讨论里维护者原话："如果把它当作第三方调用工具……就有被封号的风险。" OAuth 那两条的额度是给那个 App 自己交互用的。你用 CLIProxyAPI 转出去喂 Claude Code，Google 能从客户端指纹和调用量上识别。Pro 免费层基本废了（~50次/天）。

〔AI:claude〕〔幻〕选 AI Studio API Key —— 安全、额度够、免信用卡。对脏活层用 Flash 系（gemini-3.5-flash），绝不用 Pro。

〔林〕（通过 AskUserQuestion）"我说的是反代网页？网页的话就能既用pro也能flash了"

〔AI:claude〕〔校正〕"先停一下——'反代网页'这条路我必须给你泼盆冷水，因为它看起来香，其实对你这个用途是个坑。"

〔AI:claude〕〔实〕三条死人：
1. **封号风险拉满**——网页 cookie 反代被发现 = Google 可能封**整个账号**（Gmail、Drive、照片），代价灾难级不可逆。API key 被封只是换个 key。
2. **撑不起 agent 后台**——网页版没有 tool calling、没有 system prompt 控制、没有 prompt caching。喂 Claude Code 会行为错乱。
3. **三天两头坏**——cookie 几小时轮换，Google 改前端反代就挂。

〔AI:claude〕〔实〕给 Claude Code 当后台就用 AI Studio API key。网页反代那点"免费 Pro"换来的是账号级灾难 + 根本跑不动 agent。

〔林〕（通过 AskUserQuestion）同意 AI Studio API key。
