## 弧线二：思考变长——中转延迟与缓存诊断

〔AI:claudian〕〔实〕开思考模式让每回合多一个推理 pass——但那是几十秒量级，撑不起"几分钟"。主因是你走的是第三方中转（freemodel），中转的代价是：多一跳网络、共享池排队/限流，而且**很多中转不透传 prompt caching**。正常情况下你这套巨大的自动加载上下文只在第一回合付全价，之后命中缓存就便宜了。但如果中转不透传缓存，**这坨上下文每回合都按冷的重算一遍**。能拉的杠杆：轻问答时关思考、那份 `zh/` 中文规则副本是纯冗余可以摘掉、有官方端点额度重活换官方会稳很多。

## 弧线五：边界核验——编码 bug 的连环自纠

〔AI:claudian〕核验脚本首次运行——发现 `00 Inbox` 有 3 个命中。

〔AI:claudian〕深入检查：`00 Inbox` 命中是 `_stub/00 Inbox/README.md`（空壳 stub，HOME.md 的 wikilink 留下的占位，content 长度 0）——没读任何内容 ✓。但**我自己的核验脚本有 bug**：`Set-Content -Encoding ascii` 把中文 `小林的`/`70 素材` 吃成了 `???`，等于没查。

〔AI:claudian〕改用 `\u` 转义重查——发现 `communities` 列的 JSON dump 里赫然躺着 `_stub/小林的/40 Journal/INDEX.md` 等 Pre-AI 区路径名和 `_stub/claude code 密钥.md`！没正文，但文件名浮出来了——**按你"不索引、不链"的铁律，这也不行**。

**根因**：工具会给每个指向未索引文件的 wikilink 创建 `_stub` 空壳。你在允许区笔记里写了 `[[小林的/40 Journal/INDEX]]` 这类链接，于是 Pre-AI 区的路径名以空节点形式进了图谱。

**修法**：改 parser.ts，跳过所有悬空链接、根本不建 stub（宁可丢断链检测——Obsidian 自己能查）。

〔AI:claudian〕改完 `--force` 重建索引。

〔AI:claudian〕第二次核验——又是两件事：parser 补丁生效了（新 stub=0），但 `--force` 不清空旧表（是 upsert），上一轮 36 个旧 stub 赖在库里。而且**我又犯了同一个蠢**：脚本又写了字面中文被 ascii 编码吃掉，`小林的=0` 是假阴性。

〔AI:claudian〕**两个根治法**：① 直接删 `kg.db` 从零重建（保证 0 stub 残留）② 验证脚本改用 Write 工具落盘 UTF-8（中文不再被吃）。

〔AI:claudian〕删库重建 + Write 工具落盘 `kg-verify-final.py`（UTF-8）。

〔AI:claudian〕第三次核验——中文真查到了："小林的"有 20 个命中。但**顶层文件夹没有"小林的"**（只有 80知识库/10Projects/AI/根），所以这些命中不是 Pre-AI 区文件夹漏了，是某个允许区文件的名字含"小林的"三个字（子串误报）。

〔AI:claudian〕揪出确切 id——唯一命中是 **`80 知识库/_backlinks-to-小林的.md`**，在允许区 `80 知识库/` 里（`leading_PreAI_dir: False`），不是 stub。它是一个 AI 维护的**反向索引**——当 80 知识库的笔记引用了"小林的/"的创作文件时，这里记录一句理由。**内容只含 wikilink 和一句话理由，不含 Pre-AI 区正文**——这是 ingest 约定的正常操作。

〔AI:claudian〕〔实〕**边界最终判决**：`小林的/` 文件夹本身**0 文件被索引**，0 正文内容泄露。唯一的"小林的"命中是允许区内的反向索引文件（只含 wikilink 和理由摘要），符合 ingest 约定。`70 素材/` 和 `00 Inbox/` 全程 0 命中。107 个真实节点全在允许区。**边界守住了。**
