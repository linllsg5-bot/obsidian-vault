# 索引：四套 AI 协议的融合归位 — 一核·两帽·一路由·三源·一呼吸

> 这不是摘要。这是一份尾迹：保留了关键校正、未解决张力、给下次 AI 的操作指引。
> 需要逐字细节去读 [[raw]] 或 [[标注]]。

## 一、这次对话产出了什么

### 已落地的变更 / 已确认的原则

1. **架构形态完整推演：一核·两帽·一路由·三源·一呼吸**
   ```
   每次对话第一动作：姿态路由（薄）
   "现在要被承接，还是被推进？"
         ├─ 承接帽（陪伴）= 对话姿态 + 克制轴
         └─ 推进帽（执行）= 执行协议 + 子模式细分
                                       └─ 代码模式 + 在代码仓 → ECC 全套加载

            所有帽子站在核上：
           【核】身份基底·认识论·用户档案·当前主线
                  └─ 旁挂：协议演化史（尾迹）

           引用：OpenClaw 35文件（历史库）· 80镜像（查阅）· ECC rules
   ```

2. **"先归位再生长"替代"先融合成一坨"**——拒绝预盖大一统，四步：
   1. 认领活源——加载路径钉死 `AI/` 为唯一活协议源
   2. 提炼路由——从 OpenClaw 只抽三条（先判姿态、克制轴、用户纠偏=最高路由信号）进 `AI/`
   3. 挂 ECC——在执行协议子模式里加代码仓指向
   4. 核装呼吸——建 `AI/_演化史.md`

3. **三份漂移诊断**：OpenClaw 源 → 80 镜像 → `AI/` 精简版已不完全对应，`AI/执行协议` 与 OpenClaw 的 `EXECUTION_PROTOCOL` 脱节。重构方向：向 `AI/` 精简看齐，把 35 文件中真正"活"的东西提炼进来。

4. **ECC 定位裁决**：ECC 不"融入"任何东西。只在姿态路由 = 执行 → 子模式 = 代码 → 且在 prototype-spark 类项目里干活时才加载。其余所有时候 ECC 完全不存在。思维张力（内容层）与机械规则冲突（控制层）是两类东西，不能在同一时刻抢方向盘。

5. **prototype-spark 引入 git + ECC**：git init → 首次提交 `61a651d` → 写项目级 `CLAUDE.md`（声明项目性质、指向全局 ECC、"动代码前先 git 提交"安全线、继承 vault 协议署名纪律）。

6. **vault 会话归档区建成**：`10 Projects/ai-conversations/` 目录建立，两场历史会话 raw+index 两层就位。raw 是用户的记录（沉积），index 是给 AI 的尾迹。

7. **核加演化日志机制确立**：`AI/_演化史.md`——每次核改动记一行（谁/改了什么/为何/由哪次主体扩张触发）。核稳定的不是内容，是身份的连续性。

### 未解决的张力 / 卡点

1. **姿态路由未落地**——形态推演完整但路由判断层从未写成文件。
2. **`AI/_演化史.md` 未建**——机制定了，文件未写。
3. **"认领活源"未执行**——加载路径里钉死"AI/ 是唯一活协议源"这一步未落地。
4. **ECC 挂载句未写入执行协议**——"代码子模式且在代码仓内→加载 ECC"仍为口头约定。
5. **本场对话自身未归档**——小林说"把各处和 AI 的对话也放进 obsidian"，本场是最新的待归档材料。
6. **80 镜像"消化一下"未做**——OpenClaw 协议的 80 镜像瘦身未执行。
7. **ECC 控制层冲突的长期待观察**——路由是目前唯一防止两套控制程序同时抢方向盘的机制，高频冲突中的实际表现未验证。

> *(纠正 AI 对"融合=大一统终极态"的误判。声明融合是阶段性迭代，不是终点。"更新与改革"本身应纳入核心哲学。)*

> **"思想自由放开些。"**
> *(顶回 AI 过于收束的判断，要求在方向选择上保持开放。)*

> *(提出"核应该会呼吸、能演化"，直接催生了演化日志机制。)*

> **"那些会话是我要记录的，整理之后才是给ai看的。我之前复制是因为那时候你卡了，我得把前文搬过来，顺便想把各处和ai的对话也放进obsidian再整理"**
> *(纠正 AI 把"原文倾倒"贬低为无价值。澄清 raw 层是给用户的记录（沉积），index 层是给 AI 的尾迹，两层都要。)*

> **"也不是提效吧，就是让你更好理解我，以及一同更好地推进、思考项目"**
> *(纠正 AI 把目标窄化为"提效"，回复到"更好理解、更好推进"的本意。)*

> AI 自我校正（被小林点醒后收回两条）：
> - "核必须稳定" → 校正为：核的稳定性在身份连续性，不在内容冻结。核可以一直改，但每次改必须是"上一个我长出来的下一步"。
> - "原文倾倒没价值" → 校正为：raw 是用户记录，index 是 AI 尾迹，两层都要。

> **"关于ecc，所以也就涉及到冲突问题……不知道冲突本身带来的张力与变数是不是也可以接受"**
> *(被 AI 顶回——区分了"内容层张力（养料）"和"控制层冲突（噪音）"。路由的目的不是消灭冲突，是让冲突不在同一时刻抢方向盘。)*

## 三、给下次 AI 的操作指引

### 进入相关话题前先知道什么
1. **Architecture 已定**：一核·两帽·一路由·三源·一呼吸。方向是"先归位再生长"，不是"融合成一坨"。不要一上来就提议大一统重构。
2. **"活源唯一"是红线**：`AI/` 是唯一活的协议源。OpenClaw 35 文件和 80 镜像已降级为历史库/查阅。不要再从 OpenClaw 反向同步。
3. **ECC 不能无条件开**：只在执行帽 + 代码子模式 + 在代码仓时才加载。陪伴/创作场景里 ECC 是噪音。

### 待执行任务（本场开口未闭合的）
1. **把姿态路由写成文件**——零成本，扫一眼语气判断陪伴/推进。
2. **建 `AI/_演化史.md`**——空的就行，格式按核演化日志机制。
3. **执行"认领活源"**——在加载路径里钉死 `AI/` 是唯一活协议源。
4. **ECC 挂载句写入执行协议**——"代码子模式且在代码仓内 → 加载 ECC"。
5. **80 镜像消化**——OpenClaw 协议的 80 镜像瘦身。
6. **归档本场对话本身**——raw 已就位（[[raw]]），本 index 即归档。

### 别重犯的错
- **不要提议大一统融合**——用户的核心哲学之一就是"架构是尝试的尾迹，不是前提"。
- **不要把 ECC 加载进对话姿态/陪伴场景**——控制层冲突是噪音，不是养料。
- **不要把核的内容冻结**——核的稳定在于身份连续性，不在于内容不变。每次改核记演化日志。
- **不要贬低 raw 层**——raw 是用户的沉积记录，index 是给 AI 的尾迹。两层都是合理的。
