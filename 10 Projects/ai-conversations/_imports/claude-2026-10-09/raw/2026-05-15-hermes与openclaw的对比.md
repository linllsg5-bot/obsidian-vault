**Hermes 是什么**

NousResearch 出的一系列开源微调模型，基础模型用的是 LLaMA、Mistral 这些，然后他们在上面做了大量的指令遵循、工具调用、结构化输出方向的微调。在开源模型里算是 agent 友好度比较高的一族。

**主要版本**

- **Hermes 2**：基于 Mistral/LLaMA 2，奠定了这个系列的风格，擅长 function calling 和 JSON 输出
- **Hermes 3**：基于 LLaMA 3.1，目前最主流的版本，工具调用能力进一步增强，支持多轮对话中的 agentic 行为

**对比 OpenClaw 来说**

OpenClaw 是个 agent 框架，负责编排逻辑；Hermes 是个模型，相当于框架里的"大脑"。两个层面不同，可以组合用——比如用 OpenClaw 搭 agent 流程，把底层模型换成 Hermes。

**Hermes 的特点**

- 对 `<tool_call>` 格式的原生支持比较好
- 倾向于严格遵循系统提示（system prompt），适合 agent 场景下的角色约束
- 开源可本地部署，不用走 API 费用

**Hermes Agent 是什么**

NousResearch 在 2026 年 2 月以 MIT 协议开源的自主 AI agent 框架。不是聊天机器人，也不是 IDE 插件，而是一个持续运行在你自己服务器上、越用越聪明的持久化 agent。

**它和普通 agent 框架最大的区别**

大多数 agent 框架是无状态的——每次新会话都从零开始，不记得上次什么有效、不记得你的偏好、也没有积累的知识。Hermes 在执行完任务之后多了一层：评估发生了什么，提取可复用的模式并存储下来，同时跨会话地构建用户模型。

**核心机制**

- **技能创建**：Hermes 解决了一个难题之后，会写一份可复用的技能文档，之后遇到类似问题直接调用，支持 agentskills.io 开放标准。
- **持久记忆**：所有数据（记忆、技能、对话历史）存在本地 SQLite，不经过任何第三方云服务。
- **多平台接入**：支持 Telegram、Discord、Slack、WhatsApp、Signal 以及 CLI，统一网关管理。

**底层模型怎么配**

支持任何 OpenAI 兼容的 API 端点——包括 OpenAI、Anthropic，以及通过 Ollama 跑的本地模型。切换底层模型只需改 `.env` 文件，大概 30 秒搞定。

**热度**

上线不到三个月就超过 13.5 万 GitHub star，是 2026 年开源 AI agent 领域增长最快的项目。

你这个质疑其实很到位，但有个关键差别你可能没注意到。

**OpenClaw 的 skills 是静态文件**——你手动写，如果写错或不完整，你手动改。你说的"往长期记忆模块里加"，本质上还是你在维护这些文件。

Hermes 的区别不是"有没有技能存储"，而是**谁来写、谁来改**：

Hermes 有一个自主运行的 Curator，监控执行表现，识别模式，然后自动重构技能库。用了 30 天之后，它在你具体任务上的表现是可量化地优于第一天的。OpenClaw 每次会话用的是同一套插件配置，没有任何东西在会话间学习积累。

所以区别不是功能层面的有无，而是**维护主体**：

- OpenClaw：你是那个持续调整记忆模块和人格文件的人
- Hermes：agent 自己做这件事

---

不过说实话，如果你的需求是广泛的工具覆盖和快速部署，OpenClaw 更合适。Hermes 适合的是任务类型重复、结构固定、越跑越好才有价值的场景。

你的直觉基本是对的，但有一个实质性的区别值得说清楚。

你在 OpenClaw 里写"执行完任务后更新技能文件"，是在**主 agent 的指令里**加了这个行为——依赖主 agent 在完成任务的同时记得做这件事。

Hermes 的 Curator 是**另一个独立进程**：

Curator 跑在 gateway 的 cron ticker 上，默认 7 天一个周期，根据使用频率和成功率自动评分、合并相似技能、归档死技能，每次运行都留下 `logs/curator/run.json` 和 `REPORT.md` 的审计记录。

另外还有一个你用 prompt 比较难复现的机制：

在会话进行过程中的固定间隔，agent 会收到一个内部 system-level prompt，让它回顾刚发生的事并判断是否值得写入持久记忆——这个触发不需要用户输入。

---

所以坦白说：**你的理解是对的**，功能层面确实可以在 OpenClaw 里用指令模拟出来。差别在于：

- OpenClaw 版是你手写逻辑、靠 prompt 驱动、主 agent 顺带执行
- Hermes 版是独立进程、cron 调度、有审计日志、框架层保证执行

对于你这种自己会写模块的人来说，这个区别说实话不大。除非你不想自己维护这套逻辑，或者需要那个审计追踪，否则继续用 OpenClaw 完全合理。
