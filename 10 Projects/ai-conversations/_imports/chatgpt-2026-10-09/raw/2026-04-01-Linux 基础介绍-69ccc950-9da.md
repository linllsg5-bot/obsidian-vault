## 1. Linux 到底是什么

严格说，**Linux 原本是内核（kernel）**。

内核是什么？  
就是操作系统最核心的那一块：它直接管理

- CPU 怎么分配
- 内存怎么使用
- 硬盘怎么读写
- 进程怎么运行
- 网络怎么通信
- 权限怎么隔离

你平时真正用的“Linux系统”，通常其实是：

- **Linux 内核**
- 加上一堆 GNU 工具
- shell
- 软件包管理器
- 图形界面
- 各种系统服务

合起来，才是你看到的 Ubuntu、Debian、Arch、CentOS 这些东西。

所以一句话：

**Linux 是心脏。发行版是完整身体。**

---

## 2. 为什么很多人觉得 Linux 很重要

因为它的气质和 Windows、macOS 很不一样。

### Windows
更像“给普通用户准备好的成品机器”。

### Linux
更像“能拆开、能改造、能接线、能重构”的工作台。

它有几个非常关键的特征：

### 开源
代码公开。  
你不是只会“使用”它，你理论上可以读它、改它、重新编译它。

### 组合哲学
Linux 世界很信奉一句话：

**一个工具只做好一件事，然后把这些工具串起来。**

这就导致它特别适合工程、自动化、脚本、服务器。

### 文本至上
很多配置都在文本文件里。  
这意味着系统是可描述、可复制、可迁移、可版本管理的。

### 一切皆文件
这是 Linux 很迷人的地方之一。

硬盘、设备、进程信息、系统接口，很多东西都能被抽象成文件。  
你面对的不是一个神秘黑箱，而是一片可读写的结构。

## 3. Linux 的核心结构，可以怎么理解

你可以把 Linux 想成一个城市。

### 内核
像城市的地下基础设施：电网、水网、交通中枢。  
平时看不见，但一切都由它协调。

### Shell
像你和城市对话的窗口。  
你输入命令，它替你调度系统。

常见 shell：
- bash
- zsh
- fish

### 文件系统
像整个城市的空间布局。  
Linux 不像 Windows 那样 `C:` `D:` 一盘一盘分得很明显。  
Linux 是**一棵从根 `/` 开始的树**。

例如：

- `/home`：用户自己的家
- `/etc`：系统配置
- `/var`：经常变化的数据，比如日志
- `/usr`：大量程序和库
- `/bin`：基础命令
- `/tmp`：临时文件

这棵树不是“美观设计”，而是秩序。

## 4. Linux 最重要的几个概念

### 4.1 文件权限

Linux 很在意“谁能做什么”。

每个文件通常有三组权限：

- 所有者 `user`
- 所属组 `group`
- 其他人 `others`

每组权限里有三种动作：

- `r` 读
- `w` 写
- `x` 执行

比如：

```bash
-rwxr-xr--
```

意思大概是：

- 文件主人：可读可写可执行
- 同组用户：可读可执行
- 其他人：只可读

这套机制，是 Linux 世界秩序感的来源之一。

---

### 4.2 进程

程序放在磁盘上时，只是文件。  
运行起来后，才变成**进程**。

Linux 非常擅长管理进程：

- 启动
- 杀掉
- 挂后台
- 查看资源占用
- 让多个进程通信

常见命令：

```bash
ps
top
htop
kill
killall
```

你之前折腾 Docker、OpenClaw、gateway、端口冲突，其实本质上都在跟**进程**打交道。

---

### 4.3 管道与重定向

这是 Linux 最有力量的地方之一。

```bash
command1 | command2
```

`|` 叫管道。  
前一个命令的输出，直接变成后一个命令的输入。

例如：

```bash
ps aux | grep python
```

意思是：

- 先列出所有进程
- 再筛选出含有 python 的行

重定向：

```bash
>    覆盖写入文件
>>   追加写入文件
<    从文件读取输入
```

比如：

```bash
echo hello > a.txt
```

这是在把“hello”写入文件。  
这时命令行就不只是交互工具，而是**构造信息流的地方**。

---

### 4.4 包管理器

Linux 安装软件，不是随便去网站点个 exe。

它更常见的是通过包管理器安装：

- Debian / Ubuntu：`apt`
- Arch：`pacman`
- Fedora：`dnf`

比如：

```bash
sudo apt update
sudo apt install git
```

这种方式的好处是：

- 依赖关系统一管理
- 更新方便
- 卸载干净
- 适合自动化部署

---

### 4.5 root 与 sudo

Linux 里，普通用户不是皇帝。

真正拥有最高权限的是 `root`。  
普通用户如果要临时提升权限，常用：

```bash
sudo
```

这很重要，因为 Linux 默认假设：

**力量越大，越要克制。**

## 5. Linux 发行版是什么

Linux 内核只有一个大方向，但用法可以长出很多分支，这就是发行版。

常见几个：

### Ubuntu
最适合入门。  
资料多，社区大，软件兼容好。

### Debian
比 Ubuntu 更稳，更“老派”，服务器很常见。

### Arch Linux
更自由、更原教旨，也更折磨人。  
安装和维护过程本身就是学习。

### CentOS / Rocky / AlmaLinux
偏服务器生态，和企业环境关系更深。

你可以粗暴地理解：

- **Ubuntu**：友好
- **Debian**：稳
- **Arch**：纯、硬、能学到底层

## 9. Linux 最难的地方，不是命令本身

而是它要求你改变思维。

Windows 常常让你问：

“按钮在哪？”

Linux 更像在问你：

“这个系统结构是什么？这件事本质上是在操作什么对象？”

比如你遇到“端口被占用”。

Windows 用户容易停留在：
- 软件坏了
- 关了重开

Linux 思维会继续追：
- 哪个进程占用了端口？
- 这个进程是谁启动的？
- 是 systemd 托管的吗？
- 配置文件在哪？
- 日志写了什么？
- 是监听在 `127.0.0.1` 还是 `0.0.0.0`？
- 是权限问题、依赖问题，还是网络绑定问题？

Linux 不只是系统。  
它在训练一种**结构化排错能力**。

1. **路径 / 文件 / 目录**

5. **端口 / 网络连接**

# 第一部分：你点名的命令，我先给你讲透

---

## 一、路径与文件：`pwd ls cd mkdir rm cp mv`

这组命令处理的是：

**我在哪，我要去哪，我要造什么，我要删什么，我要改什么。**

---

### 1) `pwd`
**print working directory**

显示你当前所在目录。

```bash
pwd
```

输出类似：

```bash
/home/lnp/project
```

它回答的不是“你打开了哪个窗口”，而是：

**当前这个 shell 的工作位置在哪里。**

你后面很多命令，都是相对这个位置执行的。

---

### 2) `ls`
列出目录内容。

```bash
ls
ls -l
ls -a
ls -lh
ls -la
```

最重要的是这几个选项：

- `-l`：长格式，显示权限、所有者、大小、时间
- `-a`：显示隐藏文件（以 `.` 开头）
- `-h`：让大小更可读，比如 `K M G`

例如：

```bash
ls -lah
```

你会看到：

```bash
drwxr-xr-x  3 lnp lnp 4.0K Apr  1  test
-rw-r--r--  1 lnp lnp  123 Apr  1  a.txt
```

这里不是“看文件列表”那么简单。  
这里已经把**权限、文件类型、归属关系**都暴露出来了。

---

### 3) `cd`
切换目录。

```bash
cd /home/lnp
cd ..
cd ~
cd -
```

你至少要熟这几个：

- `cd ..`：回上一级
- `cd ~`：回家目录
- `cd -`：切回上一次所在目录

最核心的概念不是命令本身，而是：

### 绝对路径
从根 `/` 开始写完整路径。

```bash
cd /etc/nginx
```

### 相对路径
相对于当前目录。

```bash
cd ../project/logs
```

Linux 里，路径感非常重要。  
路径感差，后面会一直乱。

---

### 4) `mkdir`
创建目录。

```bash
mkdir test
mkdir -p a/b/c
```

`-p` 很重要。  
表示如果中间目录不存在，就一起创建，不报错。

比如：

```bash
mkdir -p ~/lab/week1/logs
```

---

### 5) `rm`
删除文件或目录。

```bash
rm a.txt
rm -r dir1
rm -rf dir1
```

这里要非常小心。

- `-r`：递归删目录
- `-f`：强制，不提示

`rm -rf` 是很危险的。  
它的本质不是“放进回收站”，而是直接移除目录项，往往不可逆。

先养成习惯：

```bash
rm -i file
```

会先询问。

---

### 6) `cp`
复制。

```bash
cp a.txt b.txt
cp -r dir1 dir2
```

- 复制文件：`cp 源 目标`
- 复制目录：要加 `-r`

---

### 7) `mv`
移动，或者重命名。

```bash
mv a.txt b.txt
mv a.txt dir/
```

它有两个常用意义：

### 重命名
```bash
mv old.txt new.txt
```

### 移动
```bash
mv file.txt ~/project/
```

注意：  
在同一文件系统里，`mv` 往往不是“复制再删除”，而是直接改目录记录，所以通常很快。

---

## 二、看文本：`cat less grep find`

Linux 很多东西最终都会落到文本上。

配置是文本。  
日志是文本。  
报错是文本。  
命令输出还是文本。

所以你要会“看”和“筛”。

---

### 8) `cat`
最直接地输出文件内容。

```bash
cat a.txt
```

也常用于快速拼接或查看小文件。

比如：

```bash
cat /etc/os-release
```

但它不适合看大文件。  
大文件直接 `cat`，一股脑冲出来，很蠢。

---

### 9) `less`
分页查看文件。

```bash
less a.log
```

这才是看日志、看长配置文件的常用工具。

常见操作：

- `j` / `k`：上下移动
- `/关键字`：搜索
- `n`：下一个匹配
- `q`：退出

你以后看 OpenClaw 日志、systemd 日志、配置文件，`less` 会比 `cat` 更常用。

---

### 10) `grep`
在文本里筛选内容。

```bash
grep python file.txt
grep -n error app.log
grep -i failed app.log
grep -r openclaw .
```

常见选项：

- `-n`：显示行号
- `-i`：忽略大小写
- `-r`：递归搜索目录

经典组合：

```bash
ps aux | grep openclaw
```

意思是：

- 先列出进程
- 再筛出含 openclaw 的行

`grep` 本质上是文本过滤器。  
Linux 世界里，大量信息流靠它切开。

---

### 11) `find`
在文件系统里找文件。

```bash
find . -name "*.log"
find /etc -name "nginx.conf"
find . -type d
find . -type f
```

常见条件：

- `-name`：按文件名找
- `-type f`：只找文件
- `-type d`：只找目录

例如：

```bash
find ~/.openclaw -name "*.json"
```

这对你这种会折腾配置的人非常有用。

## 三、权限：`ls -l`、`chmod`、`chown`

Linux 不只是“有没有文件”。  
更关心：

**谁拥有它，谁能碰它，谁不能碰它。**

---

### 1) 先看 `ls -l`

例如：

```bash
-rwxr-xr-- 1 lnp lnp 1200 Apr 1 run.sh
```

拆开看。

#### 第一位：文件类型
- `-` 普通文件
- `d` 目录
- `l` 链接

#### 后面九位：权限
分三组：

- `rwx`：所有者 user
- `r-x`：组 group
- `r--`：其他人 others

其中：

- `r` = read 读
- `w` = write 写
- `x` = execute 执行

所以这个文件表示：

- 所有者：可读可写可执行
- 同组：可读可执行
- 其他人：只可读

---

### 2) `chmod`
修改权限。

#### 符号写法
```bash
chmod u+x run.sh
chmod g-w file.txt
chmod o-r secret.txt
```

- `u`：user
- `g`：group
- `o`：others
- `a`：all

#### 数字写法
这是你必须会的。

- `r = 4`
- `w = 2`
- `x = 1`

所以：

- `7 = rwx`
- `6 = rw-`
- `5 = r-x`
- `4 = r--`

例如：

```bash
chmod 755 run.sh
chmod 644 file.txt
```

### `755`
- owner: rwx
- group: r-x
- others: r-x

### `644`
- owner: rw-
- group: r--
- others: r--

最常见的理解：

- **脚本 / 可执行文件**：常见 `755`
- **普通文本文件**：常见 `644`

---

### 3) `chown`
改所有者。

```bash
sudo chown lnp file.txt
sudo chown lnp:lnp file.txt
sudo chown -R lnp:lnp mydir
```

- 前一个 `lnp`：用户
- 后一个 `lnp`：组

很多“权限不够”问题，不是 chmod 的问题，而是这个文件根本不是你的。

比如 Docker 或 sudo 产生的文件，可能归 `root`。  
你编辑不了，不一定是“坏了”，而是**归属不对**。

---

### 4) 最容易被忽略的一点：目录权限和文件权限不一样

这是重点。

对于**目录**来说：

- `r`：能列出里面有什么
- `w`：能改里面的目录项
- `x`：能进入这个目录

所以目录的 `x` 不只是“执行”，更像“通行权”。

有时候一个目录有 `r` 但没 `x`，你能知道它存在，却进不去。  
这就是 Linux 那种冷静又残酷的秩序感。

## 四、进程和端口：`ps top kill ss -tulpn lsof`

这一组是系统排障核心。

你之前遇到的：

- 端口占用
- 服务没起来
- gateway 不可达
- Docker 端口冲突
- 某个程序死循环

本质都落在这里。

---

### 1) 什么是进程

程序文件在磁盘上时，只是代码。  
运行起来后，变成一个**进程**。

比如：

- 你开一个 Python 脚本 → 一个进程
- 开 Docker daemon → 一个进程
- OpenClaw gateway → 一个进程
- Nginx → 一个或多个进程

Linux 系统的活性，靠的就是一堆进程。

---

### 2) `ps`
查看进程。

```bash
ps
ps aux
ps -ef
```

最常用是：

```bash
ps aux
```

含义大致是：

- `a`：看所有终端用户的进程
- `u`：用户格式显示
- `x`：包括没有终端的后台进程

配合 `grep`：

```bash
ps aux | grep openclaw
ps aux | grep python
```

这会快速看某个进程是不是在跑。

---

### 3) `top`
实时看系统资源。

```bash
top
```

你会看到：

- CPU
- 内存
- 进程列表
- 每个进程资源占用

如果装了 `htop`，体验更好：

```bash
htop
```

它更直观。

当你怀疑某个 agent、某个 worker、某个模型服务在疯狂吃资源时，先看这里。

---

### 4) `kill`
给进程发信号。

```bash
kill PID
kill -9 PID
```

默认 `kill PID` 发送的是 `SIGTERM`，意思是：

**请你正常结束。**

而：

```bash
kill -9 PID
```

是 `SIGKILL`，意思是：

**我不跟你谈了，直接强制终止。**

先用普通 `kill`，别一上来 `-9`。  
`-9` 像一把斧子。

---

### 5) 端口是什么

一个程序如果要接收网络请求，往往要监听某个端口。

比如：

- 3000：web 界面
- 11434：ollama
- 18789：OpenClaw gateway
- 18791：browser control

端口不是“程序”，而是**程序在网络里的入口编号**。

---

### 6) `ss -tulpn`
查看端口监听情况。

```bash
ss -tulpn
```

你可以理解为：

- `t`：tcp
- `u`：udp
- `l`：listening
- `p`：显示进程
- `n`：数字显示，不解析名称

最常用实际是：

```bash
ss -tulpn | grep 3000
ss -tulpn | grep 18789
```

这能回答：

- 端口有没有在监听
- 谁在监听
- 绑定在哪个地址上

例如：

```bash
LISTEN 0 511 127.0.0.1:18789 ...
```

说明它只监听本机回环。

而：

```bash
0.0.0.0:3000
```

说明所有网卡都能访问。

这个区别很重要。

---

### 7) `lsof`
list open files

```bash
lsof -i :3000
lsof -i :18789
```

Linux 世界里，“一切皆文件”。  
网络 socket 也算“打开的文件”。

所以 `lsof` 很强：  
它不仅看普通文件，还能看端口、连接、句柄占用。

查端口占用时：

```bash
sudo lsof -i :3000
```

通常非常好用。
