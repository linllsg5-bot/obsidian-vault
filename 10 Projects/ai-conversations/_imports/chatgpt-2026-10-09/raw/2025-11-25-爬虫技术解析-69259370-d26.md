## HTML 的定义（最本质的那一句）
**HTML 是一种用来描述网页内容结构的标记语言。**

不是编程语言，  
不负责计算，不负责逻辑。

它只做一件事：  
**告诉浏览器：页面上有哪些内容，以及它们彼此之间的结构关系。**

---

## 它的本质
HTML 的本质是：

> 一份“结构说明书”，让浏览器能够把信息组织成页面。

它的作用不是显示漂亮的效果，  
而是告诉浏览器“这是什么”。

比如：

| 标签 | 意义 |
|------|-----|
| `<h1>` | 这是标题 |
| `<p>`  | 这是段落 |
| `<img>` | 这是一张图片 |
| `<a>` | 这是一个超链接 |
| `<ul>` `<li>` | 这是一个列表和列表项 |
| `<table>` | 这是表格 |
| `<form>` | 这是表单 |

只要浏览器读懂了这些结构，就能“把一堆文本和资源变成一个页面”。

---

## 为什么会出现 HTML？
因为在互联网的早期，人们想在网上分享信息。  
但**信息不是纯文本就够了**——它需要形式。

比如想告诉别人：

- 这里有一篇文章
- 那是一张图
- 这是表格
- 这个词是超链接
- 那段文字是标题而不是正文

光靠纯文本无法表达这样的**结构**。

于是产生了 HTML——  
一种人为约定的**通用标记系统**，  
让浏览器知道如何排布内容。

没有 HTML，互联网的页面只会是一堆混乱的字符串，  
没有层次、没有顺序、没有可读性。

# 大局观（先有方向）
网页表面是 DOM + HTML，但真实的样式和很多“显示内容”往往不是静态 HTML：
- CSS 可能来自 `<link>` 的外链、`<style>` 的内联、或 JS 在运行时用 CSSOM 动态插入（`insertRule`、`adoptedStyleSheets`）。  
- 有 Shadow DOM / Web Components，会把规则封闭，不在主 document 的样式表里。  
- CSS 里可能包含 `url(...)` 指向图片 / sprite / data URI。  
- 真正的数据（章节、图片地址）常通过 XHR/fetch/WebSocket 从 API 拉来，JS 用这些数据去填 DOM 或生成内联样式。  

看清这些，你就能决定要抓“样式表”还是抓“请求”。

# 开发者工具的正确打开顺序（路线图）
1. F12 → **Elements**（检查实时 DOM / Shadow DOM / iframe）  
2. **Styles** 面板：查看元素对应的样式来源（右侧会显示 rule 的文件与行号）

# 控制台实用脚本（复制黏贴即用）

### 1) 列出页面加载的样式表与来源
```js
Array.from(document.styleSheets).map(ss=>{
  try{
    return {
      href: ss.href || 'inline <style>',
      rules: ss.cssRules ? ss.cssRules.length : 'cross-origin or blocked'
    }
  }catch(e){
    return {href: ss.href || 'inline <style>', error: e.message}
  }
})
```
> 如果看到 `cross-origin`，说明样式表被跨域保护；需要在 Network 面板中直接打开该 CSS 请求查看响应头/内容。

### 2) 在所有样式表里搜索包含 `url(...)` 的规则（找图片或 sprite）
```js
const urls = [];
Array.from(document.styleSheets).forEach(ss=>{
  try{
    Array.from(ss.cssRules || []).forEach(r=>{
      const s = r.cssText || '';
      const m = s.match(/url\(([^)]+)\)/g);
      if(m) m.forEach(u=>{
        urls.push({href: ss.href || 'inline', url: u.replace(/url\(|\)|["']/g,'')})
      })
    })
  }catch(e){}
});
console.table(urls);
```

### 3) 列出对某个选择器生效的规则并定位源文件
```js
function findRulesFor(sel){
  const res=[];
  Array.from(document.styleSheets).forEach(ss=>{
    try{
      Array.from(ss.cssRules || []).forEach(r=>{
        if(r.selectorText && r.selectorText.includes(sel)) res.push({sheet: ss.href||'inline', rule: r.cssText})
      })
    }catch(e){}
  });
  return res;
}
// 用法： findRulesFor('.chapter-image')
```

### 4) 列出所有 Shadow Roots（检测 web components）
```js
(function scan(root=document){
  const res=[];
  const walker = document.createTreeWalker(root, NodeFilter.SHOW_ELEMENT);
  let n=walker.currentNode;
  while(n){
    if(n.shadowRoot) res.push({tag: n.tagName, node: n, shadow: !!n.shadowRoot});
    n = walker.nextNode();
  }
  return res;
})()
```

### 5) 抓取页面上所有图片 URL（DOM + CSS 背景图）
```js
const imgs = Array.from(document.images).map(i=>i.src);
const bg = [];
Array.from(document.querySelectorAll('*')).forEach(el=>{
  const s = getComputedStyle(el).backgroundImage;
  if(s && s !== 'none') bg.push(s.replace(/url\(|\)|["']/g,''));
});
Array.from(new Set(imgs.concat(bg)))
```

### 6) 监测样式表或 style 元素的动态插入（当页面用 JS 生成 CSS）
```js
new MutationObserver(muts=>{
  for(const m of muts){
    m.addedNodes && m.addedNodes.forEach(n=>{
      if(n.tagName === 'STYLE' || (n.tagName==='LINK' && n.rel==='stylesheet')) console.log('新样式:', n);
    })
  }
}).observe(document.documentElement, {childList:true, subtree:true});
```

# 如果样式是被 JS 动态生成（常见）怎么办？
- 在 **Sources → pretty print** JS，寻找 `insertRule`、`adoptedStyleSheets`、`.style.cssText`、`.className =`、`element.style.setProperty` 等语句。  
- 在 Network 的 `XHR` 里找请求到的 JSON，看它是否包含：className、style、img list、base64 等。  
- 用上面的 MutationObserver 捕获何时生成 `<style>`，并在触发时打印 `newStyle.innerText`。

# 常见“迷雾”与排查技巧
1. **被加密/签名的资源 URL**：看请求 URL 里是否有签名参数（timestamp+sign）。那通常要逆向生成签名（查看对应 JS 文件）。  
2. **Service Worker / Cache 存资源**：Application → Service Workers；有时资源不是直接从网络而是从 SW 的 cache 中读出。  
3. **CSP / cross-origin 限制**：若样式表来自第三方，控制台会报错或阻止访问 `cssRules`。可在 Network 打开该 CSS 文件直接查看。  
4. **内联样式被覆盖**：Computed Style（右侧的 Computed 面板）是你最后的真相，告诉你最终生效的值。  
5. **CSS Module / 哈希类名**：类名是随机哈希，可以通过观察在运行时生成的映射（JS 中可能有映射对象）去定位真实含义。

# 要找“整站内容”时的思路（从样式过渡到数据）
- 先用 Network → XHR 观察页面交互：加载章节时在哪个请求返回 JSON 或图片清单？  
- 找到那个请求的 Response，复制它的 URL、Headers（尤其是 Referer、Cookie、Authorization）并在 curl 或脚本里模拟。  
- 如果请求参数被混淆/加密，打开相应的 JS（Sources）寻找签名函数或时间戳逻辑。  
- 如果是 WebSocket：在 Network → WS 里看传输内容。  
- 有些站把图片做成分片或 sprite，或用 base64 嵌在 CSS 中（用上面脚本找 `url(...)` 或 data URI）。

# 进阶工具（当 DevTools 不够）
- Headless 浏览器：Puppeteer / Playwright（能像真实浏览器一样执行 JS，得到最终 DOM、样式）  
- 抓包：mitmproxy / Fiddler（可观察被 JS 发出的真实请求与响应，重放请求）  
- 反混淆：在本地把 JS pretty-print，然后用断点（Sources → Event Listener Breakpoints，XHR/fetch）逐步跟踪请求生成过程。
