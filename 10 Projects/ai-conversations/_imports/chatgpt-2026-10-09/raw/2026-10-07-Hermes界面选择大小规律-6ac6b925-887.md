## assistant

如果你说的是现在的 **Hermes Agent**，我会直接选：

> **TUI > GUI > 经典 CLI**

而且对你来说，我更推荐 **TUI**。

官方现在也明确把 TUI 定位成 Hermes 的**推荐交互方式**；它和经典 CLI 用的是同一个 agent、同一套 session、slash commands 和运行时，本质上不是换了一个 Agent。citeturn0search1turn0search4

### 三个东西其实不是“能力等级”

| | TUI | GUI / Desktop | CLI |
|---|---|---|---|
| Agent能力 | **一样** | **一样** | **一样** |
| 工具调用 | 一样 | 一样 | 一样 |
| Session / Memory | 一样 | 一样 | 一样 |
| 操作体验 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| 看 Agent 工作过程 | **很好** | 好 | 好 |
| 键盘效率 | **最高** | 中等 | 高 |
| 适合长期跑项目 | **很适合** | 很适合 | 适合 |
| 适合脚本/自动化 | 好 | 一般 | **最好** |

Hermes Desktop 现在也是同一个 agent core，不是一个“缩水 GUI”；官方文档明确说 Desktop、CLI、TUI、Gateway 共用配置、API key、sessions、skills、memory。citeturn0search10

### 为什么我给你 TUI

你现在不是单纯“聊天问 AI”。

你实际上是在把 Hermes 当成一个：

**Agent → 思考 → 调工具 → 改代码 → 跑程序 → 查看结果 → 再决定下一步**

的长期工作环境。

这时候 GUI 的视觉确实舒服，但容易把 Agent 变成一个“软件窗口里的聊天机器人”。

TUI 反而比较接近你现在在折腾的 **Codex / pi / OpenClaw 那种工程环境**。

尤其 Hermes 新 TUI 已经有一些对你非常有价值的东西：

- `/agents` 可以看到**子 Agent 树**
- 可以暂停 / kill 子任务
- 可以看到每个分支的 token / cost / 文件变化
- `/usage` 看 token、cost、context
- `/details` 看详细 tool-call
- session 可以继续、恢复、按项目目录恢复
- 可以鼠标操作，但仍然保持终端工作流。citeturn0search6

这个其实挺符合你之前一直想看的东西：

> **“我不是只想知道 Agent 最后的答案，我想知道它内部到底发生了什么。”**

所以我甚至会建议你：

```bash
hermes --tui
```

然后把 TUI 当**主入口**。

GUI 留着做配置、浏览 session、偶尔图形化操作；CLI 则留给脚本、管道、自动化。

---

还有一个很重要的点：

**TUI 不会让 Hermes “更聪明”。**

它只是让你**更容易观察和控制同一个 Hermes Agent**。所以如果你现在是在比较“哪个界面会让 Hermes 完成项目质量更高”，答案不是 TUI 本身提高智力，而是 **TUI 的可观察性和交互控制可能让你更容易干预 Agent 的错误路径**。

对你这种经常想拆解 Agent 行为的人，这个差别反而很大。 citeturn0search1
