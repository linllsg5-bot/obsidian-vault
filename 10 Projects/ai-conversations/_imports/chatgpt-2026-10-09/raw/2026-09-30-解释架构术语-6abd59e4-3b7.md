# 解释架构术语
> 来源：ChatGPT 导出 `a653a614a5dc39b44a4fc20a01bcf3297cb01cad521120f1b2db3323cdadd864-2026-10-09-01-01-54-530ee6578da54e2d9a99ca9e9c6e3017 (1).zip`；本文件是原始会话的可读投影，不是总结。

## user

我立刻想做的是给你一套架构——substrate 分几层、binding 存哪张表、residual 用什么数据结构

解释下这句话，各个含义

## assistant

这句话其实已经从“讨论理念”切到了**准备把理念落进软件结构**。

> **“我立刻想做的是给你一套架构——substrate 分几层、binding 存哪张表、residual 用什么数据结构。”**

翻成人话就是：

**我现在很想直接开始设计系统：底层长期积累的东西怎么分层；新形成的关系到底怎么存进数据库；那些暂时解释不了、没被吸收掉的差异又以什么形式保存。**

这里三个词分别对应三种完全不同的东西。

### 1. substrate：承载后续认识的“底层基质”

`substrate` 原义是**基底、底层、承载物**。

放到我们之前谈的那个项目里，它不是简单的“数据库”。

更准确地说，它是：

\[
\text{过去活动留下的、以后还能被重新调用的结构}
\]

比如一次探索之后，AI不只是记住：

> 猫是动物。

而可能留下：

```text
对象：
猫
动物

关系：
猫 --属于--> 动物

观察方式：
可以按照“种属关系”去组织对象

操作：
遇到新对象时，可以尝试问：
“它属于哪一类？”
```

这些东西以后又参与新的认识。

这整个可持续存在、可继续被使用的底层，就可以叫 **substrate**。

所以：

> **substrate 分几层**

是在问：

这些沉淀下来的东西是不是应该区分层级。

例如可能设计成：

```text
Substrate

L0  原始经历
    ↓
L1  对象 / 特征
    ↓
L2  关系
    ↓
L3  模式 / 结构
    ↓
L4  操作方式
    ↓
L5  观察框架
```

不是一定要这么分，这只是架构问题。

---

### 2. binding：这一次到底“连上了什么”

`binding` 可以理解成：

**绑定、联结、关系实例。**

它关注的不是“东西是什么”，而是：

\[
A \leftrightarrow B
\]

为什么这两个东西现在被联系到了一起。

举个更接近你的项目的例子。

AI看到：

```text
苹果掉落
雨滴掉落
石头掉落
```

后来形成：

```text
苹果 ─┐
雨滴 ─┼── falling
石头 ─┘
```

这个“苹果”和“falling”之间建立起来的联系，就是一个 binding。

但实际系统里它可能复杂很多：

```json
{
  "source": "apple",
  "target": "falling",
  "relation": "exhibits",
  "context": "observation_192",
  "confidence": 0.84,
  "origin": "exploration_27"
}
```

所以：

> **binding 存哪张表**

已经是数据库设计问题了。

例如你可能有：

```text
entities
---------
id
type
content


bindings
--------
id
source_id
target_id
relation_type
context_id
strength
created_at
```

于是：

```text
entity 17 = 苹果
entity 42 = falling

binding:
17 → 42
relation = exhibits
```

这里重要的一点是：

**substrate 是整个长期结构；binding 是这个结构内部具体的连接。**

可以想象成神经网络：

```text
substrate ≈ 整张网络

binding ≈ 网络中的某条连接
```

虽然并不是严格等价。

---

### 3. residual：当前结构“吃不掉”的东西

这个其实是三者里我认为最有意思的。

`residual` = **残差 / 剩余 / 未被解释掉的差异**。

假设AI当前认为：

```text
鸟 → 会飞
```

然后遇到：

```text
企鹅 → 鸟
企鹅 → 不会飞
```

如果系统只是把新信息硬塞进旧知识：

```text
鸟会飞
企鹅是鸟
```

它可能直接产生矛盾。

但如果存在 residual：

```text
current model:
鸟 → 会飞

observation:
企鹅 → 不会飞

residual:
“鸟→会飞”这个结构无法解释企鹅
```

数学上非常像：

\[
Residual
=
Observation - Prediction
\]

也就是：

\[
r=x-\hat{x}
\]

已有结构预测：

\[
\hat{x}
\]

实际观察：

\[
x
\]

二者之间的差：

\[
r
\]

就留下来。

于是系统不会马上强迫自己得出答案，而是保存：

```text
异常
矛盾
尚未解释的变化
无法归类的对象
预测失败
结构覆盖不到的部分
```

这些都可以成为 residual。

之后 accumulated residual 足够多：

```text
企鹅不会飞
鸵鸟不会飞
鸸鹋不会飞
```

系统才可能重新修改原来的结构：

```text
旧结构：
鸟 → 会飞

↓

新结构：
大多数鸟 → 飞行能力

某些鸟：
飞行能力退化
```

所以 residual 实际承担着一个很重要的功能：

> **让系统知道自己的当前认识在哪里失效。**

---

因此才会问：

> **residual 用什么数据结构？**

因为它到底不是普通文本。

可以有很多设计。

最简单：

```json
{
  "observation_id": 938,
  "expected": "bird.can_fly = true",
  "actual": "penguin.can_fly = false",
  "difference": "contradiction"
}
```

但更复杂时可能需要一个图结构：

```text
Residual
│
├── 触发观察
├── 冲突的 binding
├── 当前 hypothesis
├── discrepancy
├── unresolved questions
└── 后续探索记录
```

也就是说，一个 residual 可能不是：

```text
error = 0.42
```

而是一整个“尚未解决的问题对象”。

---

把三个放在一起，就很好看了：

```text
             外部活动 / observation
                      │
                      ▼
                ┌──────────┐
                │ substrate│
                │ 当前结构 │
                └────┬─────┘
                     │
              尝试理解 / 匹配
             ┌───────┴────────┐
             ▼                ▼
         能解释             解释不了
             │                │
             ▼                ▼
          binding          residual
        建立新关系          保留差异
             │                │
             └──────┬─────────┘
                    ▼
              substrate 改变
```

于是有一个很漂亮的循环：

\[
\text{Experience}
\rightarrow
\text{Binding}
\rightarrow
\text{Substrate}
\]

同时：

\[
\text{Experience}
-
\text{Existing Structure}
\rightarrow
\text{Residual}
\]

而 residual 又可能推动：

\[
\text{Residual}
\rightarrow
\text{Exploration}
\rightarrow
\text{New Structure}
\]

所以原来那句话的真正意思并不只是三个技术名词。

它是在说：

**“我已经开始想把‘认识如何留下、关系如何形成、差异如何推动新的认识’翻译成真实的软件对象、数据库和数据结构了。”**

而这三者大概分别对应：

\[
\boxed{
Substrate = 已经形成的世界
}
\]

\[
\boxed{
Binding = 正在形成的联系
}
\]

\[
\boxed{
Residual = 这个世界还无法容纳的东西
}
\]

最后这个 `residual`，其实很可能会成为你那个项目里非常核心的一层——因为没有 residual，系统就很容易从“持续形成认识”退化成**不断往已有知识库里塞东西**。
