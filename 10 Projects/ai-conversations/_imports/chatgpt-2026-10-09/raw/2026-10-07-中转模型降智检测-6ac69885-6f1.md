而且如果你说的是 **“中转站把原本的模型偷偷换成更弱的模型 / 降低推理能力 / 改参数”**，我觉得最实用的不是跑一堆 benchmark，而是做一个很小的**“能力指纹测试”**。

### 一招：同一道「需要真正推理」的问题，直连 vs 中转，盲测

不要问知识题，也不要问“你是谁”。

给模型一个**新颖、短小、可验证、没有现成模板可套的题**，例如：

> 有 12 个外观完全相同的球，其中恰好一个重量不同，但不知道它更重还是更轻。  
> 只能使用天平称 3 次。  
> 请给出一个必然成功的策略，并解释为什么每一种结果都不会导致歧义。

然后：

- A：官方 API / 官方 ChatGPT 对应模型
- B：中转站
- **完全相同的 system prompt、temperature、max tokens**
- 最好各跑 **3～5 次**
- 不告诉自己哪个是 A/B
- 看的是**能不能稳定解决**，而不是文风。

如果一个模型连续能解决，而另一个明显经常：

- 漏情况
- 自相矛盾
- 把条件读错
- 推理到一半突然简化
- 给出“看起来很完整但实际上不能保证”的答案

那基本已经抓到降级了。

---

但我觉得你真正想要的是更狠的：

## 「一招」不是一道题，而是一个能力探针

可以专门设计这种：

> **模型很难靠语言风格蒙混过去，但答案可以机械验证。**

比如：

**数学构造题 → 代码执行题 → 逻辑约束题**

三种任选一种。

尤其是代码：

```text
给你一个长度最多为 10^6 的整数数组。
要求：
1. O(n log n) 以内
2. 不能使用额外 O(n) 空间
3. 找出出现次数超过 n/3 的所有元素
4. 给出 Python 实现
5. 不允许调用排序
```

然后直接执行它。

这就比“让另一个 AI 判断答案好不好”强得多，因为**代理本身无法靠漂亮话骗过测试**。

---

### 还有一个非常关键的办法：测「难度拐点」

这其实比单题更能抓到中转降智。

比如准备：

```text
Level 1  很简单
Level 2  简单推理
Level 3  多步推理
Level 4  新颖问题
Level 5  多约束构造
Level 6  复杂代码/数学
```

分别记录：

```text
官方模型：√ √ √ √ √ ×
中转模型：√ √ √ × × ×
```

那么你甚至不需要知道中转站到底做了什么。

**它的能力曲线已经暴露了。**

这和现在一些模型退化检测研究的思路也是一致的：不要只比较一个总分，而是比较**逐样本结果**，统计上可以判断性能差异究竟是真退化还是随机波动。ICLR 2026 的一项工作甚至报告可以检测到约 0.3% 的准确率下降。citeturn0search5

### 如果是你现在这个「中转站 + Codex」场景

我反而建议你别测普通聊天。

直接测：

> **Codex 能不能完成一个它以前能完成、而且结果可以检查的任务。**

例如让两个端点同时：

1. 阅读一个小项目
2. 找一个指定 bug
3. 修改代码
4. 跑测试
5. 解释修改原因

最后比较：

```text
测试是否通过       ← 最重要
修改文件数量
是否误改其它东西
是否完成要求
是否出现幻觉
token / 时间
```

这比问：

> “你是不是 GPT-5.6？”

强太多了。

因为**模型可以骗你自己是什么模型，但很难伪造一个真正成功运行的程序。**

---

还有一个很有意思的东西：

如果你怀疑中转站**没有换模型，只是把 reasoning effort / thinking budget 降了**，那么可以做一个非常漂亮的实验：

**同一个问题连续跑 10 次，逐渐提高允许输出 token / reasoning budget。**

如果：

```text
低预算：经常失败
中预算：开始成功
高预算：稳定成功
```

那更像是**推理预算被压缩**。

如果：

```text
怎么加预算都不行
```

而官方端可以，那就更像是**模型本身被换了 / 模型版本不同**。

如果你愿意，我可以直接给你做一套 **「中转站降智检测器」**：大概 10 个问题，最后自动给出一个 **0～100 的“与官方模型一致度”**，甚至可以直接拿 Python 对两个 OpenAI-compatible API 跑。
