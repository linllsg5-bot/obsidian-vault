当你在 **Windows CMD** 里直接粘贴带 **“`\`”** 的多行 Linux 命令时，CMD 会把每一行当作单独命令来解析，`-p`、`-v` 这类参数就被当成了独立命令，而不是 `docker run` 的参数，因而报出：  
> `docker: invalid reference format` citeturn0search0  
> `'-p' 不是内部或外部命令……` citeturn0search1  

在 Windows 下，反斜杠 `\` 并 **不** 用作行续接符，只有在 **Unix/Linux Shell**（如 Bash）中才会被当成续行符【turn0search5】。

---

## ✅ 解决方案一：用 **单行** 命令

最简单的做法就是把所有参数写成一行，去掉所有 `\`，比如：

```bat

```
- 这样 CMD 会把整条命令一次性发给 Docker，所有端口映射、挂载卷、容器名都会正确识别 citeturn0search20。  
- 如果镜像尚未拉取，Docker 会自动 `pull`，然后启动容器 citeturn0search3。

> 注意：**CMD**（`cmd.exe`）不支持反引号续行，切换到 PowerShell（`powershell.exe`）或 Windows Terminal 就能使用。

下面这个错误：

```
Error response from daemon: Get "https://ghcr.io/v2/": dialing ghcr.io:443 … lookup ghcr.io: no such host
```

意味着 Docker **守护进程无法解析** `ghcr.io` 的域名，属于 DNS 解析或网络访问问题，而不是镜像本身不存在。下面分步说明原因与多种可行的解决办法。

---

## 错误含义

当你执行 `docker pull ghcr.io/...` 时，Docker 守护进程会先做 DNS 查询：

1. **“Unable to find image … locally”**：正常提示，本地未缓存该镜像，接下来会去远程拉取。  
2. **“lookup ghcr.io: no such host”**：DNS 查询失败，主机或 Docker 的内置 DNS 服务器都找不到 `ghcr.io` 这一域名【turn0search0】。  
3. 后续于是无法建立 TCP 连接，自然拉取也就中断了。

---

## 可能原因

1. **Docker 内置 DNS Stub 解析问题**  
   新版 Docker（或 Colima、Docker Desktop 等）通常会在容器网络中启动一个内置 DNS 服务（127.0.0.11/127.0.0.53），再转发给宿主机设置的 DNS 服务器。但如果宿主机的 `/etc/resolv.conf` 指向了不可访问或错误的地址，就会导致容器与守护进程都无法解析域名【turn0search0】。

2. **未为 Docker 守护进程配置 HTTP/HTTPS 代理**  
   如果你在公司网络或通过代理上网，终端可能能走代理访问互联网，但 Docker 守护进程没有继承这些环境变量，就会出现 DNS 解析或直连失败的情况【turn1search2】。

3. **宿主机 DNS 配置不当**  
   主机的网络设置（Wi-Fi、以太网）如果使用了内网 DNS（如路由器、私有 DNS）而这些服务器又不能解析外网域名，也会引起 Docker 找不到 `ghcr.io`【turn1search5】。

4. **企业网络/防火墙限制**  
   某些企业内网或 VPN 会拦截外部 DNS 解析或限制直连，需要额外配置才能访问 GHCR（GitHub Container Registry）。

---

## 解决方案

### 1. 给 Docker 守护进程指定 DNS 服务器

**步骤：**

1. 编辑或新建 `/etc/docker/daemon.json`（Linux）：

   ```jsonc
   {
     "dns": ["8.8.8.8", "8.8.4.4"]
   }
   ```

2. 重启 Docker 服务：

   ```bash
   sudo systemctl daemon-reload
   sudo systemctl restart docker
   ```

这样 Docker 守护进程和所有容器都会直接使用 Google 公共 DNS，绕过本地 stub 解析问题【turn1search4】。

---

### 2. 为 Docker 守护进程配置 HTTP/HTTPS 代理

如果你需要通过企业代理访问外网，必须让 Docker 守护进程也使用同样的代理：

1. 创建或编辑 `/etc/systemd/system/docker.service.d/10-docker-proxy.conf`：

   ```ini
   [Service]
   Environment="HTTP_PROXY=http://proxy.company.com:3128"
   Environment="HTTPS_PROXY=http://proxy.company.com:3128"
   ```

2. 重新加载并重启：

- `requests` 是 Python 中事实上的标准库，用于发送 GET/POST/PUT/DELETE 等 HTTP 请求，获取远程服务的数据【turn0search5】。  
- 用法示例：

## 2. 在 LangChain 中注册一个“工具”（Tool Calling）  
- LangChain 支持把任意 Python 函数“注册”为模型可调用的工具（tool），比如一个封装了 HTTP 请求的函数【turn0search0】。  
- 你只需写出类似下面的函数，并在初始化 LLM 时绑定它：  
  ```python
  def search_news(query: str) -> dict:
      import requests
      resp = requests.get(f"https://api.news.com/search?q={query}")
      return resp.json()

  from langchain import tool_calling_model
  llm = tool_calling_model.bind_tools([search_news])
  ```  
- 模型在对话中识别到需要“联网搜索”时，就会自动调用 `search_news`，拿到返回结果后再继续生成回答【turn0search4】。
