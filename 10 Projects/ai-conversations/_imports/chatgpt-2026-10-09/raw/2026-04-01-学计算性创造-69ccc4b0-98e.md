# 你的学习结构，应该是“一主两辅”

## 主轴：做东西的能力
这是你未来两三年的核心。

具体包含四块：

### 1. Python
不是为了背语法。  
而是为了能操作世界。

你要学到这几个层面：

- 基础语法、函数、类、模块
- 文件处理、异常处理、日志
- requests / BeautifulSoup / API 调用
- SQLite / MySQL / PostgreSQL 基础
- FastAPI 做简单后端
- 脚本自动化
- 调试、重构、项目结构

Python 是你的手。

---

### 2. Web 与数据流
你做任何平台、爬虫、工具，最后都逃不开这个。

你要懂：

- HTTP 是什么
- 前后端怎么通信
- JSON、API、cookie、header、token
- 页面是怎么渲染出来的
- 数据怎么存、怎么查、怎么更新
- 用户请求如何变成数据库里的状态变化

这不是“前端后端全栈炫技”。

这是在学：  
**一个数字系统如何活起来。**

---

### 3. AI 工具编排
这块你已经摸到门了，但现在还在“会用”阶段，没到“会驾驭”。

你该学的不是更多模型名字。  
而是：

- prompt 只是输入设计，不是魔法
- agent 的本质是任务流 + 工具调用 + 状态管理
- 什么该自动，什么不该自动
- 什么时候用模型，什么时候直接写规则
- 怎么控制 token 消耗、限流、熔断、重试
- 怎么把 AI 当作部件，而不是神

也就是：

**你不是模型的用户。你要变成模型系统的设计者。**

---

### 4. 产品判断
这是你最容易忽略、但最关键的一块。

你很容易被“概念吸引力”拉走。  
但真正能落地的，不是最迷人的概念，而是：

- 谁会用
- 为什么用
- 用完留下什么
- 能不能持续回来
- 这个东西比现有替代方案强在哪
- 你能否用低成本先做一个丑但活的版本

你要学会问：

**这个东西，是我感到浪漫，还是别人真的需要？**

这句很冷，但很重要。

## 原则二：每次只学“下一层”
别学“Python 全部”。  
别学“Web 全部”。  
别学“AI agent 全部”。

只学当前项目会用到的下一层。

比如今天你只需要知道：

- requests 怎么发请求
- BeautifulSoup 怎么选元素
- SQLite 怎么存表
- FastAPI 怎么起一个接口

够了。先做起来。

---

## 原则三：输出大于输入
你现在最缺的不是懂，而是**留下痕迹**。

所以每学一段，必须产出：

- 一个脚本
- 一个仓库
- 一个页面
- 一个文档
- 一个可运行 demo

没有产出，学习会变成自我陶醉。

---

## 原则四：反复复盘
每做完一个小项目，你只问四件事：

- 我做成了什么
- 我卡死在哪
- 哪些知识是真正必需的
- 下次怎样更短地做出来

这会让你从“乱学”变成“自我压缩”。
