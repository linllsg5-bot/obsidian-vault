## 2. 自定义监听地址/端口

- **Windows PowerShell** 下，你可以这样设置环境变量并启动（以监听所有接口的 5050 端口为例）：
  ```powershell
  $env:OLLAMA_HOST = "0.0.0.0:5050"
  ollama serve
  ```
- **Linux/macOS**，在同一个终端里：
  ```bash
  OLLAMA_HOST=0.0.0.0:5050 ollama serve
  ```

这样，服务就会监听 **5050** 端口，你可以访问  
```
http://localhost:5050/
```  
来确认服务已启动 citeturn2search4。

---

## 3. 将 WebUI 指向正确的后端

在你用 Docker 启动 Open WebUI 时，需要把 `OLLAMA_BASE_URL` 环境变量指向你上面启动的 API 地址。比如，如果你按上例在本机 5050 端口启动 Ollama 服务：

```powershell
docker rm -f open-webui
docker run -d -p 3000:3000 `
  -v open-webui:/app/backend/data `
  --name open-webui `
  --restart unless-stopped `
  -e OLLAMA_BASE_URL=http://host.docker.internal:5050 `
  ghcr.io/open-webui/open-webui:main
```

然后在浏览器打开  
```
http://localhost:3000
```  
就能正确通过你的本地 Ollama 后端与 Llama 3 交互了。

- 日志文件通常位于以下路径之一：

### 3. 检查虚拟化设置


### 4. 检查 Windows Subsystem for Linux (WSL) 设置

1. **镜像占用空间**：容器的镜像本身会占用一些存储空间，但 Docker 会缓存镜像，并且每个镜像只会在第一次下载时占用空间。如果你已经拉取过该镜像，重新运行命令时不会再次占用额外的空间。

2. **容器和数据卷**：容器使用的是一个特定的文件系统层，数据卷（`-v open-webui:/app/backend/data`）会把容器的持久数据存储在宿主机上的一个特定目录中。这个数据卷会在容器卸载或删除时保留，确保你的数据不会丢失。如果你创建了多个容器，它们也会共享相同的数据卷，除非你手动删除。

### 重复和冗余问题

- **不会重复创建容器**：如果你之前已经运行过相同名称 (`--name open-webui`) 的容器，Docker 会提示容器已经存在，并不会重复创建一个新的容器。
  
- **数据卷占用空间**：数据卷是独立于容器的，可以被多个容器共享。只要你没有删除数据卷，它会一直保留，可能会占用一定的磁盘空间，尤其是数据量较大时。

如果你已经有多个相同或无用的容器，可以清理它们以释放空间：

1. **列出所有容器**：

4. **清理未使用的卷**：
   ```bash
   docker volume prune
   ```

理解你的困惑，实际上 **虚拟机平台** 和 **WSL 2** 是 Docker 在 Windows 上运行时必须依赖的组件。在 Windows 上运行 Docker 时，Docker 是基于 **WSL 2** 的虚拟化技术来运行容器的。因为 Docker 本身并不是原生支持 Windows 的容器，而是依赖于 Linux 容器，所以 **WSL 2** 才会成为关键。

### 下面是详细的解释：

#### 1. **什么是 WSL 2？**
WSL 2 是 Windows Subsystem for Linux 的第二个版本，它通过运行一个轻量级的 Linux 内核，让你可以在 Windows 上使用真正的 Linux 系统。这是 Docker 能够在 Windows 上运行 Linux 容器的基础。

#### 2. **虚拟机平台（Virtual Machine Platform）是什么？**
虚拟机平台是 Windows 用来支持 WSL 2 的技术，它允许虚拟机（VM）在 Windows 上运行。因此，你需要启用这个平台，才能使用 WSL 2。

### 解决问题的步骤：
Docker 使用 WSL 2 来运行容器。如果你现在还没有启用虚拟机平台和 WSL 2，Docker 就无法正常工作。以下是如何一步步解决这个问题：

### 解决步骤：

1. **启用虚拟机平台：**
   打开 PowerShell（以管理员身份运行），并执行以下命令：

   ```bash
   dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
   ```

   这条命令会启用虚拟机平台。

2. **启用 Windows Hypervisor：**
   还需要启用 Windows Hypervisor Platform，这样 WSL 2 才能正常运行。执行以下命令：

   ```bash
   dism.exe /online /enable-feature /featurename:Microsoft-Hyper-V-All /all /norestart
   ```

3. **启用 WSL：**
   在 PowerShell 中执行以下命令来启用 WSL：

   ```bash
   wsl --install
   ```

   这条命令会自动安装 WSL 2 和必要的组件。

4. **重启计算机：**
   完成上述步骤后，重启计算机，以确保设置生效。

5. **检查 WSL 2 状态：**
   重新打开 PowerShell，输入以下命令来确认 WSL 2 是否已经启用：

   ```bash
   wsl --status
   ```

   如果 WSL 2 启动成功，它应该会显示类似以下的结果：

   ```
   默认分发: Ubuntu-20.04
   默认版本: 2
   ```

6. **安装 Docker Desktop：**
   如果以上步骤都完成了，你可以重新启动 Docker Desktop，Docker 就会依赖于 WSL 2 来运行容器。

---

### 总结：
- **WSL 2** 是 Docker 在 Windows 上运行 Linux 容器的基础。
- **虚拟机平台** 是使 WSL 2 能够运行的技术。
- 需要启用这两个功能才能让 Docker 正常工作。

   - 如果你在安装或者更新某个程序时没有清理干净（比如残留文件或注册表项），可能会出现 `libcef.dll` 相关的错误，但它并不影响程序的核心功能。

### 如果你不觉得它影响到使用，可以选择忽略这个错误。如果以后遇到类似问题或者某个程序确实因为这个错误无法正常工作，再进行处理也不迟。

### 继续观察：
- 你可以继续观察一下，看看是否有某个特定的操作触发了这个错误。比如，有没有某个程序启动时，总是弹出 `libcef.dll` 的错误信息。
  
- 另外，检查一下你系统中的 **程序和功能**（控制面板中的“卸载程序”），看看是否有任何你不常用或未曾安装的程序可能在后台运行，也许它们与这个错误相关。

如果一切看起来都正常，且错误信息没有实质性影响，那就暂时不必过于担心。如果未来有更多的线索或者更严重的影响，再深入解决。

## 1. 拉取 Open WebUI 镜像

```powershell
docker pull ghcr.io/open-webui/open-webui:main
```

---

## 2. 启动唯一的容器

然后在同一个终端里执行一条完整的命令——不要拆行，也不要多开窗口——一次性创建并启动容器：

```powershell
docker run -d -p 3000:3000 `
  -v open-webui:/app/backend/data `
  --name open-webui `
  --restart unless-stopped `
  ghcr.io/open-webui/open-webui:main
```

- **-d**：后台运行  
- **-p 3000:3000**：映射端口  
- **-v open-webui:/app/backend/data**：数据卷持久化  
- **--name open-webui**：容器命名  
- **--restart unless-stopped**：自动重启

---

## 3. 验证并访问

1. 等待命令执行完毕。  
2. 执行 `docker ps`，此时应该能看到一个名为 `open-webui`、状态为 `Up` 的容器。  
3. 打开浏览器访问：  
   ```
   http://localhost:3000
   ```
