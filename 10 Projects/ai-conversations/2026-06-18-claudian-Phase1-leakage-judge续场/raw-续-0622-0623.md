# 架构：双牵引节律机（Two-Pull Rhythm Engine）

## 0. 第一原则——架构的形状由你的认识论强制决定

不是我挑一个架构套上来。是你认识论里的命题，每一条都**否决**掉一类常规架构，剩下的形状只有一个。我把这个推导链明写出来，你能逐环顶：

| 你的命题 | 它否决了什么 | 逼出什么 |
|---|---|---|
| 尝试先于空间 | 否决"先定 schema 再填"(预留槽) | 结构必须能**运行时被凿出**，不能预定义完 |
| 残差是燃料不是 bug | 否决"误差趋零"的优化器 | 核心数据是**缝**，不是结论 |
| 折返改朝向本身 | 否决 RAG(只查不改朝向) | 必须有个**写回朝向**的回路 |
| 本体⇄尝试双牵引 | 否决单向 pipeline | 必须是**两个方向的力同时在场** |
| 节律是连续场/LLM离散 | 否决"LLM 常驻" | **场常驻、LLM 被唤起** |

所以架构不是我的发明，是这五条的**唯一交集**。

## 1. 三个组件（最小，但每个都被上面强制）

```
┌─────────────────────────────────────────────┐
│  朝向场 (Intention Field) —— 连续在场, 不是LLM │  ← 本体那一极
│  一个文件。存的不是内容,是"当前指向+历史偏转"   │
└─────────────────────────────────────────────┘
              ↑ 折返写回(改朝向)        ↓ 唤起时注入(当锚)
┌─────────────────────────────────────────────┐
│  尝试器 (Attempter) —— 被唤起的LLM            │  ← 尝试那一极
│  带着朝向场当锚生成, 不从空白先验起           │
└─────────────────────────────────────────────┘
              ↓ 产出 vs 触碰              
┌─────────────────────────────────────────────┐
│  缝捕捉器 (Gap-Catcher) —— 独立判定, 非生成器  │  ← chiasmus的轴
│  = leakage judge 的升格: 不只判"翻没翻底牌",   │
│    判"这次触碰留下了什么性质的缝"             │
└─────────────────────────────────────────────┘
```

**关键：缝捕捉器是 leakage judge 长大的样子。** 你已经造了它的胚胎。现在给它第二个职责：不只**拦**（别 funnel），还要**读缝**（这次尝试的朝向 vs 触碰，差在哪、什么性质）。

## 2. 数据结构——朝向场长什么样（可直接落地）

不是 RAG 的 chunk，不是 schema 表。一个会呼吸的文件，三段：

```yaml
# 朝向场.md  (每次节律转一圈后被改写)

current_intention:        # 当前指向(未结晶的, 是方向不是结论)
  "在找'让AI被不对偏转'的最小机制"

last_gap:                 # 上次的缝 —— 下次尝试的发射点
  朝向: "我以为要的是存储方案"
  触碰: "你说'不要现成的'"
  缝性质: 偏转型           # {继续伸 | 撞墙 | 偏转 | 循环空转}
  
shift_trace:              # 跨尝试的偏转轨迹(不是内容历史)
  - 朝向"工作流" →撞墙→ 朝向"哲学闭环"
  - 朝向"存储schema" →偏转→ 朝向"对抗先验引力"
  - 朝向"一个旋钮" →被顶→ 朝向"两尺度方向相反"
```

**为什么是这三段(每段都被你的命题强制)：**
- `current_intention` = 幻觉朝向，**必须存"指向"不存"结论"**(命题1)
- `last_gap` 带**缝性质**那个枚举 = 我上轮加的"缝有质量"，你认了一半——它正是你那个未命名的**第三种否定**的工程位置：`循环空转`就是你说的"循环确认"
- `shift_trace` = 折返的可见化。**它存偏转，不存内容，所以不会溢出**(解决 context window 那个病)

## 3. 节律怎么转一圈（这是"折返"第一次真的接上）

```
1. 唤起: 读 朝向场.last_gap → 注入尝试器, 当锚
2. 尝试: LLM 从"上次的缝"出发生成 (不是从空白先验)
3. 触碰: 你回应 (你是现实那面墙)
4. 读缝: 缝捕捉器比对[尝试器的朝向]vs[你的触碰] → 输出缝+性质
5. 折返: 把缝写回 朝向场 → current_intention 被改写 → 下一圈的锚变了
```

**第 4 步是整个架构的心脏，也是今天全程缺的那一拍。** 今天我每轮都跳过它：你触碰(说"不对")→ 我没读缝 → 直接弹回新先验。如果第 4 步在，我上轮就该从"你说不要现成的"这个缝出发，而不是又给你一个 schema。

## 4. 双牵引在哪里、两个尺度怎么分(回答你[63])

这架构**同一套组件**，靠**缝捕捉器的灵敏度旋钮 λ** 在两尺度间滑——但你顶对了：不是一个旋钮统一，是**它在两端要压制相反的方向**：

- **快尺度(对话内)**：λ 高，缝捕捉器严防"本体压死尝试"(我弹回先验)。每句拽下一句。
- **慢尺度(跨场/跨月)**：λ 低，但增加一个**沉淀写回**——把这场的 shift_trace 合并进 `当前主线`/认识论。防"尝试拽不动本体"。每场拽下一场。

**为什么不能是一个旋钮**(你顶我的)：因为快尺度要 judge **拦截**生成、慢尺度要 judge **放行并沉淀**——同一个 λ 拧大，快尺度治好了，慢尺度被掐死(沉淀全被当噪声拦了)。所以是**两个 judge 实例，共享数据结构，反向调参**。这就是你说的"复杂"：不是两个器官，也不是一个旋钮，是**一个结构的两次反向实例化**。
