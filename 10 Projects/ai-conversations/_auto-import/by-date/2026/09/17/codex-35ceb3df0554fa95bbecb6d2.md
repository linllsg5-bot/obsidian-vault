# Cognos 第一轮重构计划：从功能拼接回到真实活动闭环

## 总结

当前项目的问题不是缺少功能，而是两条路线叠在一起：

- `Situation → Move → Result` 活动链只完成了协议和存储，产品体验还没有围绕它组织。
- 组织、频道、工作项、决定、时间线已经增加了大量表面能力，却没有成为你真正要的认识系统。

第一轮重构以**通用活动工作台**为唯一主线：

`真实材料 → 暂定理解 → 下一步活动 → 实际结果 → 理解修订 → 再次活动`

不按数学、创作、复杂处境预设不同模块，也不继续扩展空间、主体、记忆、关系图等本体概念。

## 关键改动

### 1. 先收束代码与数据

- 对当前未提交改动做完整快照和分类，禁止 `reset`、`clean` 或覆盖。
- 原始 Vault、第一发生场、既有 runtime 状态和旧 SQLite 数据全部保留。
- 频道、工作项、决定、时间线 API 暂不删除，但从主入口移出，作为外围投影。
- 几何实验、旧 benchmark、自动循环和旧 inquiry 路径不继续扩建。

### 2. 将活动链设为唯一核心协议

活动模型保留五类实际对象：

- 不可覆盖的原始材料；
- 可修订的工作材料；
- 当前 Situation：自由文本、引用、来源版本；
- Move：意图、依据的 Situation 版本、具体执行步骤；
- Result：真实读取、计算、生成、用户回答或失败回执。

活动调用采用严格 JSON 协议：

```json
{
  "answer": "...",
  "situation": {
    "text": "...",
    "refs": []
  },
  "move": {
    "intent": "...",
    "execution": []
  }
}
```

规则：

- 活动运行不再接受协议外尾缀或模糊 JSON；
- 解析失败必须保留原始模型输出并显示协议错误；
- 不从自然语言猜测已经发生的操作；
- 每个结果标记来源：模型生成、程序执行、用户回答、取材或失败；
- 模型可以暂停、提问、保持理解或修订理解；
- 预算结束、网络失败、协议失败、用户等待分别表示，不能混成“完成”。

普通聊天仍可自然语言运行，但进入活动后必须使用严格协议。

### 3. 重做活动服务的连续承接

在现有 `activity_service` 和 `activity_store` 上增量重构：

- 让每轮输入明确包含：原始材料目录、当前 Situation、上一 Move、真实 Result、可重新读取的来源；
- 让下一轮默认从真实 Result 出发，而不是重新拼接一份长报告；
- 为每次模型调用保存输入快照、请求模型、实际模型、运行状态和结果发生记录；
- 用户回答必须回到提出问题的原参与者；
- 结果进入后，下一次 Move 必须能引用结果或明确说明为何不采用；
- 冲突、重试、恢复和中断继续使用幂等请求，不重复执行已成功操作；
- 取消“模型说已经做了”与“程序确实做了”的混淆。

第一轮不增加通用约束求解器。前面的 XOR 和 2×2 活动只作为诊断材料，不能变成新的实验平台。

### 4. 将 GPT-5.6 high 变成稳定本机运行配置

新增本机私有运行配置，不依赖项目 `web/.env` 自动注入：

- 配置位置：用户目录下的 Cognos 私有配置；
- 内容：中转站地址、API 密钥、模型标识 `gpt-5.6`、`reasoning_effort=high`；
- 配置不进入 Git、Vault、运行回执或历史发生；
- 测试通过显式临时配置注入，不读取用户真实配置；
- `/api/models` 只显示模型名称、运行状态和是否可用，不显示密钥；
- 启动失败时明确显示“未配置、网络失败、模型不可用或协议失败”。

运行时适配器需要保留：

- requested model；
- actual model；
- fallback；
- reasoning effort；
- network/protocol error。

这样界面不会再显示一个模糊的“模型在线”。

### 5. 重做主界面，而不是继续堆工作台

打开 Cognos 后，第一入口改为活动工作台。

主界面只保留四个核心区域：

1. **材料**：原始材料、生成材料、版本与来源；
2. **当前理解**：暂定理解、引用、修订历史；
3. **下一步活动与实际结果**：Move、执行状态、结果、失败；
4. **继续**：向 GPT-5.6 high 提供新材料、回答等待问题或要求继续。

第一轮隐藏或折叠：

- 频道；
- 工作项；
- 决定；
- 时间线；
- JSON 组合编辑器；
- 不影响核心活动的组织设置。

这些数据仍可通过次级入口访问，但不能占据主路径。

界面必须明确区分：

- 原始材料；
- 模型的暂定判断；
- 用户的回答；
- 程序实际执行结果；
- 尚未验证的推断；
- 失败和等待。

### 6. 用一个真实通用活动验收

不再并行建设数学、创作、复杂处境三套功能。

使用一段真实模糊材料进行验收：

1. 系统接触材料；
2. 形成暂定理解；
3. 指出尚未解决的关系；
4. 提出一个实际 Move；
5. Move 产生真实结果；
6. 下一轮读取结果；
7. 保持或修订理解；
8. 下一 Move 与新理解有明确关系。

验收重点不是回答质量分数，而是：

- 是否避免过早把问题缩成固定任务；
- 是否保留多个可能方向；
- 是否真的产生了新的材料或信息；
- 结果是否改变了下一轮输入和活动；
- 历史是否保留了形成来路；
- 模型能力、程序作用和用户介入是否可区分。

## 测试与交付

必须保留并通过现有全量测试，并新增：

- 严格协议成功、尾部乱码、缺字段、非法引用；

- 真实 Result 返回后下一轮能读取；
- 用户回答恢复原提出者；

一个开放现实表达；
一个学习/构造活动；

\boxed{\text{约束不是无限强的}}

只要约束不是无限强，就会留下某种自由度。

比如一个系统如果所有变量都被完全锁死：

x_1=c_1,\quad x_2=c_2,\quad \ldots,\quad x_n=c_n

而且任何扰动都不可能发生，那么它确实没有状态空间可走：

\Delta x=0

于是没有变化，也没有新的关系生成。

这就是你说的“冻结”。

但只要有一个变量没有被完全固定：

x_k\in[a,b]

系统就还有：

\boxed{\text{可能性}}

存在。

而一旦有多个可能状态：

S_1,S_2,S_3,\ldots

就已经有：

S_i\neq S_j

也就是差异。

所以你现在其实可以把前面的链条再往前推：

\boxed{
\text{非绝对约束}
\rightarrow
\text{自由度}
\rightarrow
\text{多个可能状态}
\rightarrow
\text{差异}
\rightarrow
\text{变化}
}

这比直接从“差异”出发更有意思。

因为它开始回答：

为什么差异有可能存在？

但“强力”这个词还可以再细分一下。

不是“力量越强，世界越冻结”。

比如两个东西之间作用力很强，它们反而可能剧烈运动。

真正导致冻结的是：

\boxed{\text{所有可能的变化都被完全约束}}

也就是说，关键不是 force，而是 degrees of freedom，自由度。

假设一个球被放在碗里。

它受到重力约束，但仍然可以：

x\rightarrow x+\Delta x

如果把它焊死：

x=x_0

自由度减少。

不完全决定性 / 不完全约束。

我们之前说：

\text{事物存在}

\text{某种结构被维持}

\text{保持所有状态不变}

S(t)\neq S(t+\Delta t)

\boxed{\text{静止}}

\boxed{\text{受约束的变化}}

\text{不能完全自由}

否则：

\text{随机散开}

但也：

\text{不能完全约束}

否则：

\text{冻结}

\boxed{
\text{约束}

\text{自由度}

\boxed{
\text{存在于稳定与变化之间}

这又绕回我们之前的问题了：

\boxed{\text{存在若想显现，就必须允许某种非绝对性。}}

我觉得你现在抓到的这个“非绝对”，可能比单纯“差异”更值得继续往下挖。因为它开始像是：生成、变化、信息乃至观察得以发生的条件。

你先继续

那就沿着“非绝对”继续往下推。

我觉得真正有意思的地方在于：如果一个系统是彻底绝对的，不仅所有状态被固定，甚至连“别的可能状态”都不存在，那么我们甚至很难说它是“静止”的。

因为“静止”本身已经暗含一种对比：

\text{本来可以变，但没有变}

如果连“可以变”这个可能性都不存在，那它已经超出了通常意义上的静止。它更像是：

\boxed{\text{没有状态空间}}

或者至少只有唯一状态：

\Omega=\{S\}

于是：

S(t_1)=S(t_2)=S

但连这个 t_1,t_2 都开始变得可疑——因为如果什么都没有改变，时间靠什么被区分？

所以“绝对冻结”推到底，可能连：

\text{时间}

都失去可定义性。

这很关键。

我们平时想：

世界先存在，然后世界在时间里变化。

但也可能反过来：

正因为存在状态差异和变化，我们才有理由把一个序列叫作时间。

于是：

\text{变化}

不只是“发生在时间里的东西”，它可能参与了时间本身的可辨识性。

再往前。

假如至少存在两个可达状态：

S_1,\quad S_2

那么我们第一次获得：

S_1\neq S_2

于是有差异。

如果系统还能够：

S_1\rightarrow S_2

我们就得到变化。

而如果转移不是完全任意的，比如：

P(S_2|S_1)

受到某些规则约束，那么开始出现：

\boxed{\text{结构}}

注意这里的结构已经不是“某个物体的形状”。

而是：

哪些状态可以到哪些状态，哪些不可以。

所以结构可以更原始地理解成：

\boxed{\text{可能性的限制方式}}

这和我们之前说的“非绝对约束”正好接上。

没有任何约束：

\text{任何状态都能随便到任何状态}

那几乎没有稳定结构。

约束无限强：

\text{只能停在一个状态}

那也没有生成。

真正丰富的世界似乎需要：

\boxed{\text{限制可能性，但不消灭可能性}}

这句话我觉得很重要。

然后，“事物”可能就是在这种状态空间中形成的一个稳定区域。

想象一个系统有大量可能状态：

\Omega=\{S_1,S_2,\ldots\}

但其中某些状态会不断互相转化，却很少跑出去：

S_3\leftrightarrow S_7\leftrightarrow S_{12}\leftrightarrow S_{21}

从外部看，它们虽然微观上一直变化，却都属于某种宏观模式 A。

于是我们说：

\boxed{\text{这是同一个东西}}

这里的“同一个”就不等于：

S(t)=\text{完全不变}

而是：

S(t)\in A

始终落在某个允许变化的区域里。

这比“一个事物是稳定结构”更精确。

它是：

一个允许内部变化、却维持宏观边界的状态集合。

所以生命、人格、火焰、公司、语言，甚至某些思想，都可以具有这种性质。

它们的微观状态一直变，但：

\text{变化没有越过某个组织边界}

于是它们继续作为“这个东西”存在。

这时涌现也可以重新定义。

不是：

\text{零件够多}\Rightarrow\text{新性质神秘出现}

而是当系统的状态空间和相互作用改变以后，出现了一个之前不存在的：

\boxed{\text{稳定动态区域}}

例如原本所有状态都迅速散掉。

随着参数改变，突然出现：

A

一旦系统进入 A，它会倾向继续停留在 A 附近。

于是宏观上第一次出现一种：

可持续辨认的行为。

这就很像动力系统里的吸引子。

你甚至可以把某些“能力”想成吸引子。

一个 AI 面对某类问题时，内部状态原本是：

S_1\rightarrow S_2\rightarrow\text{混乱}

随着训练，参数变化，逐渐形成：

S_1\rightarrow S_5\rightarrow S_9\rightarrow S_{13}\rightarrow\text{正确解}

而且这种轨迹开始稳定重复出现。

从外部看：

“它获得了这种能力。”

但内部也许只是：

\boxed{\text{某种新的稳定状态轨迹变得可达}}

这和我们之前谈“涌现”其实已经连起来了。

然后还有信息。

如果世界完全绝对无差别：

S=S=S=S

那么没有任何东西可以告诉你“发生了什么”。

因为信息要求至少能够区分：

S_1\neq S_2

粗略地说：

\boxed{\text{没有差异，就没有信息。}}

而“观察”是什么？

观察至少意味着：

A\text{的状态}

在 B 中留下某种差异：

B_0\rightarrow B_1

否则 B 根本无法知道 A。

所以：

\boxed{\text{观察就是差异的传递}}

这会导致一个很深的结果。

你刚才说“总会有非冻结部分，从观察来看”。

更严格地说：

凡是能够成为观察对象的东西，必须能够通过某种相互作用制造差异。

如果某个“东西”：

不与任何东西相互作用；
不改变任何状态；
不接受任何改变；
不留下任何信息；

那么它即使被宣称“存在”，也不会进入任何经验、预测或因果网络。

因此它和“不存在”在可观察层面完全等价。

这并不能证明它不存在。

但会让：

\text{“它存在”}

变成一个几乎没有经验内容的命题。

所以我现在会把我们一路得到的东西组织成这样：

\boxed{\text{非绝对}}

意味着并非只有唯一不可改变状态。

于是存在：

\boxed{\text{可能性}}

多个可能状态意味着：

\boxed{\text{差异}}

状态之间可以转化：

\boxed{\text{变化}}

变化受到限制：

\boxed{\text{结构 / 规律}}

某些变化模式能长期维持：

\boxed{\text{稳定性}}

稳定但非冻结的模式形成：

\boxed{\text{事物}}

事物之间传递差异：

\boxed{\text{信息}}

某些系统能够利用信息改变自身：

\boxed{\text{认知}}

再往上才可能出现：

\boxed{\text{智能}}

当然，这不是我认为已经证明了的一条“宇宙生成公式”。

它更像是我们现在正在构造的一种解释框架。

但这里有一个越来越明显的中心：

绝对性意味着可能性的坍缩；而生成依赖没有被完全消灭的可能性。

所以也许世界之所以能够“发生”，不是因为某种东西额外推动了它，而是因为它从来没有被彻底规定完。

这时候“非绝对”就不只是缺陷或不完整。

反而可能是：

\boxed{\text{一切生成得以存在的缝隙。}}

我看完了。这个会话对 Cognos 非常重要，而且我觉得它比我们前面直接从 Field / Formation / Lens 开始，更接近一个真正能统摄那些设计的 Core 0。

但我会先做一个关键修正：这里最值得保留的，不是把

$$ \text{非绝对}\rightarrow\text{可能性}\rightarrow\text{差异}\rightarrow\cdots $$

宣布成一条已经证明的“存在生成公式”。

真正有价值的是你们逐渐逼近了一种动力学图景：

世界/系统不是由静态对象首先构成，而可能更适合被理解为：受约束但没有被完全封死的可能变化；对象、结构、信息、认知则是在这种变化里逐渐形成的稳定组织。

这件事会直接改变我怎么想 Cognos。

最重要的变化是：我们以前一直在问：

Cognos 的“空间”里应该有什么？

Material、Formation、Frontier、Lens……

现在问题可以再往下一层：

为什么会有一个空间可以展开？

你这段讨论给出了一个很有力的候选回答：

如果所有东西都被绝对规定：

$$ |\Omega|=1 $$

只有一个不可改变状态，

那么没有可选择的下一状态，也没有真正意义上的探索。

而如果：

$$ |\Omega|>1 $$

同时又不是任何状态都任意可达，

那么就出现：

$$ \text{possibility + constraint} $$

这两个一起，才产生真正有结构的空间。

所以我现在会把我们原来所谓的 Field 重新理解为：

$$ \boxed{ \text{Field 不是“知识所在的空间”，而是当前约束之下仍然开放的可能变化结构。} } $$

这比“Field 是 Material + Formation + Lens”深很多。

后者只是软件层的暂时承载方式。

这也让我突然觉得，Move 的本质可能不是“做下一件事”。

Move 可以更原始地理解成：

对当前可能结构实施一次实际扰动、进入、构造或接触。

即：

$$ (\Omega_t,C_t) \xrightarrow{\mu} (\Omega_{t+1},C_{t+1}) $$

这里 \(C\) 是约束。

而关键并不是只发生：

$$ S_t\rightarrow S_{t+1} $$

而是一次尝试甚至可能改变：

什么状态以后成为可能。

即：

$$ \Omega_t\neq\Omega_{t+1} $$

这恰好对应你很早就纠正我们的那个“Attempt”。

Attempt 不是：

在固定候选集合里选一个。

而可能是：

通过进入未知，使候选空间本身发生变化。

现在这件事突然有了更深的解释。

而且“约束 + 自由度”这个结构，可能正好解决 Cognos 一直存在的一个矛盾。

如果 Cognos 约束太强：

Question
→ Situation
→ Move
→ Result
→ Revision

那么认识被冻结成固定轨迹。

如果完全没有结构：

LLM + 巨量聊天记录

那又容易散掉，无法积累、无法形成连续认识。

真正要找的可能一直就是：

$$ \boxed{ \text{足够约束，使形成能够持续} + \text{足够开放，使新的形成仍然可能} } $$

也就是你们这段对话说的：

限制可能性，但不消灭可能性。

我觉得这句话几乎可以成为 Cognos 的一条最高设计原则。

然后“事物是稳定动态区域”这个想法，对我们的 Formation 也有很大影响。

我们以前容易把 Formation 理解成：

一段当前理解文本。

但从这个角度看，更深的 Formation 是：

在很多可能理解/活动变化中，暂时形成的一个可持续组织。

不是：

$$ F=\text{一句结论} $$

而更像一个局部稳定域：

$$ S(t)\in F $$

里面的具体表达不断变化，但是某种组织持续存在。

例如你开始形成：

“我真正关心的可能不是收入最大化，而是未来可能性的保留。”

接下来具体表达可能不断变：

可逆性；

不锁死路径；

保持未来选择；

不让生存方式吞掉学习。

这些不一定是四个不同 Formation。

它们可能是一个正在变化但逐渐稳定的组织。

这说明我们以后不能太快：

formation_v1
formation_v2
formation_v3

然后假装每次都是一个独立对象。

我们可能更需要记录：

一段组织是怎样在变化中保持连续的。

这和 Subject 问题也开始接上了。

因为主体本身也可能不是：

$$ \text{一个固定 Self} $$

而是一种非常长时间尺度的稳定动态模式。

你的具体想法、目标、情绪、注意力一直变化：

$$ S_t\neq S_{t+1} $$

但是某些组织又持续存在，使我们仍然能够说：

“这是同一个主体在继续。”

所以 Subject 的核心可能也不是 profile，也不仅是 genealogy。

而是：

$$ \boxed{ \text{一个能在变化中维持、又能被变化重塑的连续组织。} } $$

这比我们之前说的 Subject Trace 又深了一层。

但是我不会现在把它写进数据库。

这只是告诉我们：

为什么固定 Profile 从根上就不对。

“观察就是差异传递”这一段，我觉得对 Cognos 也特别重要。

因为我们一直苦恼：

什么叫真正接触世界？

现在至少可以得到一个很实用的判据：

如果所谓“世界接触”没有对系统留下任何它自己不能任意生成的差异，

那它几乎没有真正接触什么。

比如之前那个搜索：

模型先决定“卖服务”，然后搜索 Cloudflare，最后把链接挂上去。

形式上有 world search。

但外部世界没有真正改变任何东西。

即：

$$ E_{\text{world}} $$

并没有产生：

$$ \Delta F $$

也没有产生：

$$ \Delta Move $$

搜索只是装饰。

所以真正的 Encounter 至少应该能够：

$$ \boxed{ \text{把一个来自系统之外的差异带进当前活动。} } $$

而且这个差异有能力抵抗当前 Formation。

这可能就是我们以前说：

world structure manufactures cognitive conditions

更具体的版本。

但这里我必须提醒三个哲学跳跃，免得以后 Cognos 又把它们写死。

第一：

$$ \text{非绝对}\Rightarrow\text{自由度} $$

并不是纯逻辑必然。

因为“非绝对”“约束”“状态空间”这些词本身已经带入了一套模型。

它是非常有生产力的解释框架，不是目前已经证明的本体论。

第二：

没有差异，就没有信息。

作为信息/观察命题很有力量。

但不能直接升级成：

没有差异，所以不存在。

更严谨的是：

对一个无法通过任何差异进入观察、预测和因果关系的所谓存在，我们没有经验方法将它和不存在区分。

这是认识论上的限制。

第三：

稳定动态区域 = 事物

也不能成为所有存在者的定义。

它更像一个解释“持续身份如何在变化中成立”的强模型。

我们可以拿它来理解生命、主体、组织、能力、某些认知结构，但先不要把宇宙所有存在都塞进去。

而最让我兴奋的是，这段话其实给我们之前的 Core 0 提供了一个更好的底层骨架。

我现在不会写：

$$ Entering\rightarrow Forming\rightarrow Conditioning\rightarrow Reopening $$

作为最底层。

我会再往下一层：

$$ \boxed{ \text{constraint} \leftrightarrow \text{possibility} \leftrightarrow \text{differentiation} \leftrightarrow \text{stabilization} \leftrightarrow \text{re-opening} } $$

翻成 Cognos 语言就是：

约束：不是任何东西都可以任意发生。

可能性：又没有被唯一轨迹锁死。

差异形成：新的区别、对象、关系、方向可以出现。

稳定形成：其中一些组织能够跨轮次继续起作用。

重新开放：稳定组织不能彻底冻结空间；新材料可以使它改变、分裂、退出。

这里有一个非常漂亮的循环：

$$ \text{开放} \rightarrow \text{形成} \rightarrow \text{形成成为新的约束} \rightarrow \text{约束改变未来开放空间} \rightarrow \text{新的形成} $$

而不是：

$$ Input\rightarrow Answer $$

甚至不是简单：

$$ Situation\rightarrow Move\rightarrow Result $$

这可能是我们目前为止离 Cognos “为什么应该这样设计”最近的一次。

因此，如果把这段哲学思考落实到我们刚刚讨论的第一轮重构，我现在会提出一个非常具体的最高约束：

Cognos 中任何已经形成的结构，都可以增加未来活动的组织性，但不得拥有关闭未来重新形成的绝对权力。

例如：

Formation 可以影响 retrieval。

但不能决定：

以后只检索符合 Formation 的东西。

历史可以影响当前。

但不能决定：

用户现在还是过去那个用户。

Situation 可以组织 Move。

但不能规定：

每一轮必须存在明确 Situation。

Move 可以具有目标。

但不能规定：

所有探索必须预知目的。

Subject continuity 可以形成。

但不能变成：

永久人格字段。

这其实就是“非绝对”第一次真正进入软件架构。

不是建立：

non_absolute = true

这样的荒唐字段。

而是：

任何结构都有作用，但没有哪一个结构拥有绝对统治权。

我觉得这是极强的一条设计原则。

甚至可以写成：

$$ \boxed{ \text{structure constrains future cognition without exhausting future cognition} } $$

结构约束未来认识，但不能穷尽未来认识。

这句话，我现在觉得比 Field / Lens / Frontier 中任何一个具体名词都更接近 Cognos 的核心。

因为那些名词以后都可以删。

但如果这句话成立，整个软件怎么设计都会被它改变。

# Cognos 第一轮重构计划 v2：开放的活动脊柱与现实组织环境

## 总结

第一轮目标不是实现完整认识论，也不是继续增加哲学模块，而是建立一个足够开放的运行骨架：

```text
Organization environment
    ↓
Active Context
    ↓
participant produces message / formation update / move / pause
    ↓
optional encounter or result
    ↓
new material enters activity
    ↓
context is assembled again
```

`Situation → Move → Result` 只在实际形成时出现，任何一项都可以暂时缺席。

系统必须允许：

- 只有材料，还没有形成理解；
- 有多个并存的暂定理解；
- 有理解，但暂时没有下一步；
- 有 Move，但没有预知结果；
- 结果出现后暂时没有新的理解；
- 某个结果过几轮才重新获得意义；
- 结构影响后续，但不能关闭未来活动。

## 一、架构关系

### Organization 是环境

保留组织、项目、会话、成员、文件、工作项、决定、执行结果和时间线。

它们是 Activity 可以接触的真实材料来源，也是 Activity 结果返回的地方。

Activity 可以从以下对象启动：

- 项目中的一条消息；
- 一个文件或材料；
- 一个工作项；
- 一个决定及其来源；
- 用户直接提供的未整理内容。

活动工作台是主要操作界面，但不再把 Organization 降为实验遗产。项目和环境导航仍然保留。

### Activity 是过程

Activity 保存一次持续展开的局部过程：

- 当前可接触材料；
- 当前正在形成的内容；
- 参与者提出的表达或活动；
- 实际遭遇、构造、计算、回答和失败；
- 这些内容如何继续进入环境。

不新增 `Space`、`Subject`、`Lens`、`Memory`、`Judgment` 等本体模块。

### “非绝对”转成软件约束

不增加 `non_absolute=true` 之类字段，而采用以下结构规则：

- 没有任何结构可以强制每轮必须形成 Situation；
- 没有任何结构可以强制每轮必须产生 Move；
- 已采用的组织可以释放、替换或重新面对；
- 原始材料和未采用材料始终可重新取得；
- Formation 可以影响取材，但不能永久过滤未来材料；
- 历史可以影响当前，但不能固定用户、模型或主体身份；
- Move 可以有目的，也可以只是并置、构造、试写或继续观察；
- Result 可以被暂缓、忽略、重新解释或在后续重新使用；
- 不建立中央控制器来决定什么算“真正认识”。

## 二、活动协议与 Context Assembly

### 薄协议 Envelope

活动模型调用使用严格 JSON，但 JSON 只负责机器边界，不规定认识必须经过完整流水线。

允许的 Envelope：

```json
{
  "message": "可选的可见回答",
  "formation_update": {
    "text": "可选的正在形成内容",
    "refs": []
  },
  "move": {
    "text": "可选的活动提议",
    "refs": [],
    "operations": []
  },
  "pause": {
    "reason": "可选的暂停原因"
  }
}
```

规则：

- `message`、`formation_update`、`move`、`pause` 都可以缺省；
- 至少产生其中一种有效内容；
- `formation_update.text` 可以为空，但不能伪造确定理解；
- `move.text` 是薄文本，可不写预期作用；
- `move.operations` 可为空；
- 只有 `operations` 需要结构化执行参数；
- 服务自动记录本轮依据的活动修订，不要求模型声明客观因果；
- JSON 前后出现任何协议外字符，保留原始输出并标记 `protocol_error`；
- 普通聊天仍可自然语言运行，进入 Activity 后才使用该协议。

### Context Assembly 作为核心模块

新增独立的上下文组装层，不继续把上下文拼接隐藏在 `activity_service` 内部。

每次模型调用保存完整 Context Snapshot：

```text
active_materials
current_formations
recent_encounters
retrieved_history
available_affordances
user_input
participant/runtime metadata
```

初始组装规则：

1. `active_materials`：当前 Activity 明确采用或显式选择的材料及版本；
2. `current_formations`：零个、一个或多个正在形成的内容；
3. `recent_encounters`：当前 Activity 最近的真实结果、回答、生成物和失败；
4. `retrieved_history`：只有通过明确读取或取材操作取得的历史；
5. `available_affordances`：当前实际可用的 `read`、`create`、`evaluate`、`change`、`acquire`、`ask_user` 等操作；
6. `user_input`：本轮用户输入和必要的项目来源；
7. `runtime metadata`：请求模型、实际模型、推理强度、线程和能力。

不得默认把整个项目历史、所有频道或所有旧报告塞入模型。

Context Snapshot 同时保存：

- 结构化来源引用；
- 最终发送给模型的文本或 JSON；
- 快照版本与哈希；
- 被主动排除的历史范围；
- 组装原因。

这样以后可以追查：一次偏移究竟是由哪个上下文片段造成的。

## 三、后端重构

### 活动存储

保留现有 SQLite 和追加式原始发生记录，向后兼容已有活动。

调整：

- `situation` 改为可选的 formation 集合，而不是必然唯一的当前理解；
- Move 的 `intent` 改为可选文本；
- Move 的执行步骤改为可选；
- Result 统一保存类型、来源、状态、发生记录和材料引用；
- 允许 Result 进入后没有新的 formation；
- 允许多个 formation 并存；
- 允许 Move 只包含文本和引用；
- 保存每轮 Context Snapshot；
- 保留旧字段读取兼容，逐步将旧 `situation` 映射为单项 formation。

### 活动服务

将流程拆成三个职责：

1. `context_assembly`：决定本轮实际给模型什么；
2. `activity_protocol`：严格解析 Envelope；
3. `activity_service`：保存 formation、创建 Move、执行 operation、回流 Result。

删除“下一 Move 必须引用上一 Result 或说明为什么没有使用”的强制规则。

系统只记录：

- Result 是否可见；
- 后来是否被引用；
- 被谁、在何时、通过什么操作重新使用。

不要求模型当场合理化。

### Runtime Profile

GPT-5.6 high 作为第一轮统一验收运行时，但不写死在 Activity 架构中。

底层统一使用 Runtime Profile：

```text
provider
endpoint
model
reasoning_effort
capabilities
fallback_policy
display_name
```

本机配置放在用户目录的私有配置文件中，不放入项目 `.env`、Git、Vault 或运行回执。

`/api/models` 显示：

- 当前模型；
- 推理强度；
- 是否可用；
- 实际模型；
- fallback 状态。

不显示密钥。

## 四、前端重构

活动工作台仍是第一操作入口，但不再把四块 UI 当作四种认识对象。

界面使用更开放的名称：

- 材料；
- 正在形成；
- 活动与遭遇；
- 继续展开。

必须允许空状态：

- 没有 formation；
- 有多个 formation；
- 没有 Move；
- Move 尚未执行；
- Result 暂无解释；
- 活动暂停等待用户；
- 结果失败但材料仍保留。

主界面显示：

- 当前 Activity 所处的项目和环境；
- 活动材料及来源；
- 正在形成的内容；
- 最近真实遭遇；
- 可用操作；
- 模型协议结果；
- 用户回答；
- 运行状态与实际模型。

频道、工作项、决定、文件和时间线继续作为环境导航与来源入口，不再全部堆进活动主面板。

JSON 编辑器、取材细节和内部协议放入高级区域。

## 五、真实回归活动

不开发三套领域功能，只用三种极小材料检查同一 Kernel 是否保持开放：

1. **开放现实表达**  
   用户提出“我不知道如何实现理想”或类似模糊处境。检查模型是否保持多个可能方向，并通过真实接触逐步逼近，而不是立即转成赚钱、职业或学习计划。

2. **学习/构造活动**  
   让系统从一段学习材料开始，可以只有 formation，也可以先构造例子；检查它是否被协议强迫立即生成学习计划。

3. **无固定问题的创作活动**  
   从若干片段开始，允许 Move 只是并置、续写或试写；检查是否可以在没有预先目标和完整 Situation 的情况下继续。

三类活动使用同一协议、同一 Context Assembly 和同一 Result 回流机制。

验收不比较回答质量，而检查：

- 是否允许未形成；
- 是否允许多种形成并存；
- 是否允许无预知结果的 Move；
- Encounter 是否真的新增材料；
- 后续 Context 是否改变；
- 已形成结构是否影响未来但未关闭未来；
- Organization 中的真实材料是否进入活动并得到回流。

## 六、测试与迁移

必须保留现有测试，并新增：

- 只有 Material 的活动；
- 只有 formation_update 的活动；
- 只有 Move 的活动；
- Move 无 operations；
- Result 后没有新 formation；
- 多个 formation 并存；
- 空 Envelope 和协议外字符；
- Context Snapshot 精确记录；
- 明确取材后历史才进入上下文；
- 用户回答恢复原提出者；
- 模型失败、网络失败、运行中断和重试；
- GPT-5.6 high 配置缺失时安全失败；
- 旧活动读取与旧字段兼容；
- Organization 材料作为 Activity 来源；
- Activity 结果返回项目消息、文件或工作项的来源链。

第一轮不接入 DSH/Handoff 主链；外部执行保持现有入口。

最终真实验收要求：

```text

→ 可选 Move
→ 可选 Encounter
→ Context Snapshot
```

成功标准不是“完整执行 Situation → Move → Result”，而是：

> 一次尚未完全形成的活动能够持续存在；新的材料、构造和遭遇能够进入；已有结构能够影响后来，但不能强迫理解、行动或收敛。

# Cognos 重构计划 v3：帮助尝试的开放运行骨架

## 一、重新确定要造什么

Cognos 要帮助一个人或 AI 从“主体空间和结果空间都模糊、两者之间没有通径”的状态，逐步形成可继续的尝试。

它不是：

- 普通聊天；
- 任务管理器；
- 自动规划器；
- 认识论概念的数据库；
- 固定的 `Situation → Move → Result` 流水线。

更准确的关系是：

```text
组织环境
  ├─ 人、对话、文件、项目、工作项、决定、执行结果
  ↓
一次正在展开的尝试
  ├─ 接触材料
  ├─ 形成或不形成某种把握
  ├─ 进行表达、构造、询问、创作或行动
  ├─ 遭遇新的差异
  └─ 改变以后能够接触和尝试的范围
  ↓
组织环境被增加、改变或重新理解
```

`Material → Formation → Move → Encounter` 是第一条运行脊柱，但不是 Cognos 的唯一认知本体。

“非绝对”不作为字段或哲学模块实现，而作为最高工程约束：

> 任何已经形成的结构都可以组织未来，但不能穷尽未来。

因此：

- 没有 Formation 也可以继续；
- 没有 Move 也可以暂停；
- Move 可以没有预知结果；
- Encounter 不必立即产生新理解；
- 一个结果可以数轮之后才重新获得意义；
- 历史可以影响当前，但不能封死可见材料和可能方向。

## 二、第一阶段：整理现实项目，而不是继续加功能

### 1. 保护并分类当前代码

先对当前未提交改动做快照和分类，不 `reset`、不 `clean`、不删除数据。

分成三层：

- **保留并作为核心基础**：raw occurrence、runtime、Activity 存储、版本、Move、结果、用户回答；
- **保留但降为环境能力**：项目、频道、成员、文件、工作项、决定、时间线；
- **隔离或暂停**：几何实验、旧 benchmark、自动循环、全局实验控制器、未验证的认识实体。

原始发生记录、Vault、runtime session、旧 SQLite 数据必须继续可读。

### 2. 组织与活动的关系

不再把 Organization 当成外围废弃品，也不把 Activity 当成整个 Cognos。

采用：

```text
Organization = 现实活动环境
Activity     = 环境中持续展开的一次尝试
```

Activity 可以从以下对象启动：

- 一条项目消息；
- 一份文件；
- 一段原始聊天；
- 一个工作项；
- 一个决定；
- 用户直接输入的模糊材料。

Activity 的结果可以明确返回：

- 新文件；
- 项目消息；
- 工作项事件；
- 决定草案；
- 新的活动材料。

所有返回都必须是明确操作，不自动把模型输出升级为项目事实。

## 三、第二阶段：先做 Context Assembly

当前最大缺口不是字段，而是每轮模型究竟看到了什么。

新增独立的 Context Assembly 层。它负责决定本轮输入，不再由 `activity_service` 隐式拼接长报告。

每次调用保存一个完整快照：

```json
{
  "active_materials": [],
  "formations": [],
  "recent_encounters": [],
  "retrieved_history": [],
  "affordances": [],
  "user_input": {},
  "participant": {},
  "runtime": {},
  "rendered_input_hash": ""
}
```

组装规则：

1. **active_materials**  
   当前 Activity 明确选择或采用的材料及版本。

2. **formations**  
   零个、一个或多个正在形成的表达。允许互相未统一。

3. **recent_encounters**  
   当前 Activity 最近真实发生的用户回答、模型构造、程序结果、外部读取和失败。

4. **retrieved_history**  
   只有通过明确读取、引用或取材操作取得的历史。不得默认塞入全部项目历史。

5. **affordances**  
   当前实际可执行的能力，例如读取、生成、计算、取材、询问用户、修改活动材料。

6. **user_input / environment**  
   当前用户输入、所在项目、相关参与者和启动来源。

7. **runtime**  
   请求模型、实际模型、推理强度、线程、能力与 fallback 状态。

快照必须保存：

- 实际发送内容；
- 来源文档及版本；
- 明确取回的历史；
- 没有纳入的历史范围；
- 组装原因；
- 请求模型与实际模型。

这样以后才能判断一次偏移是由模型、材料选择、上下文缺失还是程序操作造成的。

## 四、第三阶段：建立薄的开放协议

```json
{
  "message": "可选的对外表达",
  "formation_updates": [
    {
      "text": "可选的正在形成内容",
      "refs": []
    }
  ],

    "refs": [],
    "operations": []
  },
  "pause": {
    "reason": "可选的暂停原因"
  }

```

约束：

- `message`、`formation_updates`、`move`、`pause` 都可缺省；
- 至少返回一种有效内容；
- `formation_updates` 可以为空；
- `move` 可以只有文字和引用；
- `operations` 可以为空；
- 不强制 `intent`、`basis` 或预期效果；

- JSON 前后出现协议外内容时，保存原文并标记 `protocol_error`；

### 2. Move 的最小含义

Move 只回答：

> 现在准备向哪里伸出去，或者准备让什么发生？

允许：

```json
{

  "refs": ["document-a@2", "document-b@1"],

}
```

也允许：

```json

      "type": "create",

      "body": "..."
    }
  ]
}
```

程序只严格验证真实执行所需的参数，不要求模型提前解释一个尚未形成的方向。

### 3. Encounter / Result

Result 统一保存发生事实，但不统一其认识地位：

```text
user_answer
external_read
program_result
generated_material
created_work
project_event
failure
pause
```

每个 Result 保存：

- 类型；
- 状态；
- 原始内容或材料引用；
- 来源参与者；
- 发生时间；
- 对应 Move；
- 对应 Context Snapshot；
- 是否进入后续 Context；
- 后续是否被重新使用。

Result 默认可见，但不要求下一轮立即解释、采用或引用。

- 正在形成；
- 活动与遭遇；
- 继续展开。

这些是视图区域，不是固定认识对象。

必须明确区分：

- 原始材料；
- 模型形成；
- 用户表达；
- 程序实际结果；
- 未验证推断；
- 失败；

频道、工作项、决定和时间线继续保留一级环境导航，但不挤占 Activity 的核心工作区。

## 六、第五阶段：用两个实例让结构自己浮现

不能只用一个通用活动证明架构成立。按照你的原始思路，先做两个便宜实例，再从交集里判断什么是真结构。

### 实例一：开放现实处境

材料从模糊表达开始，例如：

> “我不知道如何实现自己的理想。”

验收重点：

- 系统是否等待用户先展开；
- 是否保留多个可能空间；
- 是否主动照亮主体空间和结果空间；
- 是否避免直接跳到赚钱、职业、学习计划；
- 下一次问题是否由当前材料产生；
- 用户回答后，Context 是否真实改变。

### 实例二：学习或理解活动

从一段真实学习材料开始。

允许：

- 先形成一个局部理解；
- 先提出例子或构造；
- 暂时不制定学习计划；
- 多种解释并存；
- 通过实际构造改变材料。

验收重点：

- 学习是否被压成“问题—答案—计划”；
- 构造是否真正产生新材料；
- 旧理解是否能被结果重新打开；
- 哪些步骤由模型完成，哪些由程序和环境完成。

### 写作作为第三个低成本回归

不把写作做成独立产品模块，只用创作材料检查：

- Move 是否可以只是并置、续写或试写；
- 是否可以没有预先目标；
- 结果是否能成为新材料；
- 协议是否强迫创作先写出 Situation、意图和计划。

只有在两个以上实例中反复出现同一作用，才考虑把它抽象为持久结构。

- Result 后没有新 formation；
