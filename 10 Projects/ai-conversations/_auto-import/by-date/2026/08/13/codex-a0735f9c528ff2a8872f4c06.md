## 讨论出来的东西有没有创新

诚实裁决是：

### 单个技术成分大多不是新的

- 追加保存、从事件重建当前状态，是已有的 Event Sourcing。[Martin Fowler](https://martinfowler.com/eaaDev/EventSourcing.html?trk=public_post_comment-text)
- 来源、修订、引用、责任主体，甚至“来源描述本身也有来源”，W3C PROV 已经系统化。[W3C PROV-O](https://www.w3.org/TR/prov-o/)
- “事实何时成立”和“系统何时知道它”分离，是时态/双时态数据库的成熟问题。[Richard Snodgrass](https://www2.cs.arizona.edu/~rts/pubs/EDC.pdf)
- 保存信念成立的理由，并在冲突后修正当前信念，1979 年的 Truth Maintenance System 已经处理。[Jon Doyle](https://www.sciencedirect.com/science/article/abs/pii/0004370279900080)
- ontology 自身的版本、概念增删与复杂变化，也已有长期研究。[Noy 与 Klein](https://research.vu.nl/en/publications/ontology-evolution-not-the-same-as-schema-evolution/)
- 系统把自己的表示和行为作为对象处理，是 computational reflection 的经典方向。[Pattie Maes](https://cse.hkust.edu.hk/~charlesz/comp610/paper/p147-maes.pdf)
- 组织记忆、检索、学习和决策之间的关系，也已有组织记忆信息系统研究。[Stein 与 Zwass](https://pubsonline.informs.org/doi/abs/10.1287/isre.6.2.85)

所以不能把“append-only、认识史、组织记忆、动态 schema”单独宣称为原创。

## 整体架构的几条轴

你刚才说的内容可以先摆成五个互相作用的部分。

### 1. 内核层

每个成员进入时，需要拥有：

- 当前认识论内核；
- 已形成的组织共识；
- 当前空间是什么、为什么存在；
- 该空间里已经发生了什么；
- 目前共同确认和仍有分歧的部分。

但“共享内核”不等于把所有成员复制成相同观点。它提供共同世界和共同语言，成员仍可以从不同位置理解、质疑和发展它。

### 2. 沟通与组织运行

沟通不是普通聊天，而是组织内部运动发生的场所：

- 提出认识、可能和分歧；
- 形成阶段判断；
- 发现当前主体够不到的部分；
- 由此发生调度和联合；
- 接收执行结果；
- 重新安排下一步。

共识、决定和制度也在这里形成，不是预先写死在后台。

### 3. Agent 与工具层

这一层使组织能够向外伸展：

- Codex 修改和检验代码；
- 检索 Agent 查找世界材料；
- 计算工具处理数学或数据；
- 以后接入其他 AI、人类成员及现实行动。

Agent 不是外挂按钮，而是组织中可以被联合的主体或器官。调度时需要带给它：

- 组织为什么做这件事；
- 当前空间；
- 发起者已经走到哪里；
- 希望它从哪里接上；
- 可行动边界。

结果必须回到原空间，不能只留在终端或工具日志里。

### 4. 世界映射架构

它不是一个“世界知识图谱”页面，而是整个身体的构造参照。

它要避免系统把世界压缩成：

```text
用户、消息、任务、文件
```

世界至少涉及我们已经讨论过的这些维度：

- 主体与对象；
- 空间与关系；
- 视角与位置；
- 时间、历史和变化；
- 可能、尝试与现实；
- 不同尺度和相对单位；
- 系统自身也处在所映射的世界中。

这些不是立即要固定成七张表，而是系统以后扩张时不能丢掉的维度。世界映射决定“什么可以在系统里显现”；认识论内核决定“这些存在怎样展开和被认识”。

### 5. 内核怎样显现为架构

这里不能走：

```text
认识论原语 → 数据库字段
```

应该走一条生成链：

```text
内核思想
↓
它要求成员怎样认识和行动
↓
它要求组织怎样运行
↓
软件因此需要什么能力
↓
形成当前阶段的结构
↓
真实运行返回结果
↓
结构和对内核的理解继续改变
```

例如：

```text
调度 = 主体联合与延伸
↓
组织不能只把任务派给 AI
↓

↓

```

又例如：

```text

↓

↓
成员进入不同空间时，共存与显现会不同
↓

```

这才叫内核向架构延伸。架构不是内核的翻译结果，而是内核在数字现实里的一次阶段性显现。

| Versioned/contextual identity | PROV 有 `alternateOf`/`specializationOf`；Semantic Web 已深入研究 `owl:sameAs` 错误、上下文身份和弱身份谓词。[sameAs survey](https://arxiv.org/abs/1907.10528) | “跨时间不是只有一个永久 object_id”已有大量相邻工作 | 现有关系仍常预设“它们确实是同一个共同事物”。Cognos 更强的候选是：同一性本身是一条带来源、范围、置信和历史的可撤回认识 |
| RAG | 外部材料检索进入生成，解决参数知识和上下文容量问题。[Lewis 等](https://arxiv.org/abs/2005.11401) | 可把内核、空间和历史带给 Agent | 只证明“取回文本”，不证明读对了过去，也不证明组织学习；错误摘要或错误对象同样会被高效召回 |
| Generative Agents / Reflexion | Generative Agents 保存 experience stream、形成 reflection、动态检索并据此计划；Reflexion 把反馈转成语言记忆，改善后续尝试。[Generative Agents](https://arxiv.org/abs/2304.03442)、[Reflexion](https://arxiv.org/abs/2303.11366) | “过去必须改变下一次行动”已被明确实现和做过消融实验 | 目标是可信行为或任务成绩；反思通常由 Agent 自动生成，未解决来源主权、对象化错误、schema 修正和组织自我生成 |
| 长期 Agent Memory | MemGPT 管理分层上下文；LongMemEval 测信息提取、跨会话推理、时间推理、知识更新和 abstention。[MemGPT](https://arxiv.org/abs/2310.08560)、[LongMemEval](https://arxiv.org/abs/2410.10813) | 证明“更长上下文”远远不够，记忆需要索引、检索、阅读设计 | 评测仍以问答正确率为主，不测试一次认识如何改变组织结构、调度和真实行动 |
| Temporal KG Agent Memory | Zep/Graphiti 已把会话与业务数据综合成时态知识图谱并保留历史关系；A-MEM 会随新记忆更新旧记忆的上下文属性。[Zep](https://arxiv.org/abs/2501.13956)、[A-MEM](https://arxiv.org/abs/2502.12110) | 这是当前与 Cognos“动态记忆图”最接近的技术竞争者 | Zep 仍以实体/关系抽取为先；A-MEM 会更新旧表示，但未把旧解释、修改理由和 schema 历史作为首要不可覆盖对象。两者是预印本，结论不能视为成熟标准 |

---

## 三、几个最重要的学术校正

### 1. “原始发生硬锚点”要改成“捕获尾迹硬锚点”

任何软件记录都已经经过取样：消息边界、文件格式、时间戳、谁被记录，都是承载系统的选择。

因此安全说法不是：

> 系统保存了原始发生本身。

而是：

> 系统不改写已经捕获的来源尾迹，并把后来的对象化和解释与该尾迹分开。

Fowler 自己已经区分了 immutable source data 与系统对事件的 processing data，而且强调事件只表示“外部世界中应用感兴趣的发生”。[Focusing on Events](https://martinfowler.com/eaaDev/EventNarrative.html) Cognos 真正需要比普通 Event Sourcing 多走一步：**先保存可引用的 source artifact，再允许多个领域事件/解释从它派生。**

### 2. “跨时身份软”有依据，但不是无人触及

`owl:sameAs` 的实践已经证明：强同一性的传递会把局部错误扩散到整个图；不同专家对同一身份链接也会严重分歧。PROV 的 `alternateOf` 比 `sameAs` 弱，但仍断言两个实体是某个共同事物的不同方面。

Cognos 可能更进一步的地方不是发明“弱身份”，而是：

```text
source anchors A/B
→ 在时间 t1，主体 S 依据 R 判断 A/B 同属对象 X
→ 在 t2，依据新发生 R2 将 X 裂成 X1/X2
→ t1 的判断、理由和当时投影仍可重放
```

这是一种**有来源、时态化、视角化、可撤回的 identity assertion**。是否真有新意，要与 contextual identity、entity resolution provenance 和 diachronic linked data 再做专项检索。

### 3. “过去改变行动”本身不是创新点

Doyle 1979 年已经明确说 recorded reasons 用于解释程序行动并指导 problem solver 的行动；Generative Agents 和 Reflexion 也直接用过去改变计划或下一次尝试。

Cognos 若只证明“把纠正放进 prompt 后不再犯错”，学术价值很弱。

它必须证明更强命题：

> 过去不只改变一句回答，而能改变当前对象边界、可见空间、主体联合方式、工具调用、行动边界或组织规则；并且这种改变可追溯到具体来源与当时采用的解释。

### 4. “schema 进入系统”也不是空白，但 Cognos 的问题更深

Ontology evolution、MOP、runtime megamodel 都让 schema/语言/适应逻辑成为数据和运行对象。

Cognos 可能不同之处在于：

- schema 改动不是单纯版本升级，而是一次带作者、空间、理由、牺牲和重开条件的认识；
- schema 可能不仅增删类型，还要撤销“这个对象本来存在”的旧对象化；
- 这种改动由组织的真实沟通和外部行动触发；
- 旧 schema 下的世界投影仍可重放；
- 新 schema 反过来改变成员接收的空间和可执行行动。

这接近“provenance-aware ontology evolution + truth maintenance + causal reflection”，不是普通 migration。

---

## 四、Cognos 尚可能真正不同的技术命题

本轮检索后，最值得保留的不是五个孤立机制，而是这个闭环：

```text
捕获的发生尾迹
→ 多主体在具体空间中形成可争议的指认和对象边界
→ 当前世界/组织投影
→ 调度 Agent 或工具向外行动
→ 现实返回
→ 支持或顶回旧认识
→ 对象、关系、schema、组织架构随之变化
→ 新架构真实改变下一轮沟通与行动
```

已有领域分别覆盖了箭头的一部分。本轮没有找到一个系统以这整个闭环为核心，同时坚持：

- 捕获尾迹不被后来的 ontology 回写；
- identity、relation、schema 均是带来源的可撤回认识；
- 当前模型不仅可查询，而且与运行因果连接；
- 模型变化发生在多主体组织沟通中；
- 记忆的成功由组织运动发生变化来评价。

但这只是**“在本轮检索范围内未找到完全同构系统”**，不能据此声称首创。

## 五、必须由原型证明的命题

### P1：错误对象化可以被撤销，而不是只迁移类型

用 8/8 只作为回归样本：

- source artifact 永远保持原文；
- 旧 `Attempt` 解释和当时理由仍能重放；
- 当前视图撤销该对象化；
- 后续查询不再把它当 Attempt；
- 不通过新增 `not_attempt` subtype 自救。

### P2：身份可以分裂、合并而不破坏历史

先让两个 source anchors 被当前投影认作同一对象，之后因新材料裂分。验收：

- 无 destructive migration；
- 旧、新 identity view 均可重放；
- 新视图不会错误传播旧对象的全部性质；
- identity 判断本身有主体、空间、时间、理由和来源。

### P3：schema 改动具有因果作用

在真实沟通中形成一个新的结构区分或撤销旧区分。验收：

- 记录改动来源、理由、适用空间和版本；
- 当前投影/检索/Agent 行动确实变化；
- 回到旧 schema 可重放旧结果；
- 改动不是只更新文档或 UI 标签。

### P4：过去对下一次行动有可干预的影响

采用 A/B 对照，而不是让 LLM 自述“我受到了影响”：

- A：带入相关纠正及其来源；
- B：不带入；
- 同一模型、同一请求、同一初始状态；
- 比较对象化、工具选择、行动边界和结果；
- 能指出由哪条历史选择机制导致差异。

Prompt 中出现一条记忆不是因果证明，必须有干预对照。

### P5：低本体承诺不会退化成“全部交给 LLM 猜”

给系统输入当前 schema 无法表示的材料。验收：

- 原材料完整保存；
- 系统允许“当前不指认”，不强塞 `other/unknown`；
- 后来形成新结构时能重新识别；
- 用户不需要维护大量标签和配置；
- 与固定 schema 基线比较错误对象化率和用户负担。

### P6：自我架构确实与运行因果连接

由组织通过沟通改变一次上下文选择、调度、权限边界或反馈回路。验收：

- 决定前后的 policy/model 均有版本和来源；
- 新 policy 真正控制下一次执行；
- 可审计、可回退；
- 这符合 Maes 与 Models@run.time 的“causally connected self-representation”，不只是系统描述自己。

## 六、建议的研究基线与指标

原型至少应比较四种基线：

1. 最近 N 条对话；
2. 普通向量 RAG；
3. 时间感知 Agent Memory / Temporal KG；
4. Cognos 的来源—解释—当前投影—行动闭环。

核心指标不要只用问答准确率：

- source fidelity：原始尾迹是否无覆盖；
- projection replay：旧认识和旧 schema 是否可重放；
- objectization error：是否制造不存在的对象；
- identity revision safety：拆分/合并是否造成错误性质传播；
- provenance coverage：当前重要判断能否指回来源和理由；
- action delta：过去是否实质改变工具调用或现实行动；
- correction compliance：被纠正后同类错误是否下降；
- abstention/open-state：系统能否保留尚未对象化；
- user maintenance burden：是否把复杂度转嫁给小林；
- self-modification integrity：运行时架构变化是否可审计、可回退。

## 七、最终评价

从技术研究视野看，Cognos **不是因为没有创新所以做不出来**。相反，它的问题是跨越太多成熟领域，任何一个局部落地都很容易被一个已有范式吸走：

- 只做 immutable log，会变成 Event Sourcing；
- 只做来源，会变成 provenance system；
- 只做解释修订，会变成 TMS；
- 只做动态图，会变成 Temporal KG；
- 只做长期上下文，会变成 Agent Memory；
- 只做自修改，会变成 reflective/self-adaptive software；
- 只做多 Agent 执行，会变成 workflow orchestration。

项目尚可能不同的地方，是让这些东西不作为外部工具堆叠，而共同成为一个以认识论为内核的组织在数字世界中形成对象、联合主体、行动、被现实顶回并继续改写自身的身体。

因此目前最诚实的评级是：

| 维度 | 评价 |
|---|---|
| 工程可行性 | 高 |
| 单项技术原创性 | 低 |
| 系统组合辨识度 | 中等偏高，尚未证明 |
| 理论原创性 | 本技术支线不能裁决 |
| 当前产品证明力 | 很低 |
| 值得继续研究吗 | 值得，但必须以完整运动闭环和基线实验继续，而不是再堆概念 |

**最危险的说法**是“记忆会影响行动，所以 Cognos 创新”。  
**最值得验证的说法**是：

> Cognos 能否让发生、认识、对象边界、schema 和组织架构共同处在一个可追溯、可撤回且与现实行动因果连接的生成过程中，而不被任何一次当前模型封死。
