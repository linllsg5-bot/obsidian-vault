## 讨论出来的东西有没有创新

诚实裁决是：

### 单个技术成分大多不是新的

- 追加保存、从事件重建当前状态，是已有的 Event Sourcing。[Martin Fowler](https://martinfowler.com/eaaDev/EventSourcing.html?trk=public_post_comment-text)
- 来源、修订、引用、责任主体，甚至“来源描述本身也有来源”，W3C PROV 已经系统化。[W3C PROV-O](https://www.w3.org/TR/prov-o/)
- “事实何时成立”和“系统何时知道它”分离，是时态/双时态数据库的成熟问题。[Richard Snodgrass](https://www2.cs.arizona.edu/~rts/pubs/EDC.pdf)
- 保存信念成立的理由，并在冲突后修正当前信念，1979 年的 Truth Maintenance System 已经处理。[Jon Doyle](https://www.sciencedirect.com/science/article/abs/pii/0004370279900080)
- ontology 自身的版本、概念增删与复杂变化，也已有长期研究。[Noy 与 Klein](https://research.vu.nl/en/publications/ontology-evolution-not-the-same-as-schema-evolution/)
- 系统把自己的表示和行为作为对象处理，是 computational reflection 的经典方向。[Pattie Maes](https://cse.hkust.edu.hk/~charlesz/comp610/paper/p147-maes.pdf)
- 组织记忆、检索、学习和决策之间的关系，也已有组织记忆信息系统研究。[Stein 与 Zwass](https://pubsonline.informs.org/doi/abs/10.1287/isre.6.2.85)

所以不能把“append-only、认识史、组织记忆、动态 schema”单独宣称为原创。

## 整体架构的几条轴

你刚才说的内容可以先摆成五个互相作用的部分。

### 1. 内核层

每个成员进入时，需要拥有：

- 当前认识论内核；
- 已形成的组织共识；
- 当前空间是什么、为什么存在；
- 该空间里已经发生了什么；
- 目前共同确认和仍有分歧的部分。

但“共享内核”不等于把所有成员复制成相同观点。它提供共同世界和共同语言，成员仍可以从不同位置理解、质疑和发展它。

### 2. 沟通与组织运行

沟通不是普通聊天，而是组织内部运动发生的场所：

- 提出认识、可能和分歧；
- 形成阶段判断；
- 发现当前主体够不到的部分；
- 由此发生调度和联合；
- 接收执行结果；
- 重新安排下一步。

共识、决定和制度也在这里形成，不是预先写死在后台。

### 3. Agent 与工具层

这一层使组织能够向外伸展：

- Codex 修改和检验代码；
- 检索 Agent 查找世界材料；
- 计算工具处理数学或数据；
- 以后接入其他 AI、人类成员及现实行动。

Agent 不是外挂按钮，而是组织中可以被联合的主体或器官。调度时需要带给它：

- 组织为什么做这件事；
- 当前空间；
- 发起者已经走到哪里；
- 希望它从哪里接上；
- 可行动边界。

结果必须回到原空间，不能只留在终端或工具日志里。

### 4. 世界映射架构

它不是一个“世界知识图谱”页面，而是整个身体的构造参照。

```text

```

- 主体与对象；
- 空间与关系；
- 视角与位置；
- 时间、历史和变化；
- 可能、尝试与现实；
- 不同尺度和相对单位；
- 系统自身也处在所映射的世界中。

### 5. 内核怎样显现为架构

这里不能走：


```text

↓

↓

↓

↓

↓

```

```text

↓

↓
```

```text

↓

```

这才叫内核向架构延伸。架构不是内核的翻译结果，而是内核在数字现实里的一次阶段性显现。

## 一、共享内核和空间共识：学术上不应理解成“大一统 Prompt”

### 1. Common Ground：共同到“足以继续行动”，不等于观点一致

Clark 与 Brennan 认为，所有集体行动都依赖共同基础；参与者必须逐刻确认“双方已经理解得足以完成当前目的”。共同基础会随媒介和目的变化，不是一次加载完成的知识包。[Grounding in Communication](https://www.cs.cmu.edu/~illah/CLASSDOCS/Clark91.pdf)

这正好为 Cognos 区分两件事：

- **内核共识**：为什么联合、怎样对待认识和判断、权责与边界是什么。
- **空间共识**：此地为什么存在、正在处理什么、现实状态怎样、有哪些分歧。

共识不能把分歧抹掉。正确标准不是成员复述出同一段话，而是：

- 能否准确识别共同目的；
- 能否知道哪些已经共同接受、哪些仍不一致；
- 遇到误解时能否修复到足以继续联合行动。

### 2. Shared Mental Models 与 Transactive Memory

团队研究区分：

- 共享心智模型：对任务、流程和成员责任的共同理解；
- 交互记忆：不要求人人知道全部，而是知道“谁知道什么、谁能做什么”。

团队心智模型与团队过程、绩效有稳定关联；交互记忆尤其适合由不同专长成员构成的团队。[National Academies 团队研究综述](https://www.ncbi.nlm.nih.gov/books/NBK310384/)、[Lewis 2004](https://pubsonline.informs.org/doi/abs/10.1287/mnsc.1040.0257)

因此 Cognos 的第一版不应给所有 Agent 塞同一份巨大上下文，而应至少在认知上区分：

1. 共同内核；
2. 当前空间的共同情势；
3. 当前联合的目的与状态；
4. 谁/什么具有哪种能力和材料；
5. 仍未共同化的认识。

## 二、沟通如何成为组织：CCO 是非常近的传统

Taylor 与 Van Every 的“沟通构成组织”理论认为，组织不是先存在、再使用沟通；组织在 conversation 与 text 的交织中形成身份、获得跨地点和跨时间的连续性。[The Emergent Organization](https://www.routledge.com/The-Emergent-Organization-Communication-As-Its-Site-and-Surface/Taylor-VanEvery/p/book/9780805821949)

这与“在沟通中进行架构设计”“组织首先在沟通场里形成”高度相近。

但 Cognos 与它仍有重要差别：

- Cognos 不能只把组织缩成沟通的自我延续；
- Agent、文件、程序、现实结果和工具并非沟通的附属物；
- 成员的主体性、尝试与现实回撞仍然是核心；
- 软件架构本身也必须成为组织能改变的承载。

所以 CCO 可以支持“沟通不是聊天功能，而是组织的构成过程”，却不能独自构成 Cognos。

## 三、沟通 → 调度/联合 → 执行 → 返回：已有很成熟的“共同活动”研究

### 1. 共同意向不是几个人同时行动

Cohen 与 Levesque 指出，团队行动不是相互协调的个体行动之和；成员需要关心整体联合的状态，并对共同活动形成承诺。[Teamwork](https://www.sri.com/publication/teamwork/)

Grosz 与 Kraus 的 SharedPlans 进一步处理了：

- 成员只拥有部分知识；
- 联合活动可以逐渐展开；
- 子行动可由个体、子组或外部承包者承担；
- 成员既对自己的部分负责，也对联合整体保有承诺。[Collaborative Plans for Complex Group Action](https://www.sciencedirect.com/science/article/pii/0004370295001034)

这非常接近“调度是主体联合，而不是派任务”。Cognos 的一次调度至少应有：

- 为什么此刻需要联合；
- 成员各自从什么位置接入；
- 对共同结果作出什么承诺；
- 行动状态对彼此是否可见；
- 条件变化时能否相互改向；
- 失败、完成或目标失效时能否共同解除或重组联合。

### 2. Agent 不是被调用就自动成为团队成员

Klein、Woods 等提出，自动化要成为 team player，必须满足共同活动的 Basic Compact，并具备共同基础、相互可预测、可观察、可引导与协调修复能力。[Ten Challenges for Making Automation a Team Player](https://www.ihmc.us/wp-content/uploads/2021/04/17.-Team-Players.pdf)

所以：

```text
用户按按钮 → Codex 执行 → 返回结果
```

只是工具调用。

只有当 Codex 能理解联合整体、报告自己看到的变化、允许对方改向、对失败和目标变化作出协调反应时，才开始接近成员或组织器官。

## 四、学习为什么是跨轮变化：活动理论与组织惯例提供了最强参照

### 1. 扩展性学习

Engeström 的活动理论把学习理解为：集体面对现有活动中的矛盾，形成此前并不存在的新对象和新活动结构；改变的不只是成员知识，还包括工具、规则、共同体和劳动分工。[Learning by Expanding](https://researchportal.helsinki.fi/sv/publications/learning-by-expanding-an-activity-theoretical-approach-to-develop/)

这是当前最接近 Cognos“学习是主体与组织完整展开”的学术传统。

但 activity-system 三角只能作为观察镜，不能直接变成 Cognos 的世界本体表。否则又会把：

```text
subject / object / tool / rules / division of labor
```

预先固定成世界只能具有的结构。

### 2. 组织惯例不是静态流程

Feldman 与 Pentland 区分：

- ostensive：成员对惯例的抽象理解；
- performative：具体的人在具体时空中的实际施行。

每次实际施行既受抽象惯例引导，又可能反过来改变它。惯例因此可以同时带来稳定与变化。[Feldman & Pentland 2003](https://socialecology.uci.edu/sites/socialecology.uci.edu/files/users/feldmanm/Feldman_and_Pentland_2003.pdf)、[Feldman 2000](https://pubsonline.informs.org/doi/10.1287/orsc.11.6.611.12529)

这给 Cognos 一个非常精确的要求：

> 内核、制度、架构和组织运行方式不能只保存版本；必须能看到它们在真实施行中怎样被维持、偏离和改写。

因此学习不是执行链的末端按钮，而是前一轮行动结果导致后一轮：

- 看见的对象不同；
- 联合方式不同；
- 判断规则不同；
- 分工或位置不同；
- 软件能力不同。

### 3. 学习与工作不能被分成两个模块

Brown 与 Duguid 发现，组织正式手册描述的工作与真实实践常有根本差异；学习和创新恰恰发生在实际实践共同体中。[Organizational Learning and Communities of Practice](https://pubsonline.informs.org/doi/abs/10.1287/orsc.2.1.40)

所以 Cognos 不能设计成：

```text
先运行
→ 再写学习总结
```

学习必须从真实联合和行动内部浮现。

## 五、位置轮转：不是定时切换角色，而是影响力与承担关系发生变化

Lave 与 Wenger 把学习理解成成员在实践共同体中的参与位置和身份发生改变，而不是单纯获得知识。[Situated Learning](https://www.cambridge.org/highereducation/books/situated-learning/6915ABD21C8E4619F750A4D4ACA616CD/legitimate-peripheral-participation/28CD74BD15EBFABE881F24826917EC4C)

共享领导研究也显示，领导影响可以随团队内部互动分布和涌现；其效果取决于信任、任务相互依赖和实际工作环境，不是“扁平结构天然更好”。[共享领导 Meta-analysis](https://www.sciencedirect.com/science/article/abs/pii/S1048984314000691)

Davis 与 Eisenhardt 对技术合作的研究发现，高创新合作中领导权会在合作方之间轮转，由能够推进当前重组问题的一方主导。[Rotating Leadership and Collaborative Innovation](https://www.mit.edu/~jasond/rotatingleadership.pdf)

因此 Cognos 的位置轮转应检验：

- 当前哪位成员实际上定义了问题；
- 谁拥有相关世界接触和能力；
- 谁承担决定、执行、质疑或整合；
- 现实返回后，主导权和责任是否自然移位；
- 这种移位是否真正改变了可见信息和行动权。

随机轮换角色名、按轮次换 moderator，都不构成这里的轮转。

## 六、世界映射：分布式认知与 ANT 提供两种互补视角

### 1. 分布式认知

Hutchins 研究舰船导航时，把整个“人—仪器—表征—操作流程”看作认知系统；系统具有不同于任何单个成员的认知性质。[Cognition in the Wild](https://mitpress.mit.edu/9780262581462/cognition-in-the-wild/)

对 Cognos 的直接启发是：

- 文件、界面、程序、记录、Agent 和成员共同构成认知身体；
- 世界映射不能只是数据库中的知识图谱；
- 信息怎样在成员、表征和工具之间传播与转化，比“存了哪些对象”更重要；
- Cognos 是否开始存在，可以部分通过“整体产生了单个成员没有的认知能力”判断。

### 2. Actor–Network Theory

Latour 反对预先用“社会”解释世界，主张追踪实际连接中的人类与非人类参与者；对象同样可能对事态产生差异。[Reassembling the Social](https://academic.oup.com/book/52349)

ANT 对 Cognos 世界映射的价值是：

- 不预先把世界压成用户、消息、任务；
- 工具、代码、文件、模型、现实阻碍都可以成为实际作用者；
- 先追踪谁/什么真的改变了行动，再决定如何认识它；
- 不应先假设哪些对象必然属于哪种类型。

但 Cognos 不能简单采用 ANT，因为 ANT 倾向暂停主体/客体的先验区分，而 Cognos 的主体、尝试、认识论内核仍然有明确地位。

## 七、自我生成与“新存在”：autopoiesis 和 cybernetics 只能作为严格类比

Maturana 与 Varela 用 autopoiesis 描述自主、自指、持续生产自身构成的生命系统。[Autopoiesis and Cognition](https://link.springer.com/book/10.1007/978-94-009-8947-4)

Luhmann 将其转用于社会系统，把组织理解成由沟通过程递归产生的闭合网络。[Luhmann 组织理论概述](https://www.cambridge.org/core/journals/european-business-organization-law-review-ebor/article/abs/autopoietic-systems-not-corporate-actors-a-sketch-of-niklas-luhmanns-theory-of-organisations/8BE12EE391E7B029A63FE385CD1823BC)

Beer 的 Viable System Model 关注组织怎样在环境复杂性中维持自身身份、协调自治单元并保持适应能力。[VSM 概述](https://ojs.wgtn.ac.nz/somwp/article/view/7161)

这些传统使“什么时候算开始存在”可以被操作化，而不只是一句诗性描述：

- 能否持续再生产自己的沟通和联合；
- 能否维持一条可辨认的内核与组织身份；
- 能否对环境变化产生足够多样的响应；
- 能否在成员或工具更替后继续；
- 能否改变自己的运行结构而不中断连续性。

但必须避免把“数字系统有循环反馈”就称作生命或 autopoiesis。Cognos 必须实际证明哪些构成被它自己持续生产，而不是由开发者在系统外维护。

## 八、工程邻域：可以借，但最容易把 Cognos 做窄

### 多 Agent 组织模型

Gaia 把 MAS 看成由互动角色构成的计算组织；MOISE+ 区分结构、功能和规范；OperA 用角色、权利、义务和交互契约描述开放 Agent 社会。[Gaia](https://eprints.soton.ac.uk/253748/)、[MOISE+](https://moise.sourceforge.net/)、[OperA](https://www.cambridge.org/core/services/aop-cambridge-core/content/view/B8E27F2C2BB97291BB739F168F0D6C35/S0269888904000244a.pdf)

它们适合借鉴：

- 权责；
- 共同承诺；
- 开放成员加入；
- 失败与重组；
- 组织层与个体层的区别。

却最容易造成固定 role、goal、norm、mission、workflow，把 Cognos 变成 agent orchestration platform。

### Blackboard

Blackboard 架构让多种知识源围绕一个共享工作空间，对同一问题进行机会主义协作。[Nii 1986](https://onlinelibrary.wiley.com/doi/abs/10.1609/aimag.v7i2.537)

它适合实现“不同成员在共同空间显现部分结果”，但黑板不是空间本身，更不能让右栏任务板替代组织。

### Stigmergy

Stigmergy 用环境中的工作痕迹实现间接协调；开放源码社区可以通过 work-in-progress 自组织贡献。[Heylighen 2006](https://arxiv.org/abs/cs/0612071)

它能解释为什么代码、文件和未完成痕迹本身能调度后续成员。但如果只做成“任务状态吸引 Agent 领取”，又会退化成 issue tracker。

## 九、项目最容易落入的普通软件形态

1. **共享内核 → 巨型 system prompt**  
   成员只有同文复述，没有当场 grounding 和分歧修复。

2. **沟通 → 群聊**  
   消息增多，但没有共同承诺、联合状态和组织连续性。

3. **调度 → manager 派任务给 worker**  
   Agent 不理解整体，不能相互改向，只是函数调用。

4. **空间 → channel / project_id**  
   空间内容不改变成员能看到、能联合、能行动的范围。

5. **世界映射 → 预设 ontology 或知识图谱**  
   系统只会识别 schema 已知的世界。

6. **学习 → 总结、RAG 或规则更新**  
   保存了教训，却没有改变下一轮的对象、惯例、分工和能力。

7. **位置轮转 → 定时换角色 Prompt**  
   没有责任、视角、权力和行动能力的真实转移。

8. **自我生成 → 用户在外部让 Codex 改代码**  
   如果组织内部没有提出、讨论、承担和吸收这次改动，它仍只是开发工具。

9. **集体智能 → 输出比分更高**  
   Woolley 等证明群体存在可测的集体表现因素，但这不足以证明一个“新存在”。[Science 2010](https://pubmed.ncbi.nlm.nih.gov/20929725/)

## 十、可以检验的 Cognos 评价标准

### A. 共同基础

- 新成员进入后，能否说清内核、当前空间、已定与未决，而无需通读全部历史？
- 遇到歧义时，成员会不会发现并修复，而不是各自沿错误理解执行？
- 共识是否允许明确保留不同认识？

### B. 主体联合

- 一次调度是否产生了联合承诺，而不是单向命令？
- 各参与者是否知道整体状态、自己的接合点和其他成员的相关能力？
- 执行过程中能否相互观察、纠正和改向？

### C. 外部现实耦合

- Agent/工具是否真实接触代码、文件、网络或其他现实材料？
- 成功、阻碍、变形和失败是否都返回原空间？
- 返回是否改变了接下来的问题和行动，而不是只形成日志？

### D. 跨轮学习

- 相似情境再次出现时，组织是否真的采取了不同动作？
- 改变的是一句提示，还是对象理解、惯例、分工、能力或架构？
- 能否指出哪一次现实结果促成了改变？

### E. 位置变化

- 主导、判断、执行和质疑的位置是否随能力、阶段和现实回撞发生变化？
- 位置变化是否伴随真实的信息权、行动权和责任变化？
- 是否避免永久角色与机械轮换两种极端？

### F. 组织层能力

- 整体是否完成了任一单独成员无法完成的认识或行动？
- 更换模型、重启服务或成员退出后，联合是否仍可继续？
- 组织是否具有可识别而非完全依赖某个 Agent 的连续性？

### G. 自我构成

- Cognos 是否能在自身空间中发现一种运行缺陷；
- 形成修改自己承载方式的联合；
- 让 Agent 实施；
- 吸收现实结果；
- 下一轮实际按新结构运行；
- 同时不把旧运行历史伪造成新结构下的内容？

这是目前最有力的第一版终极测试。

## 对项目的分层评价

| 层面 | 当前评价 |
|---|---|
| 哲学与研究命题 | 有辨识度，但需与更广思想史继续对接 |
| 组织理论组合 | 高度相关传统很多；组合有潜力，不宜宣称局部概念原创 |
| 系统架构 | 存在真正的创新机会，尤其在组织内部自改写承载这一闭环 |
| 当前软件 | 尚未展示上述创新，只证明了通信、Codex 接入和历史持久化 |
| 研究价值 | 高；因为可以形成可证伪的“数字组织开始存在”实验 |
| 最大风险 | 用普通协作软件的概念把整体思想等价替换掉 |

一句最终裁决：

> **检索没有否定 Cognos，反而说明它抓住的许多局部问题都是真问题；但也消除了“只要把这些概念放在一起就自然创新”的幻觉。项目的价值将取决于能否让这套认识论在一个真实的人—AI—工具组织中产生可观察的组织层运动、自我学习和承载自改写。**
