# Part 1：架构详解

## 三层架构

```
┌─────────────────────────────────────────────────────────┐
│  Layer 1: 原型层（Artifact Layer）                       │
│  作品胚胎的持久存储；用户的圣物，AI 不可改写              │
└─────────────────────────────────────────────────────────┘
                          ↑↓
┌─────────────────────────────────────────────────────────┐
│  Layer 2: 联网层（Network Layer）                        │
│  双重含义：跨原型联网（内）+ 跨媒介联网（外）             │
└─────────────────────────────────────────────────────────┘
                          ↑↓
┌─────────────────────────────────────────────────────────┐
│  Layer 3: 处理层（Processing Layer）                     │
│  策展 / 对话 / 沉积 / 模式检测                           │
└─────────────────────────────────────────────────────────┘
```

---

## Layer 1：原型层

**核心定义**：每个"原型"是一等公民对象，不是聊天记录。

### 数据结构

```yaml
原型:
  id: uuid
  text: 用户的原始片段（不可被 AI 修改）
  created_at: 时间戳
  metadata:
    triggered_by: 触发源（音乐/画面/念头/其他）
    mood: 情绪标签（可选）
    related_to: [其他原型 id, ...]  # 用户手动标的关联
  sediment:
    - session_id: xxx
      date: 2026-05-23
      summary: "这次对话围绕原型挖出来的线"
      surfaced_materials:
        - source: "Anne Carson - Eros the Bittersweet"
          quote: "..."
          why_it_resonated: "..."
  patterns:  # 由 AI 自动维护
    - "你在这条原型上反复回到'不信任'这个主题"
    - "你给它的两次注意力都在凌晨"
```

### 关键设计原则

| 原则 | 说明 |
|------|------|
| **不可改写** | 原文是用户的圣物。AI 只能往周围加东西，不能动文本本身 |
| **可冻结、可孵化** | 用户可以把原型标成"完成"（变成成品），或继续"养"它 |
| **可分裂** | 一个原型养着养着可能分裂成两三个新原型——支持这种生长 |
| **可消亡** | 死掉的原型不能删，要标 archived；几年后回看会有意外 |

## Layer 2：联网层

### 内部联网（跨原型）

```
原型 A: 清子在餐厅独自哼笑
   │
   │（语义近似 → 自动检测）
   ↓
原型 B: 二姐梦境片段（同样的"独自/孤独/夜晚"主题）
   │
   │（人物相关 → 显式连接）
   ↓
原型 C: 雪（由纪宫麻的孤独）
```

**实现路径**：每个原型生成 embedding，存向量数据库，定期跑相似度聚类。用户打开原型 A 时，自动推荐"你写过的相关碎片"。

### 外部联网（跨媒介）

这是真正难的部分。一个原型贴进来要拆成多个搜索意图：

```
原型："清子记起芊芊的毒誓"
        ↓ AI 拆解 ↓
搜索意图:
  1. 文学：用毒誓施压的恋人（陀思妥耶夫斯基、张爱玲、Anne Carson）
  2. 哲学：自我诅咒在亲密关系中的心理结构
  3. 电影：长期伴侣非对称争吵的镜头（春光乍泄、一一）
  4. 绘画：表达爱与攻击共存的画作（Schiele、Frida）
  5. 音乐：捕捉这种气味的歌（Nick Cave?）
  6. 历史：古希腊的诅咒铭文、明清诅咒文化
```

**这一层最难的不是 API，是查询构造。** 通用搜索引擎不会做这种"创作意图分解"。

### 数据源（需要逐步建）

| 媒介 | 候选源 | 难度 |
|------|------|------|
| 文学全文 | Project Gutenberg, Internet Archive, 中文电子书库 | 中。版权问题麻烦 |
| 美术图像 | Google Arts & Culture, Wikimedia, 各美术馆开放 API | 低 |
| 电影截图/台词 | Letterboxd 数据、OpenSubtitles | 中 |
| 音乐 | Spotify/Apple Music API（只能给链接，不能给音频） | 低 |
| 历史/文化 | Wikipedia, JSTOR（需购买） | 中 |

## Layer 3：处理层

四种动作，循环往复：

### 1. 策展（Curation）

**输入**：搜索引擎返回的 30-50 条原始结果
**输出**：5-10 条精选

策展的核心不是"最相关"，是"**最可能触发**"。这两个标准不一样——最相关的可能是百科条目（无聊），最可能触发的可能是一句奇怪的诗（不在表层关键词里）。

**实现**：让 AI 用一个特殊 prompt 做筛选——"这是一个写作者，她刚写了 X。给她什么能让她想再写一段？而不是让她得到知识？"

### 2. 对话（Conversation）

**用户跟 AI 围绕策展结果展开**。
- 用户："我喜欢 Anne Carson 那段，再多讲点她"
- AI 深入 Carson 的诗学
- 用户："不对，我感兴趣的是她描述身体袭击的语法"
- AI 调焦到 Carson 的句式分析

这一层的关键设计：**对话不是闲聊，是聚焦**。AI 应该不断把对话拉回原型本身。

### 3. 沉积（Sedimentation）

**这是核心机制**。会话结束时（或定期），AI 自动做：

```python
def sediment(session):
    summary = ai.summarize(
        prompt=f"""
        围绕原型 {session.artifact_id}，这次对话挖出来这些线：
        - 用户特别注意了什么
        - 哪些材料触发了她
        - 出现了哪些新的角度
        把这些浓缩成 3-5 条可携带的认知，挂在原型下面。
        """,
        conversation=session.history
    )
    artifact.sediment.append(summary)
```

**关键**：沉积不是聊天历史回放。是把对话**蒸馏**成下一次能用的浓缩物。聊天历史可以删（节约存储），沉积摘要必须留。

### 4. 模式检测（Pattern Detection）

跨多个原型 + 跨多次沉积。定期跑（每周/每月）：

- "你最近三个月写了 5 段关于不信任"
- "清子和芊芊那对你回访过 12 次，比其他角色对都多"
- "你今年凌晨写的原型比白天多 3 倍"

这些模式**反馈给用户**，让她看到自己看不到的自己。

## 跟 ChatGPT / Claude 的根本差异

| 维度 | ChatGPT/Claude | 原型刺激器 |
|------|--------------|-----------|
| 主语 | Query | **作品（原型）** |
| 会话状态 | 事件，无累积 | **沉积**，每轮浓缩回填 |
| 价值随时间 | 平稳 | **累加** |
| 切换成本 | 零 | **高**——三年沉淀别人赶不上 |
| UI 心智模型 | "我问 AI" | "我在养一棵作品，AI 是花匠" |

## A. AI 写作工具（直接竞品）

### A1. Sudowrite ⭐⭐⭐⭐⭐ 最大威胁

**官网**：https://sudowrite.com/
**定价**：$10-100+/月，订阅制

**核心**：自研 Muse 1.5 模型，专为小说叙事训练。

**功能矩阵**：

| 功能 | 做什么 | 跟原型刺激器的关系 |
|------|------|--------------------|
| Write | 续写下 300 字，提供多种风格选项 | Mode 3 |
| Brainstorm | "Yes, and" 模式无限脑暴 | 跟我们的策展类似，但**没有跨媒介**也**没有沉积** |
| Describe | 把简单描述扩展成感官细致段 | 工具型 |
| Expand | 单句扩成段落 | 工具型 |
| Rewrite | 重写选中段落，多版本 | Mode 3 |
| Story Bible | 角色/世界/大纲数据库 | 类似 NovelCrafter Codex |
| Style Examples | 用你过去的写作样本训练 AI 模仿你的风格 | 接近沉积，但**只针对风格不针对内容/审美** |
| Visualize | 从描述生成插图 | 我们想做的视觉策展的反向 |
| Canvas | 思维导图式的创作空间 | 接近原型间联网，但是手动 |

**优势**：
- 品牌：写作 AI 第一梯队，文学小说作者的默认选项
- 模型：Muse 1.5 是为故事训练的，叙事质量公认领先
- 完整：从大纲到出版准备的全流程
- Style Examples 已经是简单沉积的萌芽

**劣势**：
- 入口默认是"我要写"，缺乏"我被触发"的上游
- 没有跨媒介输入（画/影/乐/史完全不存在）
- 沉积只到风格层，到不了"AI 越懂这个写作者的审美"层
- 文化偏 anglo——中文写作者用着像翻译腔

**威胁等级**：⭐⭐⭐⭐⭐ 最高。如果 Sudowrite 接入 Mem0 + 加跨媒介搜索，原型刺激器的核心命题就被吞掉了。**这是 18-24 个月窗口的来源**。

---

### A2. NovelCrafter ⭐⭐⭐

**官网**：https://www.novelcrafter.com/
**定价**：$11-20/月，BYOK（自带 API key）

**核心**：被称为 "AI 写作的 Photoshop"——高度可配置。

**特征**：
- **Codex**：结构化世界圣经。定义角色、地点、阵营、魔法体系、物种、物件。生成时 AI 读取 Codex 保持一致性
- **BYOK 模式**：你自己接 OpenAI/Claude/本地模型
- **场景级别细控**：每个场景的 AI prompt 可以精细配置
- **学习曲线陡**：上手要几周

**优势**：
- 多模型自由，避免锁定
- 长篇一致性管理强（这是 AI 写小说至今的难题）
- 可配置度让重度用户上瘾

**劣势**：
- BYOK 是技术门槛，文学读者抗拒
- 完全是"作者已坐下"的工具
- 缺乏跨媒介刺激
- 配置成本超过创作价值（对轻度用户）

**威胁等级**：⭐⭐⭐。同一群作者，但定位偏"工程师型作者"，跟"被触发型"用户基本不重合。

---

### A3. Type.ai ⭐⭐⭐

**官网**：https://type.ai/
**定价**：低，免费层比较慷慨

**核心**：Sudowrite/NovelCrafter 的低门槛替代品。

**特征**：
- 内置 GPT-5 和 Claude 4.5 Sonnet（不要 BYOK）
- 长上下文窗口
- 不强制建 Story Bible/Codex
- 主打"修订/打磨"，不是"从零生成"

**优势**：
- 上手快（几分钟 vs 几周）
- 跟现有手稿合得来——你可以贴一万字进去，它继续帮你打磨

**劣势**：
- 不沉积，每次回话从头开始
- 没有创作激发机制——你不知道要写什么时它救不了你

**威胁等级**：⭐⭐⭐。它的存在证明 Sudowrite 之外有"轻量化"的市场需求。我们也是轻量化方向，但入口不同。

---

### A4. Laterpress ⭐⭐

**官网**：https://www.laterpress.com/
**定价**：未公开

**核心**：故事结构（beats / 场景 / 大纲 / 世界观）就在写作环境里，直接驱动 AI 生成。

**特征**：
- 结构先行：先设大纲、再设场景节奏、再生成
- 一个"从想法到草稿场景"的工作流
- 不是 AI 优先，是结构优先 + AI 增强

**威胁等级**：⭐⭐。服务的是 D 类作者（建造型），跟 E 类完全不重合。

---

### A5. SidekickWriter ⭐⭐⭐

**官网**：https://www.sidekickwriter.com/
**定价**：未公开

**核心**：**genre-aware AI**——奇幻/科幻/惊悚/言情/悬疑/恐怖/文学/儿童文学有不同的 prompt 配置。

**特征**：
- 类型敏感：一个言情场景跟一个恐怖场景需要的节奏、措辞、张力完全不同
- 集成专业研究引擎，支持引文（罕见特性）
- 速度导向：1-2 小时一个章节

**优势**：
- 类型差异化是聪明的细分
- 研究引擎方向跟我们部分重合

**劣势**：
- 速度叙事跟严肃文学创作根本冲突
- "1-2 小时一个章节"对严肃作者是侮辱不是优势
- 还是"我要写"入口

**威胁等级**：⭐⭐⭐。研究引擎+类型敏感这两点要警惕。

---

### A6. NovelAI ⭐⭐

**官网**：https://novelai.net/
**定价**：$10-25/月

**核心**：自研 Kayra 模型；最少内容审查；偏 roleplay 文化。

**特征**：
- 完全自训练的模型（不依赖 OpenAI/Anthropic）
- Lorebook（类似 Codex）
- 几乎无内容过滤——黑暗/惊悚/性爱内容不会被屏蔽
- 用户群偏二次元/同人/genre fiction

**威胁等级**：⭐⭐。文化和审美跟严肃文学不在一个池子。但他们的开放性值得学习——文学经常需要写禁忌内容，过度审查会赶走严肃作者。

---

### A7. 其他

- **Raptor Write**（https://www.futurefictionacademy.com/）：免费 BYOK，Future Fiction Academy 出品。教学色彩浓
- **Inkfluence AI**（https://www.inkfluenceai.com/）：端到端——写章节 → 设计 KDP 封面 → 录制 ACX 有声书 → 导出 EPUB。纯生产线，与文学无关
- **Inkshift**（https://inkshift.io/）：成稿评估工具，不生成

## B. 灵感策展工具（精神最近）

### B1. Cosmos ⭐⭐⭐⭐ 灵魂最近的对手

**官网**：https://www.cosmos.so/
**定价**：免费 + Pro 订阅
**规模**：Apple's 25 Apps of 2025；月均 1000 万次保存

**核心**：AI 驱动的视觉策展平台。

**特征**：
- **Clusters**（不叫 boards）：自动语义聚类
- AI 标签 + 可手动调整
- AI 内容过滤：用户可以选择隐藏 AI 生成图片，保持"人类制造"纯度
- 收集：图片、视频、推文、文章、链接、引言全都能存
- 美学：克制、深色、安静——明显跟 Pinterest 的喧闹做区别

**为什么离我们近**：

1. "**策展即创作**"这个动作正在被市场验证
2. 用户群体高度重叠——文艺青年、设计师、严肃创作者
3. 已经做了一部分跨媒介
4. 排斥 AI 生成内容的洁癖——同一种对"机器水平输出"的反抗

**为什么没有威胁**：

1. **完全停在收集层**——没有进入"生产"
2. **视觉为主**——文学内容是配角
3. **AI 只做标签 + 搜索**——不做对话，不做沉积，不做创作激发

**未来威胁等级**：⭐⭐⭐⭐。如果 Cosmos 加上"AI 跟你讨论你的 cluster"+ "导出为创作起点"，就跟我们正面对撞。但他们的产品哲学是反 AI 介入的，所以可能不走这一步。

---

### B2. Are.na ⭐⭐⭐

**官网**：https://www.are.na/
**定价**：$5-7/月

**核心**：极简知识漫游网络，文字 + 链接为主。

**特征**：
- "Brutalist" UI：信息优先于美感
- 没有 AI，没有标签，纯手动组织
- Channels（频道）+ Blocks（块）的网络结构
- 用户群：严肃艺术家、思想型创作者、独立研究者
- 文化：反算法、反推荐、反 viral

**为什么有借鉴价值**：

1. 用户群跟我们目标重合度最高——严肃创作者
2. 极简 UI 哲学——这种用户讨厌花哨
3. "缓慢、深度"的节奏感

**为什么没有威胁**：

1. **完全没有 AI**——他们价值观上反对
2. **没有进入生产层**——是图书馆不是工坊
3. **付费墙限制规模**

**借鉴启发**：原型刺激器的 UI 美学应该向 Are.na 靠（克制、信息优先），不向 Sudowrite 靠（花哨、功能堆叠）。

### B3. Savee ⭐⭐

**官网**：https://savee.it/

类 Cosmos，更偏纯视觉。可以快速浏览，建集。AI 描述但没有 AI 策展。

**威胁等级**：⭐⭐。视觉路线，不进入文学。

---

### B4. Pinterest

不在同一文化层。大众消费产品，跟我们目标用户审美冲突。

## C. AI 记忆框架（基础设施）

这一块**不是直接竞品**，是**我们可以使用的基础设施**。

行业把 2026 称为 **"Year of Context"**，2027 称为 **"Year of Coherence"**。AI agent memory 市场：$6.27B（2025）→ $28.45B（5 年内），CAGR 35%。

### C1. Mem0 ⭐ 候选基础设施

**官网**：https://mem0.ai/
**类型**：开源 + 云服务

- Drop-in 个性化记忆，社区规模大
- 适合做"知道用户偏好"这一层
- 但**不针对 artifact-centric**——它存的是 user facts，不是 work-in-progress

**用法**：可以做用户层的偏好记忆（"她喜欢 Anne Carson 那种诗学"）。

---

### C2. Zep / Graphiti ⭐⭐ 候选基础设施

**官网**：https://www.getzep.com/
**核心**：时间推理强，知识图谱底层。LongMemEval 评测高 15 分。

- 适合做时间序列的认知（"她三个月前关心的是 A，现在转到 B"）
- 知识图谱能跨原型建立关系
- 工程接入难度比 Mem0 高一档

---

### C3. AI Context Flow

跨平台通用记忆扩展，浏览器插件形态。适合让用户的偏好在不同 AI 工具间互通——但跟我们的"作品中心"理念正交。

---

### C4. Supermemory, MemSync, Memory Plugin

各家不同切入点。短期不必深究，等 MVP 上线后再选基础设施。

---

### 行业关键判断（直接引用）

> "memory captures preferences — not decisions, artifacts, or reasoning chains. Memory captures preferences — not decisions, artifacts, or reasoning chains."

来自 2026 行业分析。这句话**正中我们的方向**——已经有人在认识到"用户偏好"和"作品本身"是两个不同的持久层。

**意味着**：
- 好消息：我们不用从零造记忆引擎，可以站在 Mem0/Zep 肩膀上
- 坏消息：等基础设施成熟，**Sudowrite 接上 Mem0 就是我们的直接竞品**

# Part 3：空白带分析

## 三张地图叠在一起

```
   AI 写作工具         灵感策展        AI 记忆框架
   (Sudowrite 等)     (Cosmos 等)     (Mem0 等)
       ↓                  ↓               ↓
    会生成              会收集          会记忆
    不喂养              不连接生产       通用，不针对创作
    不策展              不进入对话       
        \              |              /
         \             |             /
          \            |            /
           ↓           ↓           ↓
        ╔═══════════════════════════════╗
        ║  我们的位置                    ║
        ║                              ║
        ║  入口：我刚被某个东西打到       ║
        ║  动作：策展 → 对话 → 沉积       ║
        ║  根：作品本身（artifact）       ║
        ║                              ║
        ║  跟 A 不同：上游入口            ║
        ║  跟 B 不同：进入生产闭环         ║
        ║  跟 C 不同：垂直创作场景         ║
        ╚═══════════════════════════════╝
```

## 这个空白带是真的

每一个邻近产品都有自己的位置约束让它进不来：

- **Sudowrite** 入口是"坐下来写"，要改成"被触发"需要重做产品哲学
- **Cosmos** 已经表态反 AI 介入，路径锁死在策展，进不到生产
- **Are.na** 价值观反对算法/AI
- **NovelCrafter** 工程师导向，跟"被触发型"作者文化冲突
- **Mem0/Zep** 是基础设施，没法直接面向写作者

我们能站的位置不是因为别人没想到，是因为**别人的存量产品决定了他们走不到这里**。

# Part 4：定位策略（重要修正）

**严肃文学是 anchor，不是 ceiling。**

这是 Apple / Substack / Are.na 的模式：

| 案例 | Anchor 用户 | Mass 用户 | 关系 |
|------|----------|-----------|------|
| Apple | 设计师、创作者 | 普通消费者 | "用专业工具的感觉" |
| Substack | 严肃 essayist、记者 | 一般 newsletter 作者 | "我和严肃作者用同一个平台" |
| Are.na | 独立艺术家、研究者 | 文艺青年 | "我在严肃创作者的圈子里" |

**原型刺激器的分层**：

| 层 | 目标群 | 他们用什么 | 为什么愿意付费 |
|----|----|---------|----------|
| **核心（Anchor）** | 严肃文学/诗歌作者、MFA 学生 | 全功能，深度定制，品味策展 | 策展品味独一无二，"this gets me" |
| **创作型** | 类型小说作者、爱好者、内容创作者 | 同产品，轻引导 | 漂亮的灵感流，触发感强 |
| **邻近创作** | 编剧、文案、设计师、记者 | 同引擎，不同入口 | 跨领域创意激发 |
| **学习/研究** | MFA 项目、写作老师、研究者 | 教育许可 | 帮学生探索文学传统 |

**策略**：
1. **品牌由 Anchor 定义**——所有营销、UI、内容选择都以严肃作者为标准
2. **产品给 Anchor 全功能，给 Mass 简化版**——共用引擎，差异在引导和默认值
3. **Anchor 不付费养 Mass 付费**——这是 Are.na 的死法，避免
4. **Anchor 是 quality signal，Mass 是 volume**——两个收入都要

# Part 5：风险

## 5.1 时间窗口

**Sudowrite + Mem0 = 24 个月后的我们。** 任何当前竞品都能走这条路径，只是他们的存量产品惯性让他们慢。

**对策**：
- 18 个月内让早期用户**养出可观的沉积**——这是切换成本，是护城河
- 不要试图功能上跑赢 Sudowrite，赢不了
- 赢在**入口设计**和**情绪定位**

---

## 5.2 市场规模

2025 Author Guild 调查：45% 已发表小说家用 AI，但**绝大多数是 genre fiction**。

严肃文学全球付费用户基数估算：**5 万-15 万人**。

按 $15/月 ARPU 算：年收入上限 $9M-$27M。

**对策**：anchor + mass 分层。严肃文学不可能撑起独立公司，必须借品牌势能扩出去。

---

## 5.3 跨媒介数据成本

文字搜索 vs 图像/影视/音乐 vs 历史专业数据库——**成本差 10-100 倍**。

**对策**：
- MVP 阶段只做文字 + 公共 API 的图像
- 影视/音乐用元数据 + 链接（不存内容）
- 历史用 Wikipedia，付费数据库（JSTOR 等）后期接入

---

## 5.4 冷启动死亡谷

沉积型产品的特性：**长期价值在第二年才显现，但用户第一周就走**。

**对策**：
- 第一次使用就要给"足够触发"的体验（这是策展质量的考验）
- 第一周内塞进去几个"假装是你过去写的"原型让用户感受沉积的样子
- 第一个月内每周一次"你最近的模式"邮件，强制让用户感受到累积

---

## 5.5 严肃作者的传统抗拒

文学圈对 AI 普遍抗拒，部分作者把"使用 AI"当道德污点。

**对策**：
- 强调"策展和对话"不是"代写"——Mode 3 严格隔离
- 邀请严肃作者参与设计，给他们 thought leadership 位置
- 文化产品不只是工具，是身份——让用 ProtoSpark（暂名）成为"严肃但开放"的身份信号

# Part 6：开放问题清单

技术层：

1. 跨媒介搜索的查询构造怎么做（最难的工程问题）
2. 沉积摘要的格式和触发时机
3. 用 Mem0 还是自己搭记忆层
4. 数据存哪——独立 DB 还是跟 Obsidian 集成

产品层：

5. 命名（"原型刺激器"是描述，不是品牌名）
6. Mode 3 的视觉隔离怎么做——既保留功能又不污染主区
7. 第一周的引导剧本设计
8. 跨媒介的优先级——文字之后先加图像还是先加电影

商业层：

9. 定价策略：核心 + Mass 两层 vs 单一定价
10. 早期 alpha 用户从哪里来（Are.na 社区？小红书严肃文学？MFA 圈？）
