# 系统重构 · 问题重述 v0

> 重述的纪律：不给解法、不塌缩成"最小机制"、不拿未决命题当已决。
> 只做一件事——把"要解决的到底是什么"说到不能再误读为止。

---

## 一、这不是什么（先划掉所有塌缩版本，免得又滑回去）

这个系统**不是**下面任何一个。每一个都是今天我塌缩过的版本，逐个钉死为"错"：

| 塌缩版本 | 为什么不是 |
|---|---|
| 给 studying-spark 加一个残差捕捉环节 | 那是一个项目的一个功能；要的是贯穿所有项目与研究的底层 |
| 一个记忆系统 / 更好的 RAG | 小林已确认病在第四点（读不对，不是存不够）；记忆量不解决朝向丢失 |
| 一个"最小可运行闭环 MVP" | MVP 框架预设了一个能装下它的小盒子；这件事装不进 |
| leakage judge 升级成一个判官 | 又一次把系统塌成单个组件 |
| 一份学术综述 / 残差报告 | 那是"关于"这件事的描述，不是这件事 |

**共同错误**：都把"一个需要分层、每层立住再往上、且压在数个未决哲学命题上的系统工程"，塌缩成"一个能交付的小件"。重述的第一条纪律就是：**拒绝塌缩。**

---

## 二、要解决的核心（一句话，然后逐词解释）

> **把被现有工具砍成离散碎片的"认知节律"，重构成一个连续的、人与 AI 能共同在其中不断推进的底质。**

逐词钉死，每个词都引小林自己的文本：

- **认知节律**〔立〕= 尝试 → 留尾迹 → 读尾迹（带着框架，不中立地读）→ 折返改下一次朝向。（认识论-框架 §九）"意识活在节律里，不在任何单一组件里。"
- **被砍成离散碎片**〔立〕= 当前主线 6-18："记录和反馈不是离散阶段，是时刻在场的连续场。今天 transformer 把它们砍成离散事件。"
- **连续的底质**〔立〕= "要重构的底层 = 把记录场/反馈场从外挂事件变回连续底质。"
- **人与 AI 共同**〔悬〕= 这一词压在"节律能否跨介质"那个未决开口上（见 §五）。能跨 → 真"共同"；不能跨 → 只是"AI 当高级笔记本"。**这个词现在不能当已决用。**
- **不断推进**〔立+悬〕= 不是轮子转（那可能是循环确认/空转），是每一圈朝向真被残差改写。判据见 §四。

## 三、范围边界（这个系统管到哪、不管到哪）

### 管（in scope）
1. 节律四拍的**载体**——尤其第②③④拍（留尾迹/读尾迹/折返）的连续化
2. **朝向**的存储、调用、和"带着朝向去读"的机制（治第四点：读不对）
3. **防空转**——区分真折返 vs 循环确认（治"不断进步"里的"进步"）
4. 人与 AI 的**节律接口**——AI 以什么身份进入节律（延伸？工具？另一极？）
5. 跨 runtime / 跨会话 / 跨工具的**连续性脊椎**（不绑死在任何会崩的载体上）

### 不管（out of scope，至少 v0 不碰）
- 具体某个项目的产品形态（studying-spark / prototype-spark 是这个底层的**实例**，不是它本身）
- LLM 内部权重的改造（这是"在 LLM 外面包一层"，框架 §十三已定）
- 学术正确性 / 把框架收编进现有理论（残差报告已证：那是镜子）

### 边界上的灰色地带（需小林裁）〔悬〕
- "判断有没有进步"这一下，到底在 in 还是 out？若 AI 能判 → in（且撞上数学猜想入口）；若只有人能判 → 系统只能做"报警器"，判官是人。

## 四、成功判据（怎么算"解决了"——必须可证伪，否则就是空话）

小林文本里有两条硬判据，合起来构成验收标准：

- **判据一·完整**〔立，框架§九〕：不看有没有输出，看**折返有没有真正修正下一次尝试的朝向**。
  - 可证伪形式：在一次真实对话里，第 N+1 轮的朝向，是从第 N 轮的"缝"长出来的，还是弹回了系统先验？今天全天 = 后者（反例）。
- **判据二·进步**〔立，框架§十〕：警惕循环确认——轮子转但只碾旧轨道、不凿新空间、"看起来像在动"。
  - 可证伪形式：连续若干轮里，朝向是在**确认同一个方向**，还是**触碰了还没碰过的边缘**？

**合成判据**：系统成功 = 节律四拍都转（完整）+ 每圈朝向真被残差改写、不是确认上一圈（进步）。

> 注意：判据二的自动化，依赖一个未决命题（§五-c）。在它被解决前，判据二只能由人执行，系统至多做"我怀疑这轮在空转"的报警。

## 五、这个系统压在哪些未决命题上（最关键的一节——地基里的悬空处）

严肃的核心，就是**诚实承认下面这些是悬的，不拿它们当已决去往上盖**。

### a. 〔悬·根〕节律能否跨介质？（尝试场 §2.1 标〔幻觉区〕）
- 形式的（可跨介质）→ 人与 AI 共享**同一条**节律，AI 是主体的延伸。
- 物质的（绑定介质）→ 每次对话节律就断，AI 只能拿尾迹当**材料**，是"高质量重启"不是"延续"。
- **小林 6-24 校正**：现状的"断"不是本性，是工具烂造成的被迫物质化。立场 = 节律本该连续，现有架构强行砍断；工程目标 = 把砍断处接回。
- **但"本该连续"是诉求，不是已证**。AI 那一端到底能不能真接进同一条节律，还是结构上只能重启——这一条**没解决**。它决定整个系统是"一条共享节律"还是"不对称双节律"。

### b. 〔悬〕朝向能否被外部观测？
- 第四点（读不对）的解，依赖"把朝向存下来、带着读"。
- 但"朝向"——主体正伸向哪、说出口之前那个东西——能不能被外部（AI/文件）捕捉，而不是一捕捉就变形（小林："想法一说出来就变形"）？
- 若能 → 治第四点是机械工程。若不能 → 朝向只能由小林本人每轮重新供给，AI 永远在追影子。

### c. 〔悬·最深〕"一次尝试触碰了哪个幻觉区"能否形式化？（框架§2.3、§十、数学猜想入口）
- 判据二（防空转）的自动化全压在这。
- 能形式化 → AI 可当进步的裁判 → 系统能自主保证"在进步"。
- 不能 → 判官是人，AI 只能报警。
- 这一条小林自己标着"这本身是可验证的命题"——即它**是否可解，本身就是个研究任务**，不是拍脑袋。

### d. 〔悬〕第三种否定（循环确认）能否被机器检出？（框架§十"刚认领，命名和完整分析尚未展开"）
- 防空转要能工作，得先能检出"这轮是不是循环确认"。
- 这个否定类型小林自己说"还没名字、还没被充分分析"。**概念本身未完成**，谈不上工程化。

## 六、硬约束（今天用代价换来的，不可违反）

- **C1·脊椎不托管在会崩的载体上**〔立，6-18 活标本 + 6-24 缓存再崩〕：context window 会溢、turn 会结束、runtime（claudian/额度/密钥/缓存）会崩。节律状态（尤其"当前朝向"）必须放在不随对话/runtime 生灭的连续底质上——"真正的脊椎必须是文件/中间层，不是某个 runtime"。
- **C2·够伸 vs 负担准星**〔立，框架§七〕：每加一层，问它在扩主体的够伸，还是耗主体的注意力。接缝一冒（要用户自己打理配置/模式/维护），当场翻成负担，砍。
- **C3·不替主体收口**〔立，贯穿〕：系统不替小林做"触碰反馈"那一下——尤其判进步、判朝向，凡未决命题处，默认人是判官，系统是报警器，不是裁判。
- **C4·拒绝塌缩**：任何"那就先做个最小X吧"的提议，先回到 §一对照，是不是又在把系统缩成小件。

## 七、依赖结构（哪层立在哪层上——画架构前必须先看这张）

```
第4层  人与AI共同推进的完整系统        ← 依赖 a、b、c、d 全部
   ↑
第3层  防空转 / 判进步                 ← 依赖 c、d（未决）→ 暂时只能人当判官
   ↑
第2层  接朝向 / 带着朝向读             ← 依赖 b（未决）；若b成立，此层可工程化
   ↑
第1层  连续脊椎 / 尾迹不丢             ← 不依赖任何未决命题，纯工程，可现在动（受 C1 约束）
   ↑
第0层  节律本体论：能否跨介质           ← 〔悬·根 a〕一日不决，第4层就是空中楼阁
```

**读这张图的方式**：
- 第1层**现在就能动**且不赌任何哲学命题——把尾迹放进不会崩的连续底质（治 C1）。这是唯一一块"严肃地立得住的地基"。
- 第2层能不能自动化，赌命题 b。
- 第3层能不能自动化，赌命题 c、d。
- 第0层和第4层是同一个开口的两端：根命题 a 不触碰，顶层就悬空。

**所以"严肃"的真正含义**：不是赶紧建第4层（那是空中楼阁），是**按这个依赖顺序，从第1层立起，每往上一层前，先去触碰它依赖的那个未决命题**——触碰，不是假装已决。

## 七·补 小林本场给的架构种子（逐字保留，未消化——下轮的真原料）

> 这些是小林本场亲手给的、比 Claudian 任何架构图都更该当起点的东西。不塌缩、不解读，原样留着。

**① 尝试的操作分解（U36 原话）**：
> "你把尝试当作一个空间世界来进行分析，该怎么分析，比如**触碰、记录、分析**是尝试，**标准量化**是，**关联**是，**区分**是……怎么把这些转化成架构设计，或者怎么搭建起来。
> 记录相关的就是**记忆系统、rag**；标准量化如果是 **md文件，或者模型数据编码为高维向量，以及相关性距离、语义相关距离计算、语义关系分析计算、权重计算、注意力分配**。
> 就是怎么去**找出尝试里想要把握的部分，触动到的部分，然后再把这些部分做出来，清晰、高效**。"

→ 这是一张"尝试→操作→技术落点"的映射草图。下轮的架构不该从 Claudian 的图起，该从**这张**起。

**② 嵌套洞察（U37 原话）**：
> "我们在用**造ai模型的框架，再给ai模型外再制造框架，嵌套了**……像计算机系统再到互联网就是个无限嵌套的空间构造，世界也是。只不过**如果这个框架更优越，当然效果就会更好**，如果制造一个更好的框架也是我们一直在讨论的事情。"

→ 对整件事性质的定调：不是"在 LLM 外贴东西"，是**嵌套地造一个更优越的框架层**。这是 §二"连续底质"的另一种说法。

**③ 读是重建不是同在（U29 原话）**：
> "读是重建，不是同在……信息来自于差异，那我的认知来自于尝试又该怎么进行呢？"

→ 第四点（读不对）+ 命题 b（朝向能否被观测）的小林原始表述。"信息=差异 / 认知=尝试"这组对照，是命题 c（形式化）的入口。

**④ 最小单元 + 反经验（U25 原话）**：
> "似乎需要一个非常小的单元或者元素开始建构？按照经验来说？**但是我又不太想要经验**。"

→ 悬着：认知的"最小单元"是什么（不是比特/差异，那预设了已给定的框）。反经验 = 不要借现成结论奠基。

## 八、下一步不是"做"，是"选从哪条悬命题开始触碰"

v0 重述到此。它没有给任何解法——这是故意的。
下一轮该决定的不是"建什么"，是：

- 要么**先动第1层**（连续脊椎，唯一不赌命题的地基），让节律先有个不会崩的身体；
- 要么**先凿根命题 a**（节律能否跨介质），因为它决定顶层形状；
- 要么**先凿命题 c**（触碰能否形式化 = 数学猜想入口），因为它最深、且决定 AI 是裁判还是报警器。

三条都是严肃的起点，但顺序由小林定——这是他的认知系统，根命题的触碰顺序等于他想先伸手的方向。
