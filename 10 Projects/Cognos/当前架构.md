# Cognos：当前架构

> 本文件记录 Cognos 的当前工程投影。它可以被现实回撞后改写，不是认识论的最终形式。

## 已采用骨架

- 技术栈：Python + FastAPI + SQLite + 纯 HTML/JS。
- 运行形态：本地优先 Web 应用。
- 核心对象：`Space`、`EntityObject`、`ObjectInSpace`、`Relation`、`Movement`。
- 历史原则：运动/事件只追加，不覆盖既有历史。

## 数据模型

### Space

承载对象共存及关系显现的空间。空间不是被动容器；同一对象进入不同空间，可以显现不同关系。

### EntityObject

统一表示人、AI、概念、项目、关系、历史或数学结构。`type` 开放，不把主体预设成人和 AI。

当前主体化实验梯度：

| subject_level | 含义 |
|---|---|
| 0 | 普通对象：刚被指认 |
| 1 | 可展开对象：有未展开部分 |
| 2 | 候选主体：有历史、有关系、能牵引讨论 |
| 3 | 活跃主体：能进入沟通、被调度并产生影响 |
| 4 | 组织器官：承担持续功能 |

这五级是 Cognos 当前工程假设，不上升为跨 runtime 的主体定义。

### ObjectInSpace

记录对象在哪个空间中共存，使对象与空间成为多对多关系。

### Relation

- 必须依附空间：`space_id` 为强约束。
- 参与者至少两个，但关系本身也可主体化。
- `effect` 不是说明文字：活关系要能改变后续检索、上下文或行动。
- 类型开放，不能先穷举完整关系列表。

### Movement

记录消息、判断、尝试、调度、落地、纠正、共识、残余、学习等运动。当前原则是追加式，不把这些类型宣称为最终最小单位。

## Context Builder

当前采用三层，而不是机械拼接整本手册：

1. **常驻层**：极短的项目定位、压缩防线、当前参与者/位置。
2. **情境层**：当前空间目的、活对象、活关系、开放残余、当前调度。
3. **动态检索层**：根据这次行动按需取历史、纠正、来源和相关空间。

每次调用应保存上下文快照或来源清单，使“没找到 / 没注入 / 模型忽略”可以被区分。

## 数据权威关系（待运行验证）

`〔Codex 2026-08-13 架构整理建议；尚待真实运行确认〕`

| 载体 | 建议地位 | 原因 |
|---|---|---|
| JSONL 事件流 | 运行历史真相源 | 追加式、可 diff、能重放 |
| SQLite | 可重建运行索引 | 服务查询和 UI，不成为隐藏的唯一真相 |
| Markdown | 人类可读投影与确认面 | 适合审阅、链接和 Git，不与事件流竞争事件真相 |

如果三者都可独立改写同一事实，“双写”会变成三份互相漂移的活源。Phase 1 必须通过重建测试确认这张权威关系。
