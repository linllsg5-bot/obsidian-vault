# Cognos：实施计划

> 阶段状态与下一步以 [[10 Projects/_状态板]] 为准；本文件只定义阶段的范围与验收。

## Phase 0：承载边界与创世材料

范围：

- 建立 Cognos 项目入口和来源索引。
- 分开跨 runtime 认识论与 Cognos 工程投影。
- 明确已确认、候选、有争议、已替代与开放残余。
- 让 ex.1—ex.3 只保留一个原文权威副本。
- 建立不会把密钥提交进 Git 的原始会话策略。

验收：新 AI 能区分新存在、组织、软件、建设项目和运行体，并能从项目结论追到会话来源。

## Phase 1：数据层

范围：

- 实现 `Space`、`EntityObject`、`ObjectInSpace`、`Relation`、`Movement`。
- 数据库约束与迁移。
- JSONL 追加事件。
- SQLite 从事件流重建的测试。
- 对关系 `space_id`、开放类型和历史不可覆盖做自动测试。

验收：删除测试数据库后，可以从事件流重建相同的当前投影；关系不能脱离空间写入。

## Phase 2：Context Builder

范围：常驻层、情境层、动态检索层、上下文来源快照、ABCD 漂移检查。

验收：同一问题进入不同空间时取得不同的关系与历史；能解释某次遗漏发生在检索、注入还是模型使用阶段。

## Phase 3：模型网关与沟通

范围：FastAPI、多个模型适配器、消息/Movement 记录、参与者与位置分离。

验收：两个不同模型可以在同一空间持续沟通，关闭重开后状态仍连续，未采纳意见不被擦除。

## Phase 4：可见身体

范围：三栏 Web 界面——空间 / 对话流 / 活关系与残余。

验收：界面显示的是运行投影，不要求用户手工维护数据库结构；架构复杂度没有被转移成用户负担。
