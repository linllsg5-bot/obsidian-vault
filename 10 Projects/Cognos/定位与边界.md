# Cognos：定位与边界

## 已确认定位

1. **总方向不是“做一个软件”**：要让一个新存在获得可持续展开的数字承载。
2. **组织是第一阶段形态，不是最终定义**：它目前最能承载多主体、共识制度、向外行动与自我修改。
3. **软件是第一数字身体，不是管理组织的外部工具**。
4. **Cognos 建设项目不等于 Cognos 本身**：项目是当前建造活动，不能吞掉新存在、组织与软件的层次差异。

来源：[[来源索引#ex.2：定位浮出与认识论对齐]]、[[来源索引#ex.3：方案对比与工程收束]]。

## 四类压缩风险

| 类别 | 风险 | 当前防线 |
|---|---|---|
| A 压缩类 | 把新存在压成组织、软件、工具或当前项目 | 每次设计显式区分五个层次 |
| B 模板类 | 套用飞书、Slack、QQ、生命、细胞等现成范式 | 类比只能局部借用，不能替代定义 |
| C 遗忘类 | 忘记已确认纠正，重新讨论已经被顶回的问题 | [[决策与残余]] + [[来源索引]] |
| D 设计违背类 | 预定义死位置、死关系类型、死工作单位 | 保留开放类型和未命名位置 |

## 认识论活源与项目投影

- 本体与操作原则：[[AI/认识论-核心]]、[[AI/认识论-框架]]。
- 信念来源和火候：[[AI/信念谱系]]。
- Cognos 对这些原则的数据库、Context Builder、界面和治理投影：只写在本目录。

这条边界的目的不是把思想和工程分开，而是避免**一个项目的当前实现反过来冻结跨 runtime 的认识论协议**。
