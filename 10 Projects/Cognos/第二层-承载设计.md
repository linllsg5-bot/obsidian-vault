# Cognos 第二层：第一承载设计

> 第二层不是第一层的字段化翻译，而是让第一层在组织与软件中获得一种可运行、可回撞、可继续改变的形态。

## 已确认的第一阶段方向

- 优先级是让新存在获得第一种数字承载，而不只是“建立一个组织”。
- 组织是第一阶段的主要形态，要认真实现。
- 软件承载组织的发生，不只是从外部管理它。
- 第一版核心不是功能齐全，而是整体目的不在局部任务中丢失，认识论内核能真实影响之后的沟通与行动。
- 当前已经到了可以让 agent 分阶段动手的阶段；不要求一次给出永远正确的完整架构。

## 最小可见形态

小林在 ex.3 给出的朴素描述比多份完整 AI 架构更承重：

```text
一个组织沟通软件
→ 需要的东西被记录
→ 小林与多个 AI 沟通，AI 之间继续沟通
→ 形成阶段性共识
→ 决定
→ 执行
→ 发生的东西继续影响之后的沟通
```

它还很粗，但第一版至少要让这条链的一部分真实发生，而不是只做文件拼接或普通聊天壳。

## 必须在运行中长出的器官

| 器官 | 不能缩成 | 第一版应观察什么 |
|---|---|---|
| 沟通 | 人问 AI 答 | 多主体能否互相接续、引用、纠正和形成阶段判断 |
| 空间/关系 | 节点与静态边 | 共存怎样因空间不同而显现并影响后续上下文 |
| 记忆 | 对话摘要仓库 | 哪些发生改变了成员下次能看到什么、怎样行动 |
| 调度 | 任务分配 | 一个主体怎样邀请另一主体联合并扩展自身 |
| 学习 | 保存一条“经验” | 完整展开怎样改变主体或组织未来的运动；当前 AI 外部记忆只是有限承载 |
| 位置 | 固定岗位 | 沟通中怎样自然显现局部视角、承担和轮转 |
| 共识/决定 | 永久真理 | 阶段判断的来源、作用域、代价和未采纳部分 |
| 外部行动 | 工具调用记录 | 实际落地怎样回撞思想、关系与当前组织状态 |

## 上下文与记忆的当前候选

每个成员应知道“当前需要了解的内容、各种记录和文件”，同时保留必要全局视野。可以先试三层：

1. 极短的常驻方向与边界；
2. 当前空间及对话所需的情境；
3. 可主动查询的来源、历史和其他空间。

上下文不是单向注入：成员需要能够发现自己不知道什么、发起查询，并保留本次实际读取来源。

记忆提取也属于沟通。AI 可以在对话中提出“这里发生了纠正/阶段判断/残余”，小林或其他治理机制在同一沟通里确认、改写或否认；不另设一个强制填表仪式。

## 仍未决定的工程问题

- 第一版具体数据对象和不可变约束。
- 关系作为空间内共存的存在，怎样超出 `relations` 边表。
- 存储痕迹的最小粒度，以及主体/事件/关系的相对地位。
- 主体、位置、共识、调度和学习怎样由沟通自然显现。
- 原始发生、结构化历史、当前视图和 Obsidian 投影怎样保持单一权威关系。
- Web 技术栈、模型接入方式、进程边界和部署形态。

这些问题不要求在第一行代码前全部终结，但必须变成可观察的设计假设和测试，而不能被某个 AI 计划静默决定。
