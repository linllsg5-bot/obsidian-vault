## 阶段采用

| 内容 | 为什么可先试 | 重新打开条件 |
|---|---|---|
| 常驻 / 空间 / 对话与查询的三层上下文 | 小林评价“这个上下文设计还可以” | 历史重放仍丢目的，或上下文负担过重 |
| 先做最小沟通竖切，再由运行长出关系、位置和学习的细节 | 符合“先做雏形后续继续” | 竖切必须依赖更早的数据/关系约束才不变形 |
| 对原始发生追加记录、保留未采纳意见 | 多轮对话一致支持不可覆盖历史 | 实际运行证明追加模型不足以表达修正和状态 |
| 先接 Codex，不使用模型 API Key | 小林 2026-08-13 明确选择并认可新实施顺序 | ChatGPT 登录或 thread 恢复在真实验收中不可用 |
| `subject_level` 若试验则放在 `ObjectInSpace` | 主体化可能依赖对象所在空间；是工程推断，不是本体定案 | 真实运行显示主体化是跨空间稳定属性 |
| 关系优先试验 `Relation + RelationMember` | 空间内共存不天然是二元有向边；是工程推断 | 真实关系全部表现为严格二元且方向性不可约 |
| 把新的认识先带回现有实现内部折返 | 2026-08-13 小林要求继续实现，并明确不要把本轮推进只收成新材料或 `ContextSnapshot` 需求 | 现实证明现有实现尚无可被检验的承载点 |

## 候选，尚未确认

| 候选 | 当前处理 |
|---|---|
| `Space / EntityObject / ObjectInSpace / Relation / Movement` | 作为可测试数据投影，不称“当前采用骨架” |
| 0—4 `subject_level` | 降为实验视图，不先写进不可逆核心契约 |
| JSONL / SQLite / Markdown 三载体权威关系 | 做技术 spike 和重建测试后再决定 |
| Python / FastAPI / SQLite / HTML/JS 等技术栈 | 根据 Web 竖切、agent 可维护性和本地数据要求选择 |
| AI 在对话中提议纠正/残余、用户确认 | 可做交互实验，不把“用户确认”永远定为唯一治理机制 |
| 概念、项目、关系、历史作为主动主体 | 保留到后续阶段，先不模拟成会说话的对象 |
| 完整数据模型先于运行时和上下文落地 | 旧试作冻结；先完成 Codex 接入与上下文回放，再决定表结构 |
| `ContextSnapshot` 的具体形态 | 只可能是某一时刻的读取视图；本轮不预列 raw / interpretation / genealogy 等固定区块 |
| `H` 不变而 `Mₜ(H)` 可变；发生历史与认识历史分离 | 已用于 Vault 归档试验；作为软件模型仍待验证 |
| schema 是判断/透支；稳定是结构可变而连续性不断 | GPT 推演，有解释力但未获小林逐项确认 |

## 已否决或已替代

| 提案 | 为什么被顶回 | 仍可保留的部分 |
|---|---|---|
| 四文件 + CLI 机械拼 Prompt | 小林明确评价“非常烂”；没有分层、检索与真实组织运行 | 极短的常驻目的防线 |
| 固定四层/五层软件架构 | 没有从第一层自然长出 | 模块名可作为检查清单，不作为生成关系 |
| 事件是全系统最小单位 | 理由不足；事件更像记录形式 | 追加式事件可作为存储候选 |
| “展开”是统一工作单位 | 词义过宽，容易把不同尺度压平 | 展开仍是第一层运动，不强制变成表 |
| 预设固定 AI 岗位 | 位置应在沟通中显现和轮转 | 位置作为局部视野/当前承担仍保留 |
| 关系只是有类型、作用域和 effect 的边 | 仍未理解“空间内共存” | `effect` 可作为关系显现的一种工程实验 |
| “张力”作为系统原语 | 是 AI 借来的含混词，混合问题、可能、主体感受和残余 | 直接写开放问题/未展开可能/残余 |
| 把数学探针当普通解题 | 丢失它同时检验思想、组织与承载的目的 | 数学内容本身仍应认真研究 |
| 把本轮认识折返收束成 `ContextSnapshot` 需求 | 它会把 schema、主体边界、历史重读与自指等更大问题重新塞进一个现有组件 | `ContextSnapshot` 以后仍可作为当时视图，在真实回放后再长出 |

## 关键开放残余

- 第一层怎样真正生成第二层，而不是用原语给普通软件改名？
- 关系依附空间，在数据与交互里到底产生什么不可替代的行为差异？
- 什么在什么尺度下成为不可忽视的单位；谁能决定或组成什么？
- 记忆怎样成为主体/组织的改变，而不仅是让下一次模型多读一段文字？
- 位置、调度、共识和治理怎样从真实沟通显现，又不完全依赖小林逐项批准？
- 世界追问与承载尝试怎样互相校正，而不让某一边永久关闭另一边？
- 原始历史、当前视图和运行数据怎样保持可追溯，又不制造多个活源？
- 原始会话中的敏感信息怎样在公开 Git 历史中完成真正收口？
- schema 自身、主体边界和世界映射怎样能够随认识展开，同时仍足以支持软件运行与迁移？
- 同一原始发生被后续重新认识时，旧解释、新解释与尚未决定怎样共存，而不先固定成一套“展开性记忆”字段？
- 当前结构连缺少什么维度都不知道时，软件怎样诚实保留建模失败，而不把空无重新实体化？
