## 当前战役：阶段采用

| 内容 | 为什么现在采用 | 重新打开条件 |
|---|---|---|
| 第一组织切片作为当前主工程 | 当前 Web 仍是 `assistant slot + runtime switch`；组织尚未获得多个持续 participant 共在这一最小事实 | 真实实现证明 participant/runtime 分离不是当前关键断裂，或更前置结构无法绕开 |
| participant 先作为稳定工程身份锚点，与 runtime/model 分离 | 能在不定义主体本体的前提下验证多个 continuity 共存 | 真实运行显示 participant 身份无法独立于 runtime，或同一 participant 跨 runtime 的假设无意义 |
| 每个 participant 保持自己的 runtime continuity | 防止“切换模型 = 替换参与者” | 运行显示某类参与者不需要 runtime continuity，或 continuity 的单位另有其物 |
| 显式让一个 participant 面对另一个 occurrence | 最小跨参与者接续，不伪造共享历史 | 真实运行需要更强的 Reach/Position/Relation 机制才能表达 |
| 第一组织切片之后默认进入第一个真实组织闭环 | 组织必须从聊天走向判断→决定→执行→现实反馈→继续 | 切片本身暴露更基础断裂，必须先补 |
| 大地图 / 当前战役 / 局部探针三尺度维护 | 防止长项目因局部实验失去方向感 | 若实际维护成本过重或三层不能覆盖真实节律再重开 |

## 候选，尚未确认

| 候选 | 当前处理 |
|---|---|
| `Space / EntityObject / ObjectInSpace / Relation / Movement` | 旧数据投影；不称当前采用骨架 |
| 0—4 `subject_level` | 实验视图；不写入不可逆核心契约 |
| `Relation + RelationMember` | 比二元边开放，但没有真实关系实验支撑 |
| participant = subject | 未确认；participant 当前只作工程身份锚点 |
| Position / View / Reach / Influence / Field | 8/14 后已形成一组重要候选区分，仍需真实运行产生不可替代行为差异 |
| `NotRecognized ≠ NotEffective` | 有解释力的候选原则；尚需持续世界实验 |
| `WorldChange → EffectPropagation → World/PositionChange → SubjectReentry → View` | 持续世界候选运动，不实现成固定 state machine |
| `ActiveCognition(S)=0` 但 situated/relational existence 仍持续 | 强候选，需要真实休眠/重入与世界变化实验 |
| H 不变而 `Mₜ(H)` 可变；发生历史与认识历史分离 | 已用于 Vault 归档，作为软件模型仍需继续验证 |
| schema 是判断/透支；稳定是结构可变而连续性不断 | GPT 推演，有解释力，未获逐项确认 |
| schema 不只漏现实，也会制造错误对象 | 有 ex.1 真实样本；一般机制仍待验证 |
| 疑惑/未闭合/目的与空间形成的关系 | 8/15 候选认识；暂不 schema 化，也不占当前工程主线 |
| 模型有“伪造完整性”倾向 | 第一发生场现场候选现象；不能升格为最终模型理论 |

## 已否决、已替代或明确不作为当前方案

| 提案 | 为什么被顶回 / 替代 | 仍可保留的部分 |
|---|---|---|
| 四文件 + CLI 机械拼 Prompt | 没有分层、检索与真实组织运行 | 极短常驻目的防线 |
| 固定四层/五层软件架构 | 没有从第一层自然长出 | 模块名可作检查清单，不作生成关系 |
| 事件是全系统最小单位 | 理由不足；事件更像记录形式 | append-only event/occurrence 可作局部存储形式 |
| “展开”是统一工作单位 | 词义过宽，压平不同尺度 | 展开仍是第一层运动 |
| 预设固定 AI 岗位 | 位置应在沟通中显现和轮转 | 局部承担仍可出现 |
| 关系只是有类型、作用域和 effect 的边 | 没理解空间内共存 | effect 可作关系显现实验 |
| “张力”作为系统原语 | 混合问题、可能、主体感受和残余 | 可继续用自然语言说“张力”，不立表 |
| 把数学探针当普通解题 | 丢失同时检验思想、组织与承载的目的 | 数学内容本身继续认真研究 |
| `ContextSnapshot` 作为本轮总收束 | 把更大问题塞回现有组件 | 以后可作某时刻 view |
| “首个 runtime 只接 Codex，多模型不作为首轮前置” | 已被现实越过；Gemini 已真实进入第一发生场 | RuntimeAdapter 保持小作用域仍成立 |
| “三层上下文必须先完成，再进入组织问题” | 当前 runtime continuity 已证明可先运行；会把真实 participant 差异提前压成统一 context | 三层上下文保留为触发式 probe |
| “Occurrence 默认公开给所有参与者” | 未被确认，会偷渡全员可见/广播假设 | 发生可在同一承载存在 |
| continuous participant = always-running/自动监听并响应 | 把持续存在误写成自动 Agent | 参与者可持续存在但当前不生成 token |
| 自动 round-robin / event broadcast / dampening 作为第一组织切片核心 | 都建立在尚未作出的 autonomy 决定上 | 未来若真实出现自治响应再处理 |
| 为了不像 Discord 而先做复杂空间 UI | UI 投影不等于底层世界；会抢跑表达层 | 真实出现多轨/空间表达失败后再改 |

## 关键开放残余

- 第一层怎样真正生成第二层，而不是给普通软件换哲学名字？
- participant 在什么条件下才值得视为主体？
- “同一场中发生”与“某主体看见/到达/受影响”之间需要什么承载结构？
- History 在什么条件下才成为 Memory，而不是 prompt material？
- Position / View / Reach / Influence / Field 哪些是独立结构，哪些只是不同投影？
- 关系依附空间，在数据与交互里怎样产生不可替代行为差异？
- 一个主体如何通过联合借另一个主体已经展开的世界继续扩张，同时不抹去差异？
- 模型休眠时世界怎样变化；重入为何不是简单读 unread events？
- runtime 身体变化时，什么连续、什么应当改变？
- 语言/符号怎样不只描述世界，而是改变可达空间与认识？
- 疑惑、未闭合和“外部”怎样在不被每轮回答消化掉的情况下继续有效？
- 阶段判断、共识和决定怎样既足以行动，又保留未采纳部分与重新打开条件？
- 现实行动怎样成为 Cognos 的一等运动，而不是聊天之后附带的 tool log？
- Cognos 怎样越来越多地在 Cognos 中建设自己，而不是继续依靠小林跨平台搬运上下文？
- 原始会话、runtime 发生、当前项目视图、认识史和未来世界状态怎样保持可追溯又不制造多个互相竞争的“真相源”？
