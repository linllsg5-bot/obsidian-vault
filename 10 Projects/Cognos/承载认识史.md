# Cognos：承载认识史

> 记录我们曾怎样切分 Cognos 的承载、什么发生使旧切法失效、后来如何重读。它不是 schema 清单，也不保证最新视图最终正确。文件只追加；当前采用什么仍看 [[_入口]] 与 [[10 Projects/_状态板]]。

## 2026-08-13｜项目层从协议层分出

- **当时切法**：`AI/` 保存跨 runtime 认识论，`10 Projects/Cognos/` 保存当前工程投影。
- **触发**：ex.1—3 已进入主线，但项目定位、实现方案和来源散在核层、状态板与长会话中。
- **阶段判断**：建立 Cognos 独立入口、边界、架构、决策、计划与来源文件。
- **后来发现的失败**：第一次整理只读了 index 和局部材料，把 ex.3 中 AI 提出的五对象模型、主体梯度、技术栈与实施顺序写得像已采用架构。

## 2026-08-13｜ex.1—3 全量重读

- **触发发生**：小林追问“仔仔细细看了 ex1、2、3 后就只需要改这些？”
- **旧结构失败**：`index/标注 → 当前结论` 的提升路径没有区分小林原话、AI 复述、局部允许和完整确认；标注版本身还存在说话人误标。
- **改写**：五对象模型、`subject_level`、技术栈和存储权威关系降为候选；项目改用“第一层思想 → 第二层承载”的生成视角，并建立 [[认知地位与来源]]。
- **牺牲/代价**：不再能直接把某份完整 AI 计划交给 agent 实现；必须先做来源核对和最小验证。
- **保留开口**：生成轴与证据轴只是当前视角，不是 Cognos 的最终本体。

## 2026-08-13｜网页 GPT 交流使归档结构折返

- **触发发生**：[[10 Projects/ai-conversations/2026-08-13-gpt-Cognos贯穿性主体扩张与空无架构/index]]。
- **小林明确认领**：主体扩展伴随边界、性质与架构扩展；schema 改变不能造成失忆、断裂或伪造旧历史；空无不允许限制、定义、计划与规则绝对化；保留可能和空间也保留幻觉生成。
- **GPT 候选**：历史与当前映射分离、schema 是判断/透支、稳定是结构可变而连续性不断等。保留为候选，不写成小林结论。
- **旧结构失败**：固定一份 `标注.md` 和一份 `index.md` 会让后来重读覆盖早先认识；`open/candidate` 仍只能容纳当前语言已经能指认的内容。
- **改写**：raw 明确为发生历史；标注允许版本化；重大重读增加 `认识史.md`；index 只充当当前入口。无法分类可以作为一次诚实的建模失败被原样保留，不强制制造 `other/unknown` 类型。
- **自指结果**：这次关于“架构应能演化”的认识，已经改变了存放它的对话标注技能与 Vault 归档约定。
- **仍未充分表达**：软件怎样承载“当前结构不知道自己缺什么维度”，仍然没有答案。本次只保护缺口，不替它命名。

## 2026-08-13｜完整分享页补出“装得进去但装错”

- **新来源**：[[10 Projects/ai-conversations/2026-08-13-gpt-Cognos贯穿性主体扩张与空无架构/raw-分享页]] 补齐整场网页对话；旧残缺粘贴与 v1 标注继续保留。
- **来源校正**：“承载不是建意识组件，而是建节律”归 Claudian 提案；小林的推进是节律已经一直发生、应被增强和扩展。该错误在 6/7 会话新建认识史，不回写旧标注。
- **旧探针不足**：只测试“当前 schema 装不下”会漏掉更危险的情况——材料被非常顺利地装成一个错误对象。
- **真实样本**：ex.1 中创作特质被识别成 trigger-type Attempt；旧结构想增加 subtype 自救，小林却校正“那根本不是什么尝试”。
- **当前改写**：Phase 2 谱系探针优先使用这个真实发生，并要求后来能撤销对象化，同时保留旧认识的来源与理由。
- **仍未认领**：四种连续性、发生锚点硬/跨时间身份软、空间作为历史场和 world model 进入 world，均只作为网页 GPT 候选，不写成 Cognos 本体。

## 2026-08-14｜Persistent History、Position、View 被拆开

- **触发发生**：[[10 Projects/ai-conversations/2026-08-14-gpt-Cognos跨Agent承载与Position验证/index]]。
- **旧切法风险**：把“外部可导航历史”直接当成 Position，会让 `B@P` 退化成另一种上下文/Prompt 方案。
- **阶段改写**：形成 `Persistent History ≠ Position ≠ Viewpoint` 的工作区分。P1 只验证 NavigableTrace；P2 若要声称 Position，必须让 `enter(P)` 在 runtime/承载层真正改变默认可达世界；P3 再讨论视角外置。
- **小林关键校正**：“视角制造外部”不能被反过来理解成主体永远不能站到世界之外形成视角。这里的“外部”首先是认识关系，不是脱离世界的本体位置。
- **仍未决定**：Position 的正式工程形态、View 的形成机制、Reach 是否是独立结构，都没有被确认。

## 2026-08-14｜语言、Field、持续暴露与潜在耦合打开另一片地形

- **触发发生**：[[10 Projects/ai-conversations/2026-08-14-gpt-Cognos语言符号支配与场结构推演/index]] 及其 raw 后段。
- **新开口**：语言/符号不只表达认识，也可能塑造甚至支配主体可区分的空间；“场”开始用于描述空间内部非对称结构所产生的倾向与流。
- **运行时缺口**：当前 LLM 常表现为 `call starts → context arrives → generate → call ends`，几乎没有对世界的持续暴露。
- **候选推进**：`NotRecognized ≠ NotEffective`、Reach/Influence、联合/轮转、`WorldChange → EffectPropagation → World/PositionChange → SubjectReentry → View`、以及 `ActiveCognition(S)=0` 时关系/处境仍可能持续。
- **边界**：这些是后续运行架构的候选运动，不是已经认领的 Cognos 本体或必须实现的 state machine；尤其不能因此立刻实现 always-on agent、sleep service 或中央状态更新器。
- **重要保留**：持续参与、持续处境与持续说话不是同一件事；主体不生成 token 时仍可能处在一个变化中的世界，是需要未来真实验证的更强命题。

## 2026-08-15｜第一发生场从探针变成真实使用现场

- **触发发生**：[[10 Projects/Cognos/运行数据/第一发生场.jsonl]] 与 [[10 Projects/ai-conversations/2026-08-15-gpt-Cognos第一发生场真实使用与第一组织切片/index]]。
- **现实变化**：第一网页身体从 Codex 单 runtime 推进到 Codex / Gemini 可选 runtime；本地 Markdown、Trace、启动诊断和 runtime/session 引用已实际运行。
- **认识回撞**：Gemini 面对复杂局面时快速生成“固定器官分工 / 统一中枢”等完整结构；小林明确顶回，并要求它重新区分发生事实与自身生成的理解结构。
- **边界改写**：“模型伪造完整性”、疑惑/目的/空间等只能作为现场候选，不因在第一发生场里出现就自动提升为 Cognos 理论。
- **项目收束**：主工程从继续打磨单 runtime 聊天体验转为“第一组织切片”——多个不互相替换、各自保持 runtime continuity 的 participant 第一次在同一发生场共在并显式面对彼此留下的 occurrence。
- **降级内容**：来源查询、migration probe、P1/P2/P3 不再按 Phase 顺序排队，而改为真实断裂触发式探针。

## 2026-08-16｜“只做下一刀”本身成为一次承载失败

- **触发发生**：小林明确指出，长上下文和大量文件已经让自己失去大方向感；AI 只强调“下一刀/跑完看哪里坏”使项目看起来像没有长期空间，甚至产生“AI 降智”的感受。
- **旧切法失败**：为了防止“大一统过度设计”，AI 过度压缩成局部碰撞主义，误把“结构保持开放”变成“不能维护大计划”。
- **改写**：建立三种时间尺度：
  1. [[大地图]]：慢变化，维护整个 Cognos 的地形、远处地标和相互关系；
  2. [[实施计划]] + [[10 Projects/_状态板]]：中速变化，维护当前战役；
  3. 局部探针/工程任务：快变化，维护下一刀与验收。
- **进一步发现**：跨文件重读确认“认识发展快于当前文档同步”。`当前架构`、`第一层/第二层`、`决策与残余`、`来源索引`、`AI/当前主线` 等存在不同程度同步债务。
- **维护规则**：当连续多轮跨越多片地形、新运行推翻旧项目视图、不同 AI 开始各自重新定义项目，或小林明显失去“为什么做这一步”的方向感时，应触发一次全局重读，而不是继续局部滚动。
