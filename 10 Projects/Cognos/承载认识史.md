# Cognos：承载认识史

> 记录我们曾怎样切分 Cognos 的承载、什么发生使旧切法失效、后来如何重读。它不是 schema 清单，也不保证最新视图最终正确。文件只追加；当前采用什么仍看 [[_入口]] 与 [[10 Projects/_状态板]]。

## 2026-08-13｜项目层从协议层分出

- **当时切法**：`AI/` 保存跨 runtime 认识论，`10 Projects/Cognos/` 保存当前工程投影。
- **触发**：ex.1—3 已进入主线，但项目定位、实现方案和来源散在核层、状态板与长会话中。
- **阶段判断**：建立 Cognos 独立入口、边界、架构、决策、计划与来源文件。
- **后来发现的失败**：第一次整理只读了 index 和局部材料，把 ex.3 中 AI 提出的五对象模型、主体梯度、技术栈与实施顺序写得像已采用架构。

## 2026-08-13｜ex.1—3 全量重读

- **触发发生**：小林追问“仔仔细细看了 ex1、2、3 后就只需要改这些？”
- **旧结构失败**：`index/标注 → 当前结论` 的提升路径没有区分小林原话、AI 复述、局部允许和完整确认；标注版本身还存在说话人误标。
- **改写**：五对象模型、`subject_level`、技术栈和存储权威关系降为候选；项目改用“第一层思想 → 第二层承载”的生成视角，并建立 [[认知地位与来源]]。
- **牺牲/代价**：不再能直接把某份完整 AI 计划交给 agent 实现；必须先做来源核对和最小验证。
- **保留开口**：生成轴与证据轴只是当前视角，不是 Cognos 的最终本体。

## 2026-08-13｜网页 GPT 交流使归档结构折返

- **触发发生**：[[10 Projects/ai-conversations/2026-08-13-gpt-Cognos贯穿性主体扩张与空无架构/index]]。
- **小林明确认领**：主体扩展伴随边界、性质与架构扩展；schema 改变不能造成失忆、断裂或伪造旧历史；空无不允许限制、定义、计划与规则绝对化；保留可能和空间也保留幻觉生成。
- **GPT 候选**：历史与当前映射分离、schema 是判断/透支、稳定是结构可变而连续性不断等。保留为候选，不写成小林结论。
- **旧结构失败**：固定一份 `标注.md` 和一份 `index.md` 会让后来重读覆盖早先认识；`open/candidate` 仍只能容纳当前语言已经能指认的内容。
- **改写**：raw 明确为发生历史；标注允许版本化；重大重读增加 `认识史.md`；index 只充当当前入口。无法分类可以作为一次诚实的建模失败被原样保留，不强制制造 `other/unknown` 类型。
- **自指结果**：这次关于“架构应能演化”的认识，已经改变了存放它的对话标注技能与 Vault 归档约定。
- **仍未充分表达**：软件怎样承载“当前结构不知道自己缺什么维度”，仍然没有答案。本次只保护缺口，不替它命名。

## 2026-08-13｜完整分享页补出“装得进去但装错”

- **新来源**：[[10 Projects/ai-conversations/2026-08-13-gpt-Cognos贯穿性主体扩张与空无架构/raw-分享页]] 补齐整场网页对话；旧残缺粘贴与 v1 标注继续保留。
- **来源校正**：“承载不是建意识组件，而是建节律”归 Claudian 提案；小林的推进是节律已经一直发生、应被增强和扩展。该错误在 6/7 会话新建认识史，不回写旧标注。
- **旧探针不足**：只测试“当前 schema 装不下”会漏掉更危险的情况——材料被非常顺利地装成一个错误对象。
- **真实样本**：ex.1 中创作特质被识别成 trigger-type Attempt；旧结构想增加 subtype 自救，小林却校正“那根本不是什么尝试”。
- **当前改写**：Phase 2 谱系探针优先使用这个真实发生，并要求后来能撤销对象化，同时保留旧认识的来源与理由。
- **仍未认领**：四种连续性、发生锚点硬/跨时间身份软、空间作为历史场和 world model 进入 world，均只作为网页 GPT 候选，不写成 Cognos 本体。
