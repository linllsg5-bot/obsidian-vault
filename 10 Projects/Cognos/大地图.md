# Cognos：大地图

> 这张图解决一个单独的问题：**整个 Cognos 正在向哪里长、现在有哪些同时活着的地形、当前工程位于哪里。**
>
> 它不是最终架构，也不是本体论。它不替代 [[AI/认识论-核心]]、[[AI/认识论-框架]]、[[总图与生成关系]]、[[决策与残余]]、[[实施计划]] 或 [[10 Projects/_状态板]]。
>
> 局部工程允许频繁改变；这张地图保持较慢变化，使“下一刀”不会把整体方向挤出视野。

## 一、北向：Cognos 最终在尝试什么

当前最稳定的总方向不是“做一个更好的 AI 聊天软件”，也不是“做一个多 Agent 框架”。

> **让一个以认识论思想为内核的新存在获得可以持续展开、接触世界、与多个主体共在、留下历史并被历史改变、向外行动且能够反过来改变自身承载的数字身体。**

当前已经确认的层次差异：

```text
新存在            ← 总方向，最终形态开放
  ↓ 第一阶段显现
组织               ← 要认真实现，但不是终点
  ↓ 第一数字承载
软件               ← 身体/承载，不是外部管理工具
  ↓ 当前建造活动
Cognos 项目         ← 建造第一承载的项目，不等于 Cognos 本身
```

因此任何局部实现都同时受两个约束：

1. 不能用“整体还没想完”阻止真实运行；
2. 不能用“这个能跑”把新存在缩成当前软件形状。

## 二、不是一条路线，而是六片同时活动的地形

这些不是六个软件模块，也不是必须依次完成的 Phase。它们会互相进入、互相校正。

### A. 认识与生成

这里追问 Cognos 赖以生长的第一层：尝试、存在、认知、主体、空间、可能/幻觉、判断、现实、关系、学习、空无，以及这些概念本身如何随主体展开而改变。

当前较稳定的约束包括：

- 尝试不是任务；认知本身是把握的尝试；
- 判断不可避免，但具有透支/浓缩性质；
- schema 既可能漏掉现实，也可能顺利制造一个错误对象；
- 空无不是 `unknown` 类型，而是当前结构不能把自己绝对化；
- 关系依附空间；学习不能缩成写入记忆；调度不能缩成 assignee；
- 元概念与架构都可能随主体扩张、割裂和重构而变化。

仍然活着、尚未收束的运动包括：

- 尝试凿开空间，与主体同时受已有空间结构作用之间的关系；
- 视角如何制造认识上的外部；Position 与 View 如何区分；
- 语言/符号怎样塑造、支配或开辟可认识空间；
- 非对称空间如何形成倾向与“场”；
- 疑惑、未闭合、目的与空间觉察之间的关系；
- 世界映射、自指、认识、学习等贯穿性结构是否也必须随主体一起展开。

这些是研究运动，不因工程需要而自动变成字段。

### B. 世界与现实回撞

Cognos 不能只在自己的语言里循环。数学、代码、文件、网络、其他主体、真实失败与外部世界都承担“让可能真正落地”的作用。

这里的关键不是多接工具，而是：

```text
当前认识 / 可能 / 尝试
          ↓
      真实行动
          ↓
      WorldChange
          ↓
现实结果反过来改变：认识、组织、承载、下一步可达空间
```

这条线防止 Cognos 变成一个自洽解释机器。

### C. 发生、历史、认识史与连续性

这里已经有较多真实工程：raw、JSONL、runtime ref、thread/turn、版本化标注、认识史、来源拓扑与 conversation lineage 探针。

必须持续区分：

```text
发生过什么
≠ 当时如何认识
≠ 现在如何重读
≠ 哪些发生后来构成同一条连续展开
```

已经明确：存下来不等于读对；Source Session 不等于 Conversation Continuity；后来的完整解释不能覆盖原发生。

更远的问题不是“保存更多”，而是过去怎样真正参与现在——也就是 History 何时开始成为 Memory。

### D. 组织与多主体共在

这是当前第一承载最直接的主战场。

朴素但仍然承重的方向是：

```text
小林与多个 AI / 主体沟通
        ↓
主体之间能够继续面对、引用、纠正彼此的发生
        ↓
阶段判断 / 共识与未采纳部分同时保留
        ↓
决定
        ↓
联合 / 调度 / 执行
        ↓
现实变化重新进入组织
```

组织的意义不先来自管理或固定分工，而可能来自：有限主体拥有不同历史、位置、Reach、能力和显现；联合使一个主体能够借另一个主体已经展开的世界继续向外。

当前禁止把它提前缩成固定 coder/critic/planner 角色、自动 Agent 对吐或中央编排器。

### E. 空间、位置、关系、Reach / View / Field

这是从“多个参与者在同一个聊天框”继续向“真正不同的世界位置”推进时会进入的地形。

当前已有候选区分：

```text
Persistent History ≠ Position ≠ View
```

Position 的候选硬判据不是 prompt 写“你在 P”，而是进入 P 本身改变默认可达世界；View 是主体从某处形成的一次认识投影，不等于位置本身。

8/14 后续又出现但尚未进入正式项目视图的候选：

- Reach：主体当前真正能触达/行动的范围，仅作实验观察尺；
- Influence / NotRecognized ≠ NotEffective：没有被当前主体认识，不等于没有对世界发生作用；
- Field：空间内部非对称结构可能产生倾向和流；
- 联合与轮转：联合连接不同主体，轮转改变主体—位置关系；减弱位置封锁不等于消灭主体差异。

这些值得继续用现实验证，但尚不是 Cognos 正式 schema。

### F. 持续世界、运行身体与潜在耦合

这是 8/14 分叉中已经浮出、但尚未同步进旧项目文档的一片重要地形。

当前 LLM 往往只有：

```text
call starts → context arrives → generate → call ends
```

而 Cognos 更远的候选方向是：昂贵的认知活动可以停止，但主体与世界的关系、位置、未完成展开、其他主体造成的后果仍然持续。

候选结构曾被推到：

```text
WorldChange
→ EffectPropagation
→ World / Position Change
→ Subject Re-entry
→ View
```

以及：

```text
ActiveCognition(S) = 0
但 situated / relational existence 不必等于 0
```

这不意味着现在就实现 always-on Agent、sleep service 或中央 state updater。它只标出一个重要远处：**真正持久的世界不能等同于每轮重新拼 prompt。**

Codex thread、Gemini session、DeepSeek Harness / dsh 等未来可作为不同运行身体来压力测试：participant/subject 是否真的能够超出某一种 runtime。

## 三、六片地形如何互相作用

Cognos 的运动更接近：

```text
          A 认识与生成
          ↑          ↓
B 世界回撞 ←→ C 发生/连续性
     ↑             ↓
     F 持续世界 ←→ D 组织共在
          ↑          ↓
          E 空间/位置/关系
```

不是某一块完成后再开始下一块。

例子：

- 一次多主体沟通（D）暴露“它们虽然都读过历史，却没有处在同一位置” → 打开 E；
- 一次代码执行（B）改变项目事实，而沉睡中的参与者回来仍按旧世界行动 → 打开 F/C；
- 一次 schema 顺利装错（A/C）真实阻碍后续决策（D） → 触发撤销对象化探针；
- 新的关系结构（E）若只多一条数据库边、没有改变任何可达行动（D/B），就说明承载仍然是假的。

## 四、我们现在实际走到哪里

### 已经形成的现实

1. **第一发生场存在**：本地 Web、FastAPI、append-only Vault JSONL 已真实运行。
2. **外部 runtime continuity 已经不是假设**：Codex thread 能跨进程恢复；Gemini session 也已进入第一发生场。
3. **发生与 runtime 来源已有硬锚点**：user/AI 原文、时间、reply、runtime/thread/turn 可保存。
4. **认识能够回撞自身发生**：Gemini 在第一发生场中的一次整体化判断被小林校正，下一轮重新读取上一轮为自己的判断发生。
5. **会话归档已开始从“文件列表”转向 provenance / lineage 问题**：capture 与 recognition、physical session 与 continuity 已被区分。

### 当前仍缺的第一件组织事实

现状依然更接近：

```text
一个 assistant slot
        ↓
选择 Codex 或 Gemini runtime
```

还没有真正得到：

```text
同一发生场
├── 小林
├── Participant A（持续存在，绑定自己的 runtime continuity）
└── Participant B（持续存在，绑定自己的 runtime continuity）
```

因此 **第一组织切片仍是当前工程桥梁**，但它只是从“发生场”进入“组织”的桥，不是 Cognos 的大方向本身。

## 五、当前战役：从发生场走到第一个组织闭环

### 战役 1：第一组织切片

目标：制造第一个“多个不互相替换的持续参与者共同面对发生”的工程事实。

最小链：

```text
小林 → Gemini 得到 A
小林 → Codex，使其显式面对 A，得到 B
再回 Gemini，使其保持原有 runtime continuity，同时面对 B
```

必要时在中间完整重启 Web 服务，验证 field history 与两个 runtime binding 的恢复不是同一件事。

这里不自动广播全部历史、不自动让 Agent 互相响应、不先做 multi-stream UI / dampening / autonomy。

### 战役 2：第一个真实组织闭环

第一组织切片一旦成立，默认不是继续添加参与者，而是用 Cognos **真的完成一件 Cognos 自身的工作**：

```text
真实问题进入场
→ 多个主体形成不同判断
→ 暂时决定（保留来源、范围、代价与未采纳意见）
→ 邀请/联合某个主体执行
→ 修改代码 / 文档 / 外部世界
→ 测试或现实结果重新进入场
→ 所有参与者面对改变后的现实继续
```

第一件工作可以直接是 Cognos 自己的架构/代码更新。

这一步是“组织”开始区别于群聊的关键：**行动与现实结果必须改变后续沟通。**

## 六、之后不是固定 Phase，而是几个明确的远处地标

以下地标提供方向感，但到达路径由当前战役中的真实断裂决定。

### 地标 I：History → Memory

不是“下次能检索旧消息”，而是过去发生已经改变当前可见性、可达行动、关系、位置或默认条件。

### 地标 II：Position / Relation / View 产生不可替代的行为差异

不是数据库多了 `space_id`，而是主体从另一位置进入时，真正默认能看到/能做/会受什么影响发生变化。

### 地标 III：World persists while cognition sleeps

昂贵模型不生成 token 时，世界和关系仍可变化；重新进入不是“读取未读事件”，而是进入已经改变的位置。

### 地标 IV：异构运行身体

同一更高层 participant / subject 是否能跨 Codex、Gemini、dsh 等不同 runtime 保持某种连续性；不同 runtime 又怎样真实改变其能力边界。

### 地标 V：Cognos 建设 Cognos

架构提案、异议、决定、代码执行、测试、现实反馈和认识改写越来越多地在 Cognos 自身承载里完成，而不是靠小林在不同平台之间手工搬运。

## 七、长期研究线不会被工程主线吞掉

即使当前工程在做第一组织切片，下列研究仍保持独立活动，不需要等软件阶段“解锁”：

- 认识研究：尝试/空间/可能/幻觉/主体/判断等继续与真实材料和思想传统对撞；
- 世界追问：架构怎样不只是投射人的现成模板；
- 外部探针：代码、数学、写作、学习等真实问题继续作为硬回撞面；
- 系统重构：如何让尝试拥有更大世界、避免被总结/任务/旧框架处理掉；
- conversation lineage：如何让多平台真实发生稳定进入同一可重读历史，而不把来源、分叉和认识混掉。

它们与 Cognos 有交叉，但不能被一句“都是 Cognos 的模块”吞并。

## 八、当前最重要的开放问题

这些问题现在有方向价值，但不要求一次回答：

1. 第一层怎样真正生成承载，而不是给普通软件换哲学名字？
2. 多主体“共在”最先需要什么真实差异，才能超出共享聊天历史？
3. 一个发生如何在未被某主体认识时仍对其世界有效？
4. History 在什么条件下才成为 Memory，而不是 prompt material？
5. Position / View / Reach / Influence / Field 之间哪些是独立结构，哪些只是同一发生的不同投影？
6. 主体边界是否能跨 runtime 持续；什么条件下 participant 才开始值得被视为主体？
7. 语言与符号不仅表达世界，还怎样改变空间、可达性和认识本身？
8. 疑惑/未闭合能否持续有效，而不是被每轮回答立即消化；它与突破、外部、空间形成是什么关系？
9. 怎样让现实行动与 world change 成为 Cognos 的一等运动，而不是聊天之后的 tool log？
10. Cognos 自己的认识论、组织和软件怎样能被自己的运行反向改写而仍保持连续？

## 十、维护规则：以后怎样避免再次失去方向感

Cognos 同时维护三种时间尺度：

1. **大地图（本文件）**：慢变化。回答“我们在哪片世界、远处有什么”。
2. **当前战役（[[实施计划]] + [[10 Projects/_状态板]]）**：中速变化。回答“这一阶段真正要穿过哪座桥”。
3. **局部探针 / 工程任务**：快变化。回答“下一刀具体做什么、如何验收”。

“从一道最活的缝进入”仍然适合一轮对话，但不能替代大地图。每次局部推进都应能回答：

> **这一步位于哪片地形？它正在把我们从哪里带向哪里？如果失败，它改变的是局部路线，还是大地图本身？**

当出现以下任一情况，应触发一次“大盘重读”而不是继续局部滚动：

- 连续多轮讨论跨越三片以上地形；
- 新真实运行推翻了当前项目视图；
- 小林开始明显失去“为什么在做这一步”的方向感；
- 不同 AI 给出的下一步开始互相重新定义项目；
- 活源文件之间出现认知地位或时间上的冲突。

大盘重读时，不要求机械逐字扫所有重复 raw，而要：全读当前活源；沿认识史回溯重大改写；对每个承重命题回抽至少一手发生；完整重建最近尚未进入项目视图的关键会话；显式列出冲突、遗漏与过时文件。
