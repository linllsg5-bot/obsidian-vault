# Cognos：认知地位与来源

> ex.1—4 暴露出两个不同问题：AI 提案、复述、原话和默许混在同一层；后来的认识又容易覆盖早先认识。Cognos 的文件不能继续复制这种混合。

## 五种来源角色

| 角色 | 例子 | 能证明什么 |
|---|---|---|
| `raw-source` | 会话 `raw.md` | 当时实际出现了什么 |
| `annotation` | `标注.md`、`标注-vN-*` | 某个主体在某时刻的认识；可能误标，后续版本不得覆盖旧版 |
| `recognition-history` | `认识史.md`、[[承载认识史]] | 说明认识或 schema 为什么改变，以及旧切法哪里失败 |
| `current-entry` | `index.md`、[[来源索引]] | 提供当前最可用的导航，不替代原文或旧认识 |
| `current-view` | [[定位与边界]]、[[第一层-思想与原语]] | 经过核对后目前可用的项目视图 |
| `runtime-projection` | 数据库、JSONL、UI、自动上下文 | 运行中的某种投影，必须能追到来源和生成规则 |

## 五种认知地位

| 地位 | 判断标准 |
|---|---|
| 已确认 | 小林明确说出，或明确确认 AI 的准确复述，且后续没有顶回 |
| 阶段采用 | 为了继续设计/实现暂时使用；不宣称最终正确 |
| 候选 | AI 或小林提出、值得继续，但没有完成确认 |
| 开放 | 问题仍在，当前没有足够结构作答 |
| 已否决/已替代 | 被明确顶回；保留其来源、失败原因和仍可用局部 |

“没有评价”“勉强能继续”“其他还好”不能自动提升为“全部已确认”。

这些地位只处理当前语言已经能够指认的内容。若某次发生连“候选/开放”都不足以表达，应直接记录“当前结构无法充分表达”及其原始来源，不能为了填表制造一个 `other`、`unknown` 或“未规定区域”对象。

## 提升规则

从对话进入当前项目视图前，至少核对：

1. 这句话是谁说的？标注版和 raw 是否一致？
2. 是原话、AI 复述、AI 推导，还是完整方案中的一项？
3. 小林后来是否明确确认、局部接受、保持沉默或顶回？
4. 后续对话是否改写了它？
5. 进入当前视图后，它的作用域是什么，留下什么未决？
6. 这次解释依赖哪一版概念/schema？后来重读时是否需要保留旧解释？

只有 raw 里出现过，不等于已确认；只有被标成 `〔实〕`，也不等于已确认。

## 以后怎样更新

- 会话结束先保存 raw，再做标注和 index。
- raw 是发生历史；标注是认识历史的一次显现；index 是当前入口。三者不是“原始/半成品/最终稿”的升级关系。
- 发生重大重读时新建版本化标注并追加 `认识史.md`，不覆盖旧标注。Git 保存字面差异，认识史说明语义变化。
- 项目推进时从会话提取“候选变化”，先进入 [[决策与残余]]，不要直接改成已确认。
- 小林明确确认或现实运行给出足够证据后，再提升当前视图。
- 发生替代时不覆盖旧判断：保留旧来源、替代原因和新作用域。
