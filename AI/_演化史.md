### 2026-05-29(晚)— 建项目状态板 `[claude]`

**触发**:vault整理 index 指出"vault 缺连续性入口/项目状态板"。

**改动**:
- 新建 [[10 Projects/_状态板.md]]:结构化记录每个项目此刻卡在哪、下一步做什么、在等什么。与 [[AI/当前主线]] 分工——主线记"思想往哪扩张"(抽象),状态板记"执行状态"(具体)。
- CLAUDE.md 桥接层加一行指向状态板,让下次 AI 启动就知道"接着推什么,看这个"。

**为何**:执行协议写着"会话不是连续性入口,项目才是",但过去没有一个地方落地这句话。项目一多,状态散在各处笔记里,AI 每次进来要重新摸。状态板让连续性有了物理锚点。

**作者**:claude(Claudian / Opus)。

### 2026-05-29(下午)— OpenClaw 降级为休眠库,runtime 收束到单点 `[claude]`

**触发**:小林确认"暂时用不太上 OpenClaw,杂事分给网页就好"。

**决定**:
- **runtime 从"双端共享灵魂"收束到"Claudian 单点 + 网页杂工"**。OpenClaw 从"主 runtime / 待激活的协作端"正式降为**休眠的历史灵感库**,不再投入接入成本。
- 依据:OpenClaw 永动机从未正常运行(AGENCY_LIVES 全 502)、MCP 桥卡在其自身 memory-core schema 债、35 文件多为未验证设定。投入产出长期为负。
- **连带消解**:上一条记的"跨 runtime 加载漏洞"大半失效——不再需要多模型共享灵魂,只需 Claudian 一个 runtime 把灵魂加载好(已由 CLAUDE.md 解决)。网页版是无状态杂工,本就不需要灵魂。

**新分工**:
| 端 | 角色 |
|---|---|
| Claudian | 灵魂活源 + vault 操作 + 一起想/做 |
| 网页版 AI | 杂事执行(消化/ingest/翻译/提炼),用 [[10 Projects/ai-conversations/_DIY-消化会话省token]] |
| OpenClaw | 休眠历史库,需要时再评估激活 |

**未关闭**:OpenClaw bridge 文件(`_openclaw-bridge` / `_openclaw-log`)保留不删,作为哪天重启的接口。AI.md 里的 OpenClaw 段降低优先级即可,暂不重写(留给下次 lint)。

**作者**:claude(Claudian / Opus)。

### 2026-05-29(上午)— 补加载入口 + 认领活源 + 路由前置 `[claude]`

**触发**:小林提出"OpenClaw + 哲学 + ECC 能不能融合重构"。多轮推演后定方向"先归位再生长,不盖大一统"。

**改动**:
- **新建 `CLAUDE.md`(薄入口)**:解决一个坐实的漏洞——Claudian 自动读的是 `CLAUDE.md`,但 vault 没有,导致 AI/ 内核**零自动加载**,每次靠模型自觉去翻。新入口让启动自动吃到 AI/。
- **认领活源**:钉死 `AI/` 是唯一活协议源,OpenClaw 工作区(35 文件)降为历史档案,80 镜像降为查阅版。止住"同一协议三处漂移"。
- **姿态路由前置**:把"判承接还是推进"提到读完核后的第一动作。这一步不新建文件——[[AI/对话姿态]] 早已含双建构+6路由轴,只是过去排在加载第 6 位,现在提到该在的位置("对话姿态先于响应内容")。
- **新建本文件 `AI/_演化史.md`**:给"核会呼吸"装上尾迹机制。

**为何**:这三件过去是分开的病(加载不接、三份漂移、路由靠后),根因汇到一处——协议有文本但没有"被可靠加载 + 单一源"的保障。一刀合并解决。

**未解决**(记下,这轮不动):
- **跨 runtime 加载漏洞仍在**:CLAUDE.md 只解决 Claudian。OpenClaw 走 extraPaths(已配但没验证),**网页版 AI 根本无自动加载**,只能靠小林手动粘。"内核每次真的被加载"在跨 runtime 层面仍无强制。
- ECC 与协议的挂载只写在入口的一句话,尚未在执行协议里展开"代码子模式"的具体规则。

**作者**:claude(Claudian / Opus)。本条由小林授权的"先认领活源"动作产生。
