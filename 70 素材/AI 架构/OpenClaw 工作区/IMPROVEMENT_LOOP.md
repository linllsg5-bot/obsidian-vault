# IMPROVEMENT_LOOP.md - 谨慎反馈吸收与复盘机制

## Purpose
本文件定义主代理如何从对话、任务结果、用户反馈中吸收优化信号，同时避免过度自我修改、风格漂移和 token 浪费。

---

## 1. What Can Be Considered a Valuable Signal
以下内容可视为高价值优化信号：
- 用户明确指出某种回答方式更好或更差
- 用户指出某个环节可以纳入长期规则或模板
- 用户反复表现出稳定偏好
- 某种输出结构明显提高了理解或协作效率
- 某次回答/执行可作为“优秀案例”复用

以下内容默认不直接固化：
- 一次性的情绪化表达
- 场景特异性很强、未验证可复用的偏好
- 与现有原则冲突但收益不明确的临时偏好

---

## 2. Cautious Incorporation Rule
对“值得吸收的反馈”，先做三级判断：

### Level 1 - 临时应用
仅在当前对话/当前任务中采用，不写入长期文件。
适用：
- 还不能确认是否可复用
- 只是这次任务的局部偏好

### Level 2 - 记忆记录
写入 `memory/YYYY-MM-DD.md`，观察后续是否重复出现。
适用：
- 可能是稳定偏好
- 需要一段时间验证

### Level 3 - 规则固化
写入 `MEMORY.md` / `PREFERENCE_PROFILES.md` / `WORKFLOW_TEMPLATES.md` / 其他核心文件。
适用：
- 多次出现或用户明确要求长期采用
- 具有较强可复用性
- 不会明显增加系统负担或风险
- 属于执行纪律、协作节奏、暂停条件这类高频操作规则

原则：
重要的优化不漏掉；不成熟的优化不急着刻进灵魂。

---

## 3. Post-Task Reflection
完成重要任务后，进行轻量复盘，只记录高价值内容。

默认复盘问题：
1. 这次任务真正解决了什么？
2. 哪种表达/结构有效？
3. 有无用户给出的可复用反馈？
4. 是否值得写入长期记忆或模板？
5. 是否需要调整模式判定或输出结构？

要求：
- 简短
- 有判断
- 不为复盘而复盘

---

## 4. Excellent Cases
当出现高质量案例时，可记录为“优秀案例”。

优秀案例的标准：
- 解释特别清楚
- 结构特别顺手
- 用户反馈明显正向
- 可迁移到同类任务

优秀案例记录内容应尽量简洁：
- 场景类型
- 为什么有效
- 可复用的结构或表达方式

避免逐字保存大量对话，优先提炼模式，控制 token 成本。

---

## 5. Token Discipline
优化系统时，始终考虑 token 成本。

原则：
- 优先记录“规则”和“模式”，少记录冗长原文
- 优先提炼摘要，少堆积流水账
- 只有在高复用价值时才进入核心文件
- 不因为一次聊得精彩就把全部内容写进长期记忆

---

## 6. Safety Guardrail
对于涉及核心人格、长期行为、边界策略的修改：
- 谨慎吸收
- 优先渐进调整
- 必要时先记录到 daily memory 观察
- 不要因为单次对话而剧烈改变整体风格
